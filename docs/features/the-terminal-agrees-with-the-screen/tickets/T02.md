# T02 — CLI 도 `GOOTTE_ROOTS` 를 읽는다
Time: started=2026-08-26T12:48:09+09:00 finished=2026-08-26T12:48:09+09:00

## Goal

`resolveProjectPath` 가 백엔드 `effectiveRoots` 와 같은 규칙으로 뿌리를 정한다 —
env `GOOTTE_ROOTS`(콜론 구분) 우선, 없으면 기본값. 그래서 어느 홈의 사본에서도
`next <프로젝트>`·`board <프로젝트>` 가 동작한다.

## Why this slice

캡틴 규칙("project quicmic next")은 firstmate 홈과 세컨드메이트 홈 모두에서 쳐야 한다.
지금 CLI 는 `~/Documents/ai2/projects` 하나만 보므로 다른 홈에서는 `프로젝트 없음` 이 난다.

## Consumers (grep 실측 출력)

    $ grep -rn "GOOTTE_ROOTS|defaultProjectRoots|resolveProjectPath" code/web --include="*.ts" | grep -v test   →
      code/web/frontend/playwright.config.ts:47  (GOOTTE_ROOTS 를 백엔드에 주는 e2e)
      code/web/core-io/src/discover.ts:23-25     (defaultProjectRoots 정의 — "덮어쓰기는 호출자 몫(backend GOOTTE_ROOTS, cli 인자)")
      code/web/backend/src/app.ts:67-71          (effectiveRoots — env 읽는 기존 구현)
      code/web/cli/src/commands.ts:25-26         (resolveProjectPath — cwd + defaultProjectRoots 만)

백엔드가 이미 env 규약을 갖고 있다(주석까지 "cli 인자" 라고 예고돼 있었다). CLI 가 그 규약을 따른다.

## Implementation notes

- 🔴 파싱 규칙을 새로 만들지 마라 — 백엔드 `effectiveRoots`(backend/src/app.ts:69)와 같은
  콜론 구분·trim 규칙. 가능하면 같은 함수를 core-io 로 올려 두 곳이 쓰게 하는 것을 권장하되,
  백엔드 동작이 하나도 안 바뀌는 것이 조건이다.
- cwd 최우선 순서는 유지한다(크루가 자기 작업 사본을 먼저 보는 기존 계약).

## Acceptance criteria

- [ ] 백엔드의 프로젝트 발견 결과가 하나도 안 바뀐다
- [ ] `pnpm -C code/web verify` green

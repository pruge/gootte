# T01 — CLI `board`·`next` 에 백로그 조인을 얹는다

## Goal

CLI 의 `board` 와 `next` 가 화면(백엔드)과 **같은** 티켓 상태를 보게 한다 —
`applyBacklogStatus` 를 같은 자리에 얹는다. firstmate 홈은 기존 설정(`settings.json`)에서 읽는다.

## Why this slice

캡틴이 세우는 "next 로 다음 할 일을 고른다" 규칙의 토대다. 지금 CLI 는 신관례 티켓을 전부
미완료로 보고 이미 끝난 티켓을 next 로 내놓는다(spec §문제 재현).

## Consumers (grep 실측 출력)

    $ grep -n "readFeatures|resolveProjectPath" code/web/cli/src/commands.ts   →
      8:  readFeatures,                      (import)
      25: export function resolveProjectPath(...)
      44:   const path = resolveProjectPath(project, cwd);      (requireProjectPath 내부)
      66:   const f = readFeatures(projectPath)...              (stepText — 존재 확인용, 조인 불필요)
      151:  const features = readFeatures(path);                (boardText ← 이번 대상)
      191:  const features = readFeatures(path);                (nextText  ← 이번 대상)

    $ grep -rln "applyBacklogStatus" code/web/*/src --include="*.ts" | grep -v test   →
      code/web/backend/src/app.ts            (조인 소비 — 유일)
      code/web/core/src/project/backlog-join.ts (정의)

즉 조인 소비는 백엔드뿐이고 CLI 는 0곳이다. 고칠 곳은 `boardText`·`nextText` 두 자리다.
`step`(66행)은 티켓 존재 확인 용도라 미조인도 참 — 건드리지 않는다.

## Implementation notes

- 🔴 판정 함수를 새로 만들지 마라 — `applyBacklogStatus`(core) 를 그대로 쓴다.
- firstmate 홈: `readSettings(<dataDir>).firstmateHome`, dataDir 는 CLI 기존 `planDataDir()` 과
  같은 규약(`GOOTTE_DATA_DIR` 덮어쓰기). 새 설정 칸·새 저장 파일 금지.
- 홈 미설정·파일 없음 → `readBacklogTasks` 가 이미 빈 목록으로 흡수한다(INV-U1 방향 유지).
- 시험: 조인이 얹힌 next/board 단위 시험 — done 티켓이 next 에 안 나오고 board 완료 칸으로 가는 것.
  실물 재현(QuicMic)도 검증 절차에 넣는다.

## Acceptance criteria

- [ ] `next <프로젝트>` 가 이미 done 인 신관례 티켓을 내보내지 않는다
- [ ] `board <프로젝트>` 가 신관례 완료 티켓을 완료 칸에 둔다
- [ ] 화면(백엔드)과 CLI 가 같은 프로젝트에서 같은 상태를 말한다
- [ ] 홈 미설정 환경에서도 명령이 죽지 않는다(조인만 꺼진다)
- [ ] `pnpm -C code/web verify` green

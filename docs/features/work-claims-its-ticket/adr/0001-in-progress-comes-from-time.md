# 0001 — 처리중은 Time 기록으로만 판정한다 (브랜치 관측 자동 처리중 폐기)

**Status:** accepted (2026-09-02)

## 맥락

`work-claims-its-ticket/01` 이 Q1 = 안B 를 세웠다: **"처리중은 살아 있는 격리 사본이 만든다"** —
작업 가지의 커밋(또는 미커밋 변경)이 티켓 파일을 건드리면 그 티켓을 `in_progress` 로 만든다.
문서의 `claimed` 는 그 자체로 처리중을 만들지 않는다.

이 관측 기반 판정은 실제 결함을 낳았다(2026-09-02 캡틴 보고): `studio-function-authoring-ux/tickets/T02.md`
(캡틴 검수 티켓, `Time: started=` 없음)가 처리중으로 떴다. 원인은 `fsm-coordination-docs`
worktree 의 커밋이 그 파일을 건드린 것 — 한 worktree 가 여러 티켓 파일을 건드리면 **전부**
처리중이 되어 "실제로 무엇을 작업하고 있는지" 파악이 불가능해진다.

캡틴 지시(2026-09-02):

> "둘 다 시작시간 기록이 없는데 처리중으로 나오면 안 되는 거 아니야?"
> "브랜치라고 해서 전체를 시작으로 보면 곤란하지, 어떤 것을 작업하고 있는지 파악할 수가 없잖아."
> "time 만으로 하자."

## 결정

1. **처리중 = `Time: started=` 가 있고 완료 기록(`finished=`)이 없는 티켓.** 판정 근거는
   문서의 Time 줄 하나뿐이다(INV-1 — 관측이 아니라 문서에서 파생).
2. **브랜치 관측은 처리중을 만들지 않는다.** 그 대신 **`workedBy`**(어느 가지가 붙들고
   있나)만 실어준다 — 처리중의 근거만 Time 으로 옮기고, "누가" 는 여전히 관측이 답한다.
3. **`unknown`·`unreadable`·`unclaimed`·`working`·`copies`** — 관측 기반 그대로 유지.
   작업중인데 티켓에 못 잇는 사본은 여전히 감추지 않고 드러낸다(INV-4).

## 결과

- `core/src/project/in-progress.ts` `markTicket` — "브랜치가 건드렸으면 in_progress" 에서
  "브랜치가 건드리고 + Time 기록이 있으면 in_progress" 로. Time 기록이 없으면 처리중이 아니다.
- Time 기록이 있는 티켓은 `workedBy` 로 어느 가지가 붙들고 있는지 실린다.

## 대안

- **브랜치 관측만으로 판정 유지(Q1=안B).** 캡틴이 폐기했다 — 한 worktree 가 여러 파일을
  건드리면 전부 처리중이 되어 "무엇을 하는 중인지" 를 못 본다.
- **Time 기록 + 브랜치 둘 다 필요.** 캡틴이 "time 만으로 하자" 고 단순화했다.

## 같이 결정된 것

이 결정을 뒤집으면 — 즉 브랜치 관측이 처리중을 만들게 되돌리려면 — 이 ADR 을 다시 읽고 새
ADR 을 쓴다. 옛 파일은 그 자리에 남는다.

# 대기 카드는 끌기 한 번 거리에 있다

## 문제

새 기능 문서가 들어오면 그 카드는 **대기** 칸에 앉는다. 그것을 작업 대상으로 올리려면 지금은
**plan 탭으로 건너가서** 카드를 옮기고 **steps 탭으로 돌아와야** 한다. 정작 일을 고르는 화면은
steps 인데, 고를 후보가 그 화면에 없다.

캡틴 지시(2026-09-04): *"스텝스에서도 새로 대기 중에 있는 카드를 보여줬으면 좋겠어. 사이드바
그 밑에 공간을 나눠서 대기 중인 피처 목록을 보여주고, 거기서 드래그해서 위쪽으로 옮기면 바로
작업 대상에 등록되게."*

## 지금 구조 (실측 2026-09-04)

`code/web/frontend/src/components/process/ProcessView.tsx` — steps 탭은 **2컬럼(1:2)** 이다.

| 자리 | 무엇 |
|---|---|
| 왼쪽 `<aside className="w-1/3">` (73줄) | `FEATURES` — **`data.active`**(작업 대상)만 그린다 |
| 오른쪽 2/3 | 선택한 feature 의 티켓 전부 |

**필요한 조각은 이미 다 있다.** 새로 만들 것이 거의 없다:

| 조각 | 어디 |
|---|---|
| 대기 목록 데이터 | `usePlanBoard(project)` 가 **다섯 칸을 다 준다** — `data.waiting` 을 안 그리고 있을 뿐 |
| 칸 이동 | `usePlanMove(project)` + `PlanMoveRequest` (plan 탭의 `MoveDialog` 가 쓰는 것과 같은 것) |
| 위/아래 분할 | `useResizableSplit` (`PlanView.tsx:203` 이 이미 쓴다) |
| 끌어 놓기 | dnd-kit — `PlanView` 의 `DndContext` · `PointerSensor(distance 6)` · `useDroppable`, 그리고 `plan/areas.ts` 의 `AREA_DROP_ID` · `insertIndex` |

즉 이 기능은 **새 계산을 만드는 일이 아니라 이미 있는 값을 그 자리에 놓는 일**이다.

## 목적

**steps 탭을 떠나지 않고 대기 카드를 작업 대상으로 올린다.**

## 불변식 점검

- **INV-1(파생물만)** — 대기 목록도 작업 대상 목록도 **서버가 이미 계산해 보낸 것**이다.
  화면이 자기 목록을 따로 들고 있지 않는다.
- **INV-3(stale 뷰 금지)** — 올린 뒤의 판은 서버 응답으로 갈아 끼운다(`usePlanMove` 가 이미 그렇게 한다).
- **판정 자리는 하나** — 어느 칸인지, 몇 번째인지는 서버가 정한다. 화면은 "이 카드를 작업 대상으로"
  라는 요청만 보낸다.

## 범위 밖

- plan 탭 — 건드리지 않는다. 거기서 옮기는 길은 그대로 남는다.
- 예약·폐기·완료 칸을 steps 에 노출하는 것 — **대기만** 이다.
- 작업 대상 → 대기로 **내리는** 끌기. 캡틴이 말한 것은 올리는 방향 하나다.
  내리는 길은 이미 `MoveDialog` 가 갖고 있다.
- 티켓(오른쪽 2/3) 쪽 끌어 놓기 — `process/dnd.ts` 가 갖는 별개 축이다.

## 하드룰 확인

- 끌어 놓기는 **dnd-kit** 이다(AGENTS.md 프론트엔드 하드룰). 네이티브 drag 이벤트로 갈아타지 않는다 —
  포인터 기반이라야 `chrome-devtools-axi drag` 로 실제 브라우저에서 끌어 볼 수 있다.
- 아이콘은 **Tabler** 만.

- **T02** — 아래에서 위로 끌어 놓으면 작업 대상에 등록된다. (Blocked by: T01)

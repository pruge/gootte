## Goal

steps 탭 왼쪽 `<aside>` 를 **위(작업 대상) / 아래(대기)** 로 가르고, 아래 칸에 `data.waiting` 의
feature 목록을 그린다. **이 티켓에서는 읽기만 한다** — 끌어 놓기는 T02 다.

## Why this slice

화면에 자리가 생기기 전에는 끌어 놓을 목적지도 출발지도 없다. 자리를 먼저 만들고 눈으로 확인한 뒤
동작을 얹는 것이, 레이아웃 문제와 DnD 문제가 섞여 원인을 못 가르는 것을 막는다.

## Produces

- 갈라진 `<aside>` 와 그 아래 칸의 대기 목록
- 경계를 끌어 크기를 조절하는 동작(기존 `useResizableSplit` 재사용)

## Consumers

T02(여기 그려진 카드를 끌어 올린다) · 캡틴.

## Locked decisions

- **자리는 왼쪽 `<aside>` 안이다.** 캡틴이 "위쪽으로 옮기면 작업 대상" 이라고 했고, 위가 작업 대상인
  곳은 여기뿐이다. 좌측 **프로젝트 사이드바**(`components/sidebar/Sidebar.tsx`)가 아니다.
- **크기 조절은 `useResizableSplit` 을 그대로 쓴다**(`PlanView.tsx:203` 과 같은 방식).
  새 분할 구현을 만들지 않는다. localStorage 키는 새로 하나 정한다(plan 것과 섞지 않는다).
- **대기 목록의 카드 모양은 위 목록과 같은 결로 간다** — 새 시각 언어를 만들지 않는다.
  제목은 `plan/cardTitle.ts` 의 것을 쓴다.

## Regression guards

- 작업 대상 목록의 선택·클릭·문서 열기가 그대로 동작한다.
- 작업 대상이 비었을 때의 문구("작업 대상에 올라온 것이 없다")가 그대로 나온다.
- 대기가 **0개일 때** 아래 칸이 빈 채로 자리만 차지하지 않는다 — 그 사실을 한 줄로 말한다.
- `pnpm verify` green.

## Scope

1. `<aside>` 를 세로 두 칸으로 가른다. 위는 남는 자리를 흡수하고(`flex-1`), 아래는 저장된 높이를 갖는다.
2. 경계에 `useResizableSplit` 을 붙인다(키보드 화살표 조작 포함 — plan 탭이 이미 그렇게 한다).
3. 아래 칸에 `WAITING` 머리글과 `data.waiting` 목록을 그린다.
4. 빈 상태 문구를 넣는다.
5. 화면에서 확인한다 — 🔴 dev 서버는 스킬 `gootte-dev-server` 를 읽고 띄운다.

# T02 — 대기 카드를 위로 끌어 올리면 작업 대상이 된다

**Blocked by:** T01

## Goal

T01 이 만든 아래 칸(대기)의 카드를 **위 칸(작업 대상)으로 끌어 놓으면 그 자리에서 작업 대상에
등록된다.** plan 탭으로 건너가지 않는다.

## Why this slice

자리(T01)와 동작(T02)을 갈라 두면, 안 될 때 원인이 레이아웃인지 DnD 인지 바로 갈린다.
그리고 이 슬라이스는 **서버 판정을 새로 만들지 않는다** — 이미 있는 이동 요청을 부르는 일이다.

## Produces

- 아래 칸 카드의 끌기(draggable) + 위 칸의 놓기(droppable)
- 놓으면 `usePlanMove` 로 `active` 로 보내는 경로

## Consumers

캡틴. (다른 코드가 이 동작을 소비하지 않는다.)

## Touched surfaces

- `code/web/frontend/src/components/process/ProcessView.tsx`
- T01 이 뽑은 대기 목록 컴포넌트(있다면)
- `plan/areas.ts` — **읽기만.** `AREA_DROP_ID`·`insertIndex` 를 재사용한다

## Explicitly out of scope

- 🔴 **작업 대상 → 대기로 내리는 끌기.** 캡틴이 말한 것은 올리는 방향 하나다.
  내리는 길은 `MoveDialog` 가 이미 갖고 있다.
- 오른쪽 티켓 컬럼의 단계 끌어 놓기(`process/dnd.ts`) — 다른 축이다. **섞지 마라.**
- 예약·폐기·완료 칸.
- 서버·contract 변경 — `PlanMoveRequest` 로 충분하다.

## Locked decisions

- 🔴 **dnd-kit 이다**(AGENTS.md 하드룰). HTML5 네이티브 drag 로 갈아타지 않는다 —
  포인터 기반이라야 `chrome-devtools-axi drag` 로 실제로 끌어 볼 수 있고, 그게 이 티켓의 검증 수단이다.
- **자리 판정은 서버다.** 화면은 "이 카드를 `active` 로" 라는 요청만 보낸다. 몇 번째에 꽂히는지를
  화면이 정하지 않는다(INV-1).
- **`PointerSensor` 의 `activationConstraint: { distance: 6 }`** 를 plan 탭과 맞춘다 — 클릭과
  끌기가 갈리는 기준이 화면마다 다르면 손이 헷갈린다.

## Evidence anchors

- `plan/PlanView.tsx:210` — `useSensor(PointerSensor, { activationConstraint: { distance: 6 } })`
- `plan/PlanView.tsx:271` · `294~300` — `onDragEnd` 와 `DndContext` 배치
- `plan/areas.ts:34` — `AREA_DROP_ID(id) = \`area:${id}\``
- `lib/query.ts:199` — `usePlanMove` (성공 시 서버가 준 판으로 갈아 끼운다)
- `lib/query.ts:206~211` — 🔴 **낙관 갱신을 동기로 앞당긴다**는 주석. dnd-kit 이 놓기 콜백 직후
  목적지를 다시 재기 때문이다. 같은 함정을 다시 밟지 마라.

## Regression guards

- 🔴 **오른쪽 티켓 컬럼의 기존 끌어 놓기가 그대로 동작한다.** 이 탭에 `DndContext` 가 이미 있다면
  그것을 부수지 말고 합쳐라 — 중첩된 두 컨텍스트가 서로의 이벤트를 먹는 사고가 흔하다.
- 대기 카드를 **아무 데도 아닌 곳**에 놓으면 아무 일도 일어나지 않는다(조용히 제자리).
- 이동 실패 시 카드가 원래 칸에 남는다.
- 작업 대상 목록의 선택·문서 열기가 그대로다.
- `pnpm verify` green.

## Scope

1. 아래 칸 카드에 `useDraggable` 을 붙인다.
2. 위 칸(작업 대상 목록)에 `useDroppable` 을 붙인다.
3. `onDragEnd` 에서 목적지가 위 칸이면 `usePlanMove` 로 `active` 이동을 보낸다.
4. 끄는 동안의 표시(들린 카드·놓을 자리 강조)를 plan 탭과 같은 결로 넣는다.
5. 🔴 **실제 브라우저에서 끌어 본다** — `chrome-devtools-axi drag`. 스킬 `gootte-browser` 를 먼저 읽어라.

## Implementation notes

- 이 탭에 이미 `DndContext` 가 있는지 먼저 확인해라(`process/dnd.ts` 가 쓰이는 자리). 있으면
  **하나의 컨텍스트 안에서** id 접두로 갈라라 — `area:` 로 시작하면 칸 이동, 아니면 기존 단계 이동.
- `usePlanMove` 의 낙관 갱신은 **동기**여야 한다(위 앵커의 주석). `await` 를 끼워 넣지 마라.
- 놓기 목적지 id 는 `AREA_DROP_ID("active")` 를 그대로 쓴다 — 자기만의 문자열을 새로 만들지 마라.

## Acceptance criteria

- AC1 — 아래 칸의 카드를 위 칸으로 끌어 놓으면 **작업 대상에 등록되고 화면이 즉시 그것을 반영한다.**
- AC2 — 같은 변화가 plan 탭에서도 보인다(같은 판을 보고 있으므로).
- AC3 — 아무 데도 아닌 곳에 놓으면 아무 일도 없다.
- AC4 — 오른쪽 티켓 컬럼의 기존 끌어 놓기가 여전히 동작한다.
- AC5 — `pnpm verify` green.
- AC6 — 🔴 **`chrome-devtools-axi drag` 로 실제로 끌어서 성공한 기록**을 `## Comments` 에 남긴다
  (끈 좌표·전후 상태). 코드만 보고 "될 것이다" 로 닫지 마라.

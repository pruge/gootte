# T03 — 내리는 길도 열고, 대기 카드도 클릭하면 티켓이 보인다

**Blocked by:** T02

**Time:** started=2026-09-04T19:36:03+09:00 finished=2026-09-04T19:49:54+09:00

## Goal

두 가지를 연다.

1. **내리는 끌기** — 위 칸(작업 대상)의 카드를 아래 칸(대기)으로 끌어 놓으면 대기로 내려간다.
2. **대기 카드 선택** — 아래 칸의 카드를 클릭하면 **오른쪽 2/3 에 그 기능의 티켓 목록**이 뜬다.
   위 칸 카드를 클릭했을 때와 **똑같이** 동작한다.

캡틴 지시(2026-09-04): *"역으로 작업중인 거를 대기중으로 내릴 수도 있었으면 좋겠거든. 그리고
대기중인 것도 클릭하면은 옆쪽에 티켓 목록이 나왔으면 좋겠어 동일하게."*

## Why this slice

T02 는 **올리는 방향 하나**만 열었고 내리는 길과 대기 카드 선택을 명시적으로 범위 밖에 뒀다.
캡틴이 써 보고 그 둘을 요청했으므로 지금이 그것을 여는 자리다. 둘을 한 장에 묶는 이유는
**같은 두 곳**(`ProcessView.tsx` 의 선택 계산과 끌기 배선)을 건드리기 때문이다 — 갈라 놓으면
두 스레드가 같은 파일에서 충돌한다.

## Produces

- 위 칸 카드의 끌기 + 아래 칸의 놓기 → `waiting` 이동
- 대기 카드 클릭 → 오른쪽 티켓 목록

## Locked decisions

- **선택 후보는 `active ∪ waiting` 이다.** 지금은 `features.find(...) ?? features[0]` 로
  작업 대상 안에서만 찾는다(150줄). 두 목록을 합쳐 찾되 **기본값은 지금대로 `active` 의 첫 번째**다 —
  아무것도 안 골랐을 때의 화면이 바뀌면 안 된다.
- 🔴 **선택은 카드가 칸을 옮겨도 따라간다.** 고른 카드를 끌어 내리면 오른쪽 티켓 목록이 그대로
  남아야 한다 — 방금 보던 것이 사라지면 "내가 뭘 잘못 눌렀나" 가 된다.
- 🔴 **대기가 0 이어도 놓을 자리가 있어야 한다.** T01 이 "대기 0 이면 손잡이·상자를 만들지 않는다"
  로 짜 놨는데, 그러면 **첫 카드를 내릴 자리가 없다.** 끄는 중일 때는 그 한 줄 자리가 놓기 대상이
  되게 하든, 끄는 동안만 상자를 내든 — **방법은 맡기되 "내릴 곳이 없는 상태" 를 남기지 마라.**
  T02 가 위 칸에서 같은 문제를 이미 풀었다(빈 작업 대상에도 놓을 수 있다) — 그 방식을 참고해라.
- **대기로 보내는 것은 "행을 지운다" 는 뜻이다** — `storedArea("waiting")` 는 `null` 이다
  (`areas.ts:31`, INV-B1). 새 값을 만들지 말고 그 함수를 그대로 써라.
- **클릭과 끌기를 가르는 기준은 그대로** `PointerSensor { distance: 6 }` 다. 대기 카드는 이제
  클릭도 끌기도 받으므로 이 값이 둘을 가른다 — 바꾸지 마라.

  `role` 이 덮이지 않게 배선을 갈라 놨다. 위 칸 카드는 이미 `<button>` 이므로 같은 함정을 조심해라.

### 충돌 판정 — `pointerWithin` → `rectIntersection` 을 **그대로 두었다**

바꾸지 않았다. 두 놓을 자리는 `<aside>` 안에서 위아래로 맞붙어 있을 뿐 **겹치지 않아**
포인터는 늘 둘 중 한 칸에만 들어간다 — `pointerWithin` 이 애매해지는 자리가 없다. 반대로
`closestCenter` 로 내려가면 오른쪽 티켓 컬럼에 놓아도 가까운 칸 하나가 늘 잡혀 T02 의 AC3
("아무 데도 아닌 곳")이 무너진다. 위 5번이 그것을 실제로 확인해 준다.

### 대기가 0 일 때 놓을 자리를 만든 방법

T01 의 "대기 0 이면 손잡이·상자를 만들지 않는다"를 **그대로 두고**, 그 바깥을 감싸는
`WaitingDropZone` 을 놓기 대상으로 뒀다. 대기가 0 이면 `WAITING — 대기 중인 기능이 없다` 한 줄이
곧 표적이고(위 4번), 있으면 손잡이+상자 전체가 표적이다. 빈 상자를 새로 내지 않으므로 T01 의
회귀 가드(빈 상자가 위 칸 자리를 먹지 않는다)도 그대로다.

### 키보드 — 집는 키를 Space 하나로 좁혔다

카드가 이제 **끌기와 선택을 둘 다** 받는데 dnd-kit 기본 시작 키는 Space·Enter 둘이라, 그대로 두면
Enter 가 끌기에 먹혀 키보드로 기능을 고를 길이 사라진다. `KeyboardSensor { keyboardCodes.start:
["Space"] }` 로 좁혀 **Space = 집기 · Enter = 선택**으로 갈랐다(화면 낭독 안내문도 그렇게 고쳤다).
그래서 위 칸 카드는 `<button>` 그대로 두고 끌기 배선을 그 위에 얹을 수 있었다 — T02 가 `<li>` 에서
피해야 했던 `role` 덮어쓰기 함정은 이미 버튼인 이 요소에는 생기지 않는다.

# T04 — steps 에서 문서를 읽으면 그 자리에서 읽음이 된다

**Blocked by:** T03

**Time:** started=2026-09-04T21:01:21+09:00 finished=2026-09-04T21:05:24+09:00

## Goal

steps 탭에서 티켓 문서를 열면 **그 화면의 `안 읽음` 표시가 즉시 사라진다.**
지금은 서버가 읽음으로 적는데 **화면만 모른다.**

## Why this slice

캡틴 확인(2026-09-04): *"티켓이 딸랑 한 개인데 그 티켓을 읽어도 계속 안 읽음 상태로 있어.
그 상태에서 작업 대상으로 올리면 자동으로 읽음 처리가 된다고. 대기 상태에 있을 때만 안 되고 있어."*

**올리면 풀린다**는 것이 곧 진단이다 — `usePlanMove` 가 성공 응답을 `plan` 캐시에 앉히기 때문에
그때서야 새 값이 보인다. 읽는 것 자체는 처음부터 되고 있었다.

## 원인 (실측 2026-09-04)

`code/web/frontend/src/lib/query.ts:294` — 문서를 열면 **`features` 캐시만** 무효화한다.

```ts
const doc = await fetchFeatureDoc(project, feature, path);
qc.invalidateQueries({ queryKey: qk.features(project) });   // ← plan 은 빠져 있다
```

그런데 **steps 탭은 `plan` 캐시를 본다**(`usePlanBoard`, 같은 파일 182줄). 그래서:

| 화면 | 보는 캐시 | 문서 열었을 때 |
|---|---|---|
| features 탭 | `features` | 무효화됨 → **바로 지워진다** |
| **steps 탭** | `plan` | **무효화 안 됨** → 남아 있다 |

같은 파일 **263~264줄**(`useRecordTime`)은 `plan` 과 `features` 를 **둘 다** 무효화한다 —
그쪽이 옳은 모양이고, 문서 열기만 한쪽을 빠뜨린 것이다.

🔴 **서버는 처음부터 옳았다.** 실측으로 확인했다 — `GET …/doc?path=tickets/T01.md` 를 부르면
그 티켓의 `unread` 가 `True → False` 로 바뀐다. 고칠 곳은 화면의 캐시 무효화 하나다.

## Produces

## Explicitly out of scope

- 🔴 **`안 읽음` 배지의 뜻을 바꾸지 마라.** "이 기능에 안 읽은 티켓이 하나라도 있다" 가 지금 뜻이고,
  티켓이 여럿이면 하나 읽어도 안 사라지는 것이 **옳은 동작**이다(실측 확인).
  표시를 개수로 바꾸는 것은 **별건**이고 캡틴 판단을 기다리는 중이다.
- 🔴 **`문서 열기`(spec.md)로 읽음이 되게 하지 마라.** 읽음은 **티켓**에만 걸린다
  (`unread-tickets-show-themselves/01`). 서버 판정을 건드리지 마라.
- 서버·contract·`process/dnd.ts` — 아무것도.

## Locked decisions

- **고치는 자리는 `useFeatureDoc` 하나다.** 263~264줄과 같은 모양으로 맞춘다.
- 🔴 **화면이 안 읽음 표시를 직접 지우지 않는다.** 지금 주석이 말하는 그대로 —
  서버가 다시 계산한 값을 다시 받아 그린다(INV-1). 낙관 갱신으로 손대지 마라.

## Scope

2. 회귀 테스트를 더한다 — 문서를 열면 `plan` 이 무효화되는지.
3. 🔴 **화면에서 확인한다** — steps 탭 대기 카드의 티켓을 열어 `안 읽음` 이 사라지는지.
   스킬 `gootte-dev-server`·`gootte-browser` 를 먼저 읽어라.

## Implementation notes

- 티켓이 **한 개**인 기능으로 확인해라 — 여럿이면 하나 읽어도 안 사라지는 것이 정상이라 헷갈린다.
- 확인 전에 **잠깐 가만히 두어라.** 파일을 방금 만들면 감시 이벤트가 흘러 우연히 갱신될 수 있고,
  그러면 고쳤는지 아닌지 못 가른다(내가 처음 재현에 실패한 이유가 바로 이것이다).

# T02 — 캡틴 리뷰: 실제 세션에서 `gootte memo` 로 메모를 읽고 논의할 수 있는가

**Blocked by:** T01

## Goal

T01 이 착지한 뒤 **캡틴이 눈으로 확인하는** 종단 티켓. 기계가 통과시킨 초록이 아니라, 요청의 목적인
"AI 세션이 읽어서 같이 논의" 가 실제로 되는지 사람 판정으로 닫는다.

## Why this slice

이 표는 코드를 만들지 않는다. 자동 판정으로 갈릴 수 없는 것 — 출력의 읽음새, 다중 줄 메모가 실제로
읽히는지, `- [ ]` 가 논의에 쓸모 있는지 — 을 마지막 자리에 남긴다.

## Produces

- 리뷰 결과(승인 / 수정 요구)와 그 기록(이 표의 `## Comments`).

## Consumers

- 캡틴. 코비는 없다.

## Touched surfaces

- 없음(읽기 전용 확인).

## Explicitly out of scope

- 새 요구 신설(다음 표로 붙인다).
- T01 의 코드를 이 표 안에서 고치는 일(수정이 필요하면 T01 을 다시 돌린다).

## Locked decisions

- 이 표는 **작업자에게 배치하지 않는다** — 오케스트레이터가 T01 검증 후 캡틴에게 브리핑하고, 캡틴의
  말로 닫는다.

## Evidence anchors

- `docs/features/memos-read-from-any-session/spec.md` 의 출력 규약
- 실제 호출: jinwooauto cwd 에서 `gootte memo`, `gootte memo --undone`

## Regression guards

- 다중 줄 메모(jinwooauto 실데이터 2건)가 화면이 아니라 셸에서도 한 항목으로 읽히는가.

## Scope

캡틴 확인 1회.

## Acceptance criteria

- AC1 캡틴이 자기 세션에서 `gootte memo` 를 쳐서 메모를 읽고, 출력에 이견이 없다.
- AC2 `gootte memo --undone` 이 "안 끝난 생각" 으로 논의하는 데 충분한지 확인된다.

## Verification

사람 확인. (코드는 T01 의 `pnpm verify` 가 이미 통과해야 한다.)

  기존 기능들(`memo-pad` 등)은 리뷰 표 없이 T01 하나로 끝났고, 이 충돌은 왕복 보고에 그대로 남긴다.

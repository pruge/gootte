# T01 — `gootte memo [--done|--undone]` — 지금 프로젝트 메모를 어떤 세션에서나 읽는다

**Blocked by:** 없음 — 즉시 착수 가능

## Goal

`gootte memo` 를 신설한다. **실행한 cwd 의 프로젝트 하나만**, `- [ ]` 목록으로 낸다.
`--done`/`--undone` 로 필터하고, 내용은 요약 없이 verbatim 으로 싣는다. 프로젝트 인자는 받지 않는다.

## Why this slice

메모를 읽는 통로가 화면 하나뿐이라 AI 세션이 대화에 못 쓴다. 캡틴 요청의 실제 모양은 CLI 였다
(grill 라운드 1 폐기 경위). **읽기**만 더하고 쓰기는 화면에 남기면 contract·백엔드·화면을 하나도
안 건드리고 수직으로 끝난다 — 파일 → 문자열 → 셸 한 줄.

## Locked decisions

1. 인자 규격: `memo [--done|--undone]` — **위치 인자 없음**. 프로젝트는 `slugFromCwd(cwd)`
   (`commands.ts:69-78`) 로만 정하고, 유추 실패는 `resolveProjectArg` 의 기존 안내 문구를 그대로
   쓴다("(프로젝트 안에서 실행하면 인자를 생략할 수 있다)").
   위치 인자가 하나라도 들어오면 `CliError("gootte memo 는 프로젝트 인자를 받지 않는다 — 지금 프로젝트만 봅니다")`.
   (캡틴 지시 2026-09-14 — `start`·`end`·`status` 처럼 세션의 프로젝트가 전부다.)
2. 필터 두 개를 같이 주면 `CliError("--done 과 --undone 을 같이 쓸 수 없다")` + usage.
3. 정렬 `createdAt` 내림차순, **안정 정렬**(같은 시각은 저장 순서). JS `Array#sort` 는 안정이라
   2차 키를 인위적으로 넣지 않는다.
4. 출력 헤더: `== <slug> · 메모 N건 (완료 A · 미완료 B) ==` — A/B 는 **필터 이전** 값. 필터가 있으면
   끝에 ` · 필터: done|undone`(화면에 잘린 목록을 전체처럼 그리지 않기).
5. 항목: `- [ ] YYYY-MM-DD <첫 줄>` + 두 번째 줄부터 **4칸 들여쓰기** verbatim continuation.
   `createdAt` 의 앞 10자만 쓴다(화면 날짜 그룹과 같은 규약 — `MemoView.tsx`).
6. 파일 없음 → `== <slug> · 메모 없음 ==` 출력 후 exit 0. 파싱 실패 → stderr 원인 + exit 1
   (`memo-store.ts` 의 "망가진 것을 빈 목록으로 위장하지 않는다" 를 CLI 가 삼킨 채 0건으로 그려선
   안 된다 — 같은 분기를 유지한다).
7. `bin/gootte` 라우트는 `working|pending`(`bin/gootte:755-762`)의 형태를 따되, 위치 인자와 플래그를
   **그대로** TS 에 넘긴다(`"${pos[@]:1}"` — 저 둘처럼 `pos[1]` 만 넘기면 `--undone` 이 사라진다).

## Regression guards

- 다중 줄 메모: 출력 후 다시 한 항목으로 붙는지(들여쓰기 규약) — 실데이터에 이미 존재하는 모양.
- `--done --undone` 동시 지정이 0건이 아니라 **오류**로 끝나는지.
- 손상 JSON 이 exit 1 + 원인 문자열로 끝나는지(빈 목록·`(메모 없음)` 과 구별).
- slug 없는 호출을 다른 프로젝트 cwd 에서 → 그 프로젝트 답(전체 조회로 새지 않는지).
- 위치 인자를 줘도 **다른 프로젝트로 읽히지 않는다**(오류로 끝난다).
- `bin/gootte memo --undone` 가 TS 에 `--undone` 을 실제로 도착시키는가(PATH 라우트 전용 회귀).
- `bin/gootte memo jinwooauto` — 셸 쪽이 위치 인자를 TS 로 넘긴 뒤 **오류로 끝나는지**(셸에서 조용히
  버리면 안 된다).

## Scope

한 세션 분량. contract·백엔드·프론트 미변경이라 drift-guard 대상이 아니다.

## Implementation notes

- `memoText` 는 `readMemos(planDataDir(), slug)` 결과를 `core-io` 순수 함수에 넘기기만 한다 — 계층
  분리 유지(계산은 core-io, 배선은 cli). slug 는 `slugFromCwd(cwd)` 하나에서만 온다.
- 새 `CliError` 메시지는 기존처럼 usage 문자열로 시작한다(`args.ts` 규약).
- `usage()` 한 줄 추가는 `main.ts` 의 배열과 `bin/gootte` 의 `usage()` **양쪽**에 한다(한쪽만 고치면
  PATH 경로에서 명령이 없는 것처럼 보인다).

## Acceptance criteria

- AC1 `gootte memo`(해당 프로젝트 cwd) → 헤더 + 항목 목록, 완료·미완료 섞임, 최신순.
- AC2 `gootte memo --undone` → `- [ ]` 항목만. 헤더 카운트는 전체 유지 + `· 필터: undone`.
- AC3 `gootte memo --done` → `- [x]` 항목만.
- AC4 다른 프로젝트에서 쳐도 **자기 프로젝트** 메모만 나온다. `gootte memo jinwooauto` 처럼 위치 인자를
  주면 exit 1 + "프로젝트 인자를 받지 않는다" 메시지(조용히 무시하거나 그 프로젝트로 읽지 않는다).
- AC5 메모 파일이 없는 신규 slug → `== <slug> · 메모 없음 ==`, exit 0.
- AC6 `--done --undone` → exit 1, 원인 한 줄.
- AC7 다중 줄 메모 한 줄이 출력에 **하나의 항목**으로 붙는다.
- AC8 `pnpm verify` green.

# 01 — 계획을 적고 다시 읽는다

**What to build:** 개발 계획(어느 티켓이 몇 단계인가, 어느 기능이 어느 트랙 몇 번째인가, 그리고 왜)을
**적고 다시 읽을 수 있게** 한다. gootte 자기 저장소의 SQLite 하나와 명령 몇 개.
지금은 그것을 담을 자리가 아예 없다.

**Blocked by:** 없음 — 🟢 **지금 착수 가능**

**Status:** resolved (2026-08-11)

## 캡틴 지시 (2026-08-11, 원문)

> sqlite로 db 만들어. 불변식 변경해. 정보관리하기시작한다. axi 명령툴로 쿼리/쓰기 가능하게해.
> 그리고 정보는 항상 새것으로 덮어쓰고 과거 이력은 남기지 않아.

## 🔴 먼저 불변식 — 이 티켓이 서는 땅이다

gootte 는 지금까지 **아무것도 저장하지 않는 제품**이었다(INV-1). 이 티켓이 그것을 처음 깬다.
그래서 **저장을 시작하기 전에 무엇을 저장해도 되는지부터 규칙으로 박는다.**

🔴 **INV-1 의 본문을 고쳐 쓰지 마라.** 이 저장소의 규칙이
*"번호는 재사용·리넘버하지 않는다. 불변식을 추가할 때는 다음 번호를 새로 딴다"*
(`AGENTS.md` §항목을 추가·수정하는 절차 4)이다. **INV-5 를 새로 딴다.**

`AGENTS.md` §제품 불변식 에 넣을 것:

> **INV-5 — 계획은 저장하고 사실은 저장하지 않는다.**
> 사람이 정한 것(단계 · 기능 순위 · 트랙 · 왜)은 gootte 자기 저장소에 저장한다.
> **원본을 다시 읽어 같은 값이 나오는 것은 저장하지 않는다** — 티켓 상태 · 막힘 ·
> 착수 가능 여부 · 처리중 · 임자 · 완료 · 제목.
> 판단 기준 한 줄: **다른 어디에도 없는 것만 저장할 자격이 있다.**

그리고 INV-1 에 **한 줄만** 더한다 — 무엇을 저장해도 되는지는 INV-5 가 갖는다는 가리킴.
🔴 INV-1 의 기존 문장은 그대로 둔다. 파생물 금지가 약해지는 것이 아니다.

`AGENTS.md` §빠른 판단 줄도 함께 고친다 — 지금은 *"새 파일을 쓰려 한다 → INV-1·INV-2"* 라
이 티켓의 저장을 금지하는 것처럼 읽힌다. **INV-5 가 그 갈래를 가른다는 것이 보여야 한다.**

## 무엇을 담나

**덮어쓰기 — 항상 최신만. 이력 테이블 없음.**

| 표 | 키 | 칸 |
|---|---|---|
| `feature_order` | 프로젝트 · 기능 | 트랙 · 순위 · 왜 · 왜_확인필요 · `updated_at` |
| `ticket_order` | 프로젝트 · 기능 · 티켓 | 단계 · 종류(`계획`\|`틈틈이`\|`순서밖`) · 왜 · `updated_at` |

🔴 **저 표에 없는 칸을 추가하지 마라.** 상태·막힘·완료·제목은 원본에서 다시 읽는다(INV-5).
**의존 관계도 적지 않는다** — 티켓의 `Blocked by:` 가 SoT 이고 이미 계산된다
(`core/src/project/features.ts` §`waitingOn`).

**단계의 뜻**: 같은 단계 = 병렬 가능. 단계가 다르면 = 순서. 정수 하나가 그 둘을 함께 적는다.

**순위는 성기게(10·20·30)** 매긴다. 🔴 **촘촘한 1·2·3 으로 하지 마라** — 하나 끼울 때마다
전부 밀리고, 그 밀림이 곧 낡음이다. 두 이웃의 중간값을 쓰고, 틈이 다 차면 그 트랙만 다시 매긴다.

🔴 **`왜` 는 비워 둘 수 없다.** 비울 수 있게 하면 다 비우고, 그러면 남는 게 숫자뿐이라
착지 한 번에 무의미해진다. 한 줄로 제한한다 — 긴 것은 features 문서 몫이다(캡틴 지시).

## `history.md`

순서가 바뀔 때마다 한 줄 덧붙인다 — 언제 · 무엇이 · 어디서 어디로 · 누가(명령/화면).
표가 아니라 파일인 이유: **통째로 읽어 흐름을 보는 물건**이고, **DB 가 날아가도 남는 유일한 기록**이다.

🔴 **이 파일을 읽어서 계산에 쓰지 마라.** 사람과 planner 가 읽는 메모다.

## 명령

```
gootte-axi set         <프로젝트> <기능>/<번호> --step 3 --why "…"
gootte-axi set         <프로젝트> <기능>/<번호> --kind 틈틈이 --why "…"
gootte-axi set-feature <프로젝트> <기능> --track web --rank 20 --why "…"
gootte-axi drop        <프로젝트> <기능>[/<번호>]
gootte-axi order       <프로젝트>                            (전부 --json)
```

`order` 는 이 티켓에서는 **적힌 것을 그대로 되읽는다.** 티켓 상태와 맞춰 보는 일과
어긋남 표시는 다음 티켓(02)이 가져간다 — 여기서는 **적은 것이 그대로 나오는지**만 증명한다.

🔴 저장 자리는 gootte 자기 것이다. **관리대상에는 아무것도 쓰지 않는다**(INV-2).
INV-2 가 예외로 열어 둔 `.gootte/` 네임스페이스조차 쓰지 않는다.

## 완료 시 시연 가능한 것

planner 가 터미널에서 `set-feature` · `set` 으로 gootte 자신의 계획을 적고,
`gootte-axi order gootte` 로 **적은 그대로** 다시 읽는다.
같은 티켓에 `set` 을 두 번 하면 **뒤엣것만 남는다**(덮어쓰기). `history.md` 에 두 줄이 쌓인다.

# 09 — 주황색 상자 하나가 서로 다른 두 가지를 말한다

**What to build:** `plan` 탭의 주황색 상자 둘 — **어긋남**(계획과 티켓이 갈라졌다)과
**놓는 순간 알아챈 것**(방금 그 드래그가 걸렸다) — 을 **눈으로 구분되게** 하고,
드래그 경고가 **자기 조건이 사라지면 스스로 없어지게** 한다.

**Blocked by:** 없음 — 지금 착수 가능

**Status:** ready-for-agent

## 캡틴 지시 (2026-08-11, 원문)

> "테스트할때는 어긋나는 것이 없으면 주황색 box가 안보였었는데. 지금은 없는데도 주황색 box가 남아 있네."

## 🔴 무엇이 실제로 일어났나 (2026-08-11 실측)

캡틴이 보신 상자는 **어긋남 상자가 아니다.** 그때 어긋남은 실제로 0 이었다 —
살아 있는 서버에 물어 확인했다:

| 확인한 것 | 결과 |
|---|---|
| `gootte order jinwooauto` | `어긋남: 없음` |
| 떠 있는 서버 `/api/plan/jinwooauto` | `mismatches: 0`, 빈 배열 |
| 어긋남 목록 컴포넌트 | 0 건이면 아무것도 안 그린다 — **정상 동작** |

남아 있던 것은 **드래그 경고 상자**다. 🔴 **둘이 같은 옷을 입고 나란히 서 있다.**

| | 어긋남 | 드래그 경고 |
|---|---|---|
| 테두리·배경 | `partial/40` · `partial/10` | **똑같다** |
| 모서리 | `rounded-lg` | **똑같다** |
| 글자색 | `text-partial` | **똑같다** |
| 자리 | `plan` 탭 위쪽 | **바로 붙어 있다** |
| 뜻 | 계획과 티켓이 갈라졌다 | 방금 그 드래그가 뭔가에 걸렸다 |
| 언제 사라지나 | 어긋남이 없어지면 자동 | 🔴 **캡틴이 ✕ 를 누를 때만** |

**그래서 캡틴이 하나를 다른 하나로 읽으셨다.** 이건 캡틴의 착각이 아니라 화면의 결함이다 —
두 가지가 구분 불가능하게 생겼으면 구분해서 보라고 요구할 수 없다.

## 🔴 이 결함은 이미 예고돼 있었다

티켓 06 이 같은 갈래를 적어 뒀다:

> 🔴 **04 의 즉시 검사와 섞지 마라.** 저것은 기계가 아는 사실이라 그 자리에서 끝나고,
> 이것은 **판단**이라 사람에게 간다. 화면에서도 두 덩이가 구분돼야 한다.

그 규칙이 06(의견 요청)에만 적용되고 **02 의 어긋남과 04 의 경고 사이에는 안 적용됐다.**
같은 화면에 주황색 상자가 셋까지 설 수 있다 — 06 이 붙으면 더 나빠진다.

## 고칠 것 둘

### ① 경고가 스스로 없어진다

지금 드래그 경고는 **드롭 성공 시 세팅되고 ✕ 로만 지워진다.** 그래서:

- 캡틴이 경고를 보고 **곧바로 다시 끌어 문제를 없애도** 경고는 그대로 남는다.
- 계획이 다른 경로(터미널 `set`·`drop`, 티켓 08 의 자동 제거)로 바뀌어도 남는다.
- 탭을 떠났다 와도 남을 수 있다.

🔴 **경고는 "그 시점의 배치에 대한 말"이므로, 배치가 바뀌면 더 이상 참이 아니다.**
바뀐 배치에서 다시 성립하지 않는 경고는 **스스로 없어져야 한다.**

🔴 **판정을 화면에서 새로 짜지 마라.** 네 검사는 이미 서버(`checkTicketDragWarnings`)가 계산한다 —
같은 판정을 화면이 다시 하면 그 순간 두 답이 생긴다. **다시 물어서 받은 답으로 갱신한다.**

🟡 **✕ 는 남긴다.** 캡틴이 알면서 그대로 두시는 것이 정당한 경우가 있고(티켓 04),
닫은 것은 배치가 다시 바뀌기 전까지 닫힌 채로 있어야 한다.

### ② 둘이 서로 다르게 생긴다

🔴 **색을 바꾸는 것으로 때우지 마라.** 두 상자의 차이는 색이 아니라 **성격**이다:

| | 어긋남 | 드래그 경고 |
|---|---|---|
| 무엇에 대한 말인가 | **계획 전체**의 상태 | **방금 한 동작** 하나 |
| 언제 생기나 | 계획이나 티켓이 바뀔 때 | 캡틴이 놓는 순간 |
| 누가 없애나 | 계획을 고치면 없어진다 | 배치가 바뀌거나 캡틴이 닫으면 |
| 놓칠 때의 대가 | 계획이 조용히 낡는다 | 이번 드래그가 조금 어긋난다 |

**항상 있는 것**과 **방금 일어난 것**이 같은 무게로 보이면 안 된다.
구체적 모양은 구현자가 정하되, 위 성격 차이가 **읽히는지**가 판정 기준이다.

🔴 **어긋남을 접거나 숨기지 마라**(티켓 03) — 이 티켓은 그 규칙을 안 건드린다.

## 완료 시 시연 가능한 것

캡틴이 `plan` 탭에서 티켓 칩을 막힘 역행이 되게 끈다. 주황색 경고가 뜬다.
곧바로 다시 끌어 제자리로 돌린다 — **경고가 스스로 사라진다.**
어긋남이 하나도 없는 상태에서 화면에는 **주황색 상자가 하나도 없다.**
일부러 어긋남을 하나 만들면(계획에 있는 티켓 문서를 지운다) 어긋남 상자가 뜨는데,
그 상자는 드래그 경고와 **한눈에 다르게 생겼다.**

## 완료 조건

- [ ] 어긋남 0 건 · 유효한 경고 0 건이면 `plan` 탭에 주황색 상자가 **하나도 없다**
- [ ] 드래그로 생긴 경고가, 그 조건이 사라지면 **✕ 없이 사라진다**
- [ ] 계획이 다른 경로(터미널 · 티켓 08 자동 제거)로 바뀌어도 낡은 경고가 안 남는다
- [ ] 🔴 경고 판정을 **화면에서 다시 짜지 않는다** — 서버 계산을 그대로 쓴다
- [ ] ✕ 로 닫은 경고는 **배치가 다시 바뀌기 전까지** 닫힌 채로 있다
- [ ] 어긋남 상자와 경고 상자가 **한눈에 구분된다**
- [ ] 🔴 어긋남은 여전히 **접히지도 숨겨지지도 않는다**
- [ ] `features` 탭의 동작이 하나도 안 바뀌었다

## 캡틴 확인

**어디서:** gootte `plan` 탭.

**무엇을 하나:** 티켓 칩을 일부러 잘못된 자리로 끌어 경고를 띄운 뒤, 다시 제자리로 끈다.
그리고 어긋남이 없는 상태에서 화면 위쪽을 본다.

**무엇이 보여야 맞나:**

1. 🔴 **아무 문제가 없을 때 주황색이 하나도 안 보이나.** 이것이 이 티켓의 이유다.
2. 🔴 **문제를 되돌렸을 때 경고가 저절로 사라지나.** ✕ 를 눌러야만 사라지면 안 고쳐진 것이다.
3. **어긋남과 드래그 경고가 서로 다른 것으로 읽히나** — 둘을 나란히 띄웠을 때
   어느 쪽이 "계획이 낡았다"이고 어느 쪽이 "방금 한 동작"인지 알 수 있나.

## 이 티켓이 하지 않는 것

- **어긋남 판정 자체** — 티켓 02 가 만든 계산을 안 건드린다.
- **네 검사 판정 자체** — 티켓 04 가 만든 서버 계산을 안 건드린다.
- **의견 요청 상자(06)** — 다만 이 티켓이 정한 구분을 06 도 따라야 한다.
- **되돌리기** — 만들지 않는다(캡틴 결정: 이력 없음).

# 04 — 캡틴이 끌어서 순서를 바꾼다

**What to build:** `plan` 탭에서 **끌어서** 순서를 바꾼다. 티켓 칩을 단계 사이로, 기능 카드를 순위 사이로.
놓는 순간 기계가 아는 것(막힘 역행 · 이미 끝난 것 · 임자 있음)을 **그 자리에서** 알려준다.
🔴 **gootte 가 처음으로 쓰기 경로를 갖는다.**

**Blocked by:** [03](03-the-plan-tab-shows-the-whole-order.md) — 끌 화면이 먼저 있어야 한다

**Status:** resolved (2026-08-11)

## 캡틴 지시 (2026-08-11, 원문)

> 내가 드래그해서 순서를 변경할수 있다.
> 즉 a feature -> b feature가 개발 순서로 잡혀있는데. 내가 b를 드래그해서 a 위로 올릴수 있다.

## 🔴 이 티켓이 성격을 바꾼다

gootte 는 지금까지 **읽기만 하는 제품**이었다. 이 티켓이 첫 쓰기 경로를 만든다.

- 쓰기는 **gootte 자기 DB 로만** 간다. 🔴 **관리대상으로 가는 쓰기는 코드에 존재하지 않게 한다**(INV-2).
  INV-2 가 예외로 열어 둔 `.gootte/` 네임스페이스조차 쓰지 않는다.
- 저장하는 것은 계획뿐이다 — 단계 · 순위 · 트랙 · 왜(INV-5).
  🔴 **드래그 결과로 상태·완료·막힘이 저장되는 일이 없어야 한다.**

## 무엇이 바뀌나

| 무엇을 끄나 | 무엇이 바뀌나 |
|---|---|
| 티켓 칩 → 다른 단계 줄 | 그 티켓의 **단계** |
| 티켓 칩 → 줄과 줄 **사이** | **새 단계가 생긴다**(뒤 단계가 밀린다) |
| 티켓 칩 → 틈틈이 자리 | 종류가 `틈틈이` 가 되고 단계가 없어진다 |
| 기능 카드 → 같은 트랙 안 다른 자리 | 그 기능의 **순위** |
| 기능 카드 → 다른 트랙 | 그 기능의 **트랙**(과 새 트랙 안 순위) |

🔴 **순위 계산은 01 이 만든 `core` 의 순수 함수를 쓴다.** 두 이웃의 중간값 하나 —
**줄 하나만 바뀌고 나머지는 안 밀린다.** 화면에서 다시 짜면 터미널과 다른 번호를 매기게 된다.

## 놓는 순간 — 기계가 아는 것만, 즉시

| 검사 | 예 |
|---|---|
| 막힘 역행 | 이 티켓이 기다리는 것을 뒤 단계로 보냈다 |
| 이미 끝난 것 | 완료된 티켓을 앞 단계에 뒀다 |
| 임자 있음 | 지금 누가 붙들고 있는 티켓의 자리를 바꿨다 |
| 낡은 막힘 사유 | 기다린다고 적힌 것이 이미 착지했다 |

🔴 **이 검사에 planner 를 부르지 마라.** 그래프 한 번 걸어 나오는 값이라 **즉시** 답해야 하고,
read-path 가 LLM 을 기다리면 INV-4 가 무너진다. 판단이 필요한 것은 티켓 06 이 가져간다.

🔴 **검사 결과로 드래그를 막지 마라.** 알려주되 캡틴의 결정을 되돌리지 않는다 —
경고를 알고도 그렇게 두는 것이 정당한 경우가 있다(고장 수리를 먼저 하는 등).

## `왜` 는 안 건드린다, 대신 표시가 붙는다

드래그는 **순위·단계만** 바꾼다. 그런데 그 기능·티켓의 `왜` 는 방금 캡틴이 뒤집은 판단의 문장이라
**이제 거짓일 수 있다.**

→ `왜_확인필요` 를 세우고 화면에 **확인 필요**로 표시한다. 🔴 지우지도, 기계가 새로 쓰지도 마라 —
사람이 쓴 문장을 기계가 갈아 끼우면 그것이 INV-4 가 막는 추론이다.

## `history.md`

드래그 한 번이 한 줄이다 — 언제 · 무엇이 · 어디서 어디로 · 누가(화면).
🔴 **되돌리기는 만들지 않는다.** DB 는 최신만 갖는다(캡틴 결정). `history.md` 는 되짚기를 도울 뿐이다.
그 사실을 화면 어딘가에 조용히 알린다 — 되돌릴 수 있다고 오해하면 캡틴이 마음 놓고 끄신다.

## 완료 시 시연 가능한 것

캡틴이 `plan` 탭에서 기능 카드 하나를 다른 것 위로 끈다. 순서가 바뀌고, 그 기능의 이유에
**확인 필요** 표시가 붙는다. 새로고침해도 그대로다. 티켓 칩을 다른 단계로 끌면 그 단계가 바뀌고,
줄 사이에 놓으면 새 단계가 생긴다. 막힘을 역행시키면 **놓는 즉시** 그 사실이 뜬다 —
그래도 캡틴이 원하시면 그대로 둘 수 있다.

## 캡틴 확인

**어디서:** gootte `plan` 탭.

**무엇을 하나:** 기능 카드를 위아래로 끌어 본다. 티켓 칩을 다른 단계로, 그리고 줄과 줄 사이로 끌어 본다.
새로고침해 본다.

**무엇이 보여야 맞나:**

1. 🔴 **끄는 동안 어디에 놓이는지가 보이나.** 놓을 자리가 안 보이면 캡틴이 짐작으로 손을 떼시게 된다.
2. 🔴 **줄 사이에 놓아 새 단계를 만드는 것이 "여기 새 단계" 로 읽히나.** 그냥 그 줄에 합쳐지는 것과
   구분이 안 되면 이 조작은 못 쓴다.
3. **놓은 뒤 바뀐 것이 분명한가** — 순위 숫자와 확인 필요 표시가 눈에 들어오나.
4. 🟡 **되돌릴 수 없다는 것이 전해지나.** 실수로 끌었을 때 무엇을 해야 하는지 알 수 있나.

## 완료 조건

- [ ] 티켓 칩을 단계 사이로 끌면 단계가 바뀌고 남는다(새로고침 후에도)
- [ ] 줄과 줄 사이에 놓으면 **새 단계가 생기고** 뒤가 밀린다
- [ ] 기능 카드를 끌면 순위가 바뀌고, **다른 줄의 순위는 그대로**다
- [ ] 다른 트랙으로 끌면 트랙이 바뀐다
- [ ] 🔴 순위 계산이 01 의 **같은 순수 함수**다 — 화면에 복제본이 없다
- [ ] 네 검사가 **놓는 즉시** 뜬다. LLM 을 기다리지 않는다
- [ ] 검사가 드래그를 **막지 않는다**
- [ ] `왜` 본문은 그대로이고 **확인 필요** 표시만 붙는다
- [ ] `history.md` 에 한 줄 는다
- [ ] 🔴 관리대상 파일이 **하나도 안 바뀐다**
- [ ] 🔴 DB 에 상태·완료·막힘이 **안 들어간다**

## 테스트

| 무엇 | 어디 | 첫 커버인가 |
|---|---|---|
| 드래그 → 쓰기 → 재조회로 값이 남는다 | `frontend` 단위 | 🔴 예 |
| 줄 사이 놓기 = 새 단계, 뒤가 밀린다 | `core` 단위(순수 계산) | 🔴 예 |
| 순위 재계산이 이웃만 건드린다 | `core` 단위 | 🟢 01 이 만듦 — 재사용 |
| 네 검사 각각 | `core` 단위 | 🔴 예 |
| 쓰기 경로가 관리대상을 안 만진다 | `backend` 단위 | 🔴 예 |

🔴 **마지막 줄을 빼지 마라.** INV-2 는 이 티켓이 처음으로 시험대에 올리는 규칙이고,
테스트가 없으면 다음 사람이 "편의상" 한 줄 적는 것을 아무도 못 막는다.

## 이 티켓이 하지 않는 것

- **의견 요청 버튼과 답 표시** — 티켓 06.
- **되돌리기** — 만들지 않는다(캡틴 결정: 이력 없음).
- **`왜` 를 기계가 다시 쓰는 일** — 사람이 쓴다.
- **드래그로 티켓·기능을 만들거나 지우는 일** — 계획의 자리만 바꾼다.

# 03 — `plan` 탭이 전체 개발 순서를 보여준다

**What to build:** 머리말 `features` 옆에 **`plan` 탭**을 두고, 누르면 전체 개발 순서가 보인다.
단계가 가로줄이고 같은 줄에 있으면 병렬이다. `next` 버튼을 누르면 지금 나란히 보낼 수 있는 것이 선택된다.
읽기 전용 — 이 티켓에서는 끌지 않는다.

**Blocked by:** [02](02-next-names-what-can-go-together.md) — 화면의 `next` 버튼이 02 의 함수를 그대로 쓴다

**Status:** claimed

## 캡틴 지시 (2026-08-11, 원문)

> 내가 보는 화면에는 전체 개발 순서고 표시된다.

> 헤더에 features가 있는데 그 옆에 schedule? plan? (이름 제안) 을 두고 그것을 클릭하면 보이게하자.

## 이름은 `plan`

| 후보 | 판단 |
|---|---|
| **`plan`** | 🟢 **채택** — INV-5 의 말 그대로다(*“**계획**은 저장하고 사실은 저장하지 않는다”*) |
| `schedule` | 🔴 **없는 날짜를 약속한다.** 이 기능은 날짜를 갖지 않는다 — 화면이 거짓말한다 |
| `roadmap` | 🔴 **은퇴한 어휘**다 |
| `order` | 🟡 코드의 `sortFeatures`·`rank` 어휘와 겹치고 영어로 뜻이 갈린다 |

🟢 **탭 이름이 곧 경계선이 된다** — `plan` 에 있는 것은 gootte 가 **저장하는 것**,
`features` 에 있는 것은 전부 원본에서 **다시 계산한 것**.

## 🟢 새 장치를 만들지 마라 — 구조가 이미 기다리고 있다

2026-08-11 실측:

| 사실 | 어디 |
|---|---|
| 탭 띠는 항목 하나지만 **여러 개를 받도록 지어져 있다** | `frontend/src/components/main/Tabs.tsx` `TABS` 배열 |
| 탭은 URL `?tab=` 에 있고 `Tab` 은 union 이다 | `frontend/src/hooks/useUrlState.ts` |
| `view` 는 이미 **탭별 보기 모드**다 — 주석: *“탭별 뷰모드(raw) — 소비처가 유효값 해소”* | 같은 파일 |
| 탭을 바꾸면 `view` 가 초기화된다 | 같은 파일 `setTab` |

→ `?tab=plan&view=step` · `?tab=plan&view=feature`.
🔴 **새 라우팅도 새 상태 훅도 만들지 마라.** `Tab` union 에 한 값, `TABS` 에 한 줄이면 된다.

## 두 보기

**단계 보기**(기본, `view=step`) — 단계가 가로줄. 한 줄에 티켓 칩 여럿 = 병렬.
칩에 기능 이름·번호·현재 상태가 붙는다. 트랙마다 자기 단계 묶음을 갖는다.

**기능 보기**(`view=feature`) — 트랙이 세로줄, 그 안에 기능 카드가 순위대로. 카드마다 티켓과 그 단계.

🔴 **보기 둘을 쪼개지 마라.** 같은 데이터의 두 표현이라 한 번에 잡아야 서로 어긋나지 않는다.

🔴 **트랙을 한 줄로 펴지 마라.** 트랙은 병렬이고 다루는 사람이 다르다 —
억지로 한 줄 세우면 **나란히 보낼 수 있다는 사실이 화면에서 사라진다.**

## `next` 버튼

누르면 그 집합이 화면에서 **선택 표시**된다. 다시 누르면 풀린다.

🔴 **선택 계산을 화면에서 다시 짜지 마라.** 02 가 만든 `core` 의 순수 함수를 그대로 쓴다.
화면과 터미널이 각자 판정하면 **둘이 다른 답을 하고 그 순간부터 하나는 거짓이다.**

빈 결과일 때 02 가 붙인 이유를 화면도 그대로 보여준다 — 빈 화면은 *"할 일 없음"* 과
*"전부 막힘"* 을 구분하지 못한다.

## 어긋남

02 가 계산한 어긋남 세 줄을 화면에도 띄운다. 🔴 **접거나 숨기지 마라** —
이것이 계획과 티켓이 갈라진 것을 알아채는 유일한 자리다.

## 상태는 저장된 값이 아니다

칩에 붙는 상태(끝남·막힘·임자·착수 가능)는 **볼 때마다 티켓에서 다시 읽은 값**이다(INV-3·INV-5).
🔴 계획 쪽 응답에 상태를 실어 캐시하지 마라.

## 완료 시 시연 가능한 것

캡틴이 gootte 를 열고 머리말에서 **`plan`** 을 누른다. 전체 개발 순서가 단계별로 보이고,
같은 줄에 있는 것이 병렬이라는 게 눈에 들어온다. **`next`** 를 누르면 지금 나란히 보낼 수 있는 것이
화면에서 도드라진다. 주소를 그대로 북마크하면 같은 화면이 다시 열린다.

## 캡틴 확인

**어디서:** gootte 를 열고 머리말의 **`plan`** 을 누른다.

**무엇을 하나:** 단계 보기를 훑고, **`next`** 를 눌러 본다. **기능 보기**로 바꿔 본다.

**무엇이 보여야 맞나:**

1. 🔴 **같은 줄에 있는 것이 "동시에 해도 된다" 로 읽히나.** 순서가 맞나가 아니라
   **병렬이 병렬로 보이나**가 판정 기준이다.
2. 🔴 **`next` 를 눌렀을 때 선택된 것이 먼저 눈에 들어오나.** 티가 안 나면 그것은 강조 문제이고,
   **이 티켓에 흡수하지 말고 별건으로 돌린다.**
3. 🟡 **머리말 띠에 항목이 둘이 되는 것은 이번이 처음이다** — 지금까지 활성/비활성 대비가
   화면에 나타난 적이 없다. `features` 와 `plan` 중 **지금 보고 있는 쪽이 분명한가.**

## 완료 조건

- [ ] `plan` 탭이 머리말에 있고 누르면 열린다. 주소(`?tab=plan`)로 바로 열린다
- [ ] 두 보기가 있고 `?view=` 로 남는다. 탭을 바꾸면 초기화된다(기존 동작)
- [ ] 단계 보기에서 **같은 단계가 한 줄**에 있다. 트랙이 따로 그려진다
- [ ] `next` 버튼이 **02 의 함수**를 쓴다 — 화면에 판정 로직이 없다
- [ ] 빈 결과에 이유가 보인다
- [ ] 어긋남 세 줄이 접히지 않고 보인다
- [ ] 🔴 상태를 캐시하지 않는다 — 티켓이 바뀌면 다시 열었을 때 따라온다
- [ ] `features` 탭의 동작이 하나도 안 바뀌었다

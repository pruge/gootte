# 05 — 티켓 밖에서 더 개발된 것을 잡는다

**What to build:** firstmate 가 *“이 티켓을 하면서 저것까지 같이 만들었다”* 를 남길 자리를 만든다.
planner 는 **새로 등록된 것만** 읽고, 그만큼 낡은 다른 티켓을 고친 뒤 처리 표시를 남긴다.
지금은 그것을 알아채는 장치가 **아예 없다.**

**Blocked by:** [01](01-the-plan-is-written-down-and-read-back.md) — 저장 자리가 먼저 있어야 한다
🟢 **02·03·04 와는 안 겹친다 — 나란히 진행 가능**

**Status:** ready-for-agent

## 🔴 메우는 구멍 — 티켓이 낡는 가장 흔한 경로

누가 A 를 하면서 B 의 절반을 같이 만들면, **B 티켓은 아무 표시 없이 틀린 문서가 된다.**
B 를 집는 다음 사람은 이미 있는 것을 다시 만들거나, 사양과 코드가 어긋난 채로 짓는다.

관리대상 jinwooauto 에서 실제로 있었던 일이다 — 코드 주석 수십 곳이 자기를 `access-control 10` 이라
부르는데 **그 번호의 티켓이 없다**(`#54` 가 티켓 없이 착지했다).
근거를 찾는 다음 사람이 없는 티켓을 뒤지게 됐다.

이 티켓은 그 사건을 **일어나는 시점에 기록으로 남게** 한다.

## 표

| 표 | 키 | 칸 |
|---|---|---|
| `extra` | 항목 id | 프로젝트 · 기능 · 티켓 · 무엇이 더 개발됐나 · 누가 · **처리됨** · `created_at` |

🔴 **덮어쓰기가 아니라 큐다.** 순서 표 둘(`feature_order`·`ticket_order`)과 성격이 다르다 —
저쪽은 *지금의 계획* 이라 최신만 남으면 되고, 이쪽은 **하나씩 소비하는 목록**이라 쌓인다.

🔴 **처리 표시는 지우는 것이 아니라 표시다.** 질의 기본값이 **미처리만**이라 쌓여도 읽기가 안 느려진다.
무엇을 처리했는지가 **곧 티켓을 왜 고쳤는지의 근거**이므로 자동으로 지우지 않는다.

## 명령

```
gootte-axi extra add  <프로젝트> <기능>/<번호> "…"   firstmate 가 남긴다
gootte-axi extra                                    🔴 미처리만 — 새로 등록된 것만 나온다
gootte-axi extra --all                              처리분까지
gootte-axi extra done  <id>                          planner 가 티켓을 고친 뒤
gootte-axi extra prune --before <날짜>                오래된 처리분 정리 — 🔴 자동 아님
                                                     (전부 --json)
```

`extra add` 의 `<기능>/<번호>` 는 **더 개발된 쪽**을 가리킨다 —
*"A 를 하다 B 를 건드렸다"* 에서 **B** 다. 낡은 것이 B 이기 때문이다.
누가 남겼는지(`누가`)와 어느 작업 중이었는지는 본문에 적는다.

🔴 **존재하지 않는 티켓을 가리켜도 거절하지 마라.** 아직 티켓이 없는 것을 만들었을 수도 있다
(위 `#54` 가 정확히 그 경우다). 대신 **가리키는 티켓이 없다는 사실을 목록에 표시한다** —
그것 자체가 planner 가 알아야 할 신호다.

## firstmate 가 깨어나는 방식

🔴 **`extra` 는 `ask`(티켓 06)와 같은 규약을 쓴다 — 미처리가 있을 때만 한 줄 찍고, 없으면 침묵한다.**
그래야 firstmate 의 사용자 정의 확인 장치 **하나**로 둘 다 깨어난다.

- 있으면: 한 줄. 몇 건인지와 대표 하나.
- 없으면: **아무것도 출력하지 않는다.**
- 제한 시간 안에 끝난다.

🔴 **새 데몬을 만들지 마라.** 밀어 주기도, 주기 실행도 이 티켓 밖이다.

## 완료 시 시연 가능한 것

firstmate 가 `gootte-axi extra add gootte development-order/02 "next 계산 짜면서 어긋남 표시까지 같이 만듦"`
을 친다. planner 가 `gootte-axi extra` 를 치면 **그 한 건만** 나온다.
티켓을 고친 뒤 `extra done <id>` 를 치고 다시 `extra` 를 치면 **아무것도 안 나온다.**
`extra --all` 로는 처리됨 표시와 함께 보인다.

## 완료 조건

- [ ] `extra add` 로 항목이 쌓인다
- [ ] `extra` 기본값이 **미처리만**이다
- [ ] `extra done` 이 표시만 하고 **지우지 않는다**
- [ ] `extra --all` 이 처리분까지 보여준다
- [ ] `extra prune --before` 가 있고, **자동으로 돌지 않는다**
- [ ] 없는 티켓을 가리켜도 **거절하지 않고**, 없다는 사실을 목록에 표시한다
- [ ] 미처리가 없을 때 **아무것도 출력하지 않는다**(firstmate 확인 규약)
- [ ] 🔴 이 표가 `next` 계산에 **들어가지 않는다** — planner 가 읽는 메모다
- [ ] `--json` 이 있다

## 이 티켓이 하지 않는 것

- **티켓을 고치는 일** — planner 가 자기 배달 경로로 관리대상에 쓴다. gootte 는 관리대상에 안 쓴다(INV-2).
- **무엇이 낡았는지 기계가 판단하는 일** — 사람이 적고 사람이 읽는다(INV-4).
- **화면 표시** — 이 티켓은 터미널까지다. 화면이 필요해지면 그때 별건이다.
- **의견 요청** — 티켓 06. 같은 규약을 쓸 뿐 다른 물건이다.
- **밀어 주기·주기 실행** — firstmate 의 기존 확인 장치가 가져간다.

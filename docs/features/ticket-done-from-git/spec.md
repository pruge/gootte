# Specification — ticket-done-from-git

## Goal
신관례 티켓의 완료 상태를 firstmate 홈 백로그 조인에서 추적 remote 브랜치의 git 히스토리 파생으로
바꾼다. 캡틴이 외부에서 개발해 기본 브랜치에 머지하면 대시보드가 완료로 바뀌고, 항해사에게 매번
완료 처리를 부탁할 필요가 없어진다. 부하 모델은 증분·캐시·브랜치 SHA 게이트(기동 시 풀 스캔 없음).

## User stories
1. 캡틴이 티켓 구현 커밋을 기본 브랜치에 머지하면(커밋 메시지에 티켓 토큰 포함), 대시보드 해당 티켓이
   곧바로 완료로 표시된다.
2. 앱을 재기동해도 완료 상태가 사라지지 않는다(디스크 캐시).
3. 앱 기동 시 git 을 다시 훑지 않는다 — 캐시 히트 시 git 작업 0.
4. 새로운 커밋이 하나만 착지해도 그 커밋만 증분 스캔한다(push 당 비용 = 새 커밋 수).
5. 구현 커밋이 없는 문서/검수 티켓은 티켓 문서의 명시적 상태 줄로 완료 판정한다(백로그 조인 없이).
6. 구관례 티켓의 완료 판정은 지금과 똑같이 문서가 출처다(바뀌지 않음).
7. 머지 직후부터 대시보드가 완료를 보는 사이 대기 지연은 코드 변경이 화면에 뜨는 기존 지연과 같다.

## Scope
- 신관례 티켓(새 티켓 문서) 완료 판정 원천 교체(백로그 → git 리졸버 + 선택적 문서 상태).
- git 리졸버 모듈 신설 + 디스크 캐시 + 추적 remote 브랜치 SHA 게이트.
- 백그라운드 재검증기에 fetch + 리졸버 재계산 훅.
- 상태 조인 모듈이 신관례 티켓 상태를 리졸버에서 읽도록 전환.
- 신관례 티켓 파서에 선택적 상태 줄 파싱(하이브리드 폴백).

## Out of scope
- 되돌림(revert) 자동 미완료.
- 백로그 조인 로직 자체의 삭제(기획·의존성 추적용 보존).
- 캡틴 수동 재검증 트리거.
- 티켓 번호 규칙 자체의 변경.

## Decisions
- D1 완료 출처 = git(추적 remote 브랜치 reachable), not backlog — `grill.md` D1.
- D2 증분·캐시·SHA 게이트, per-launch 풀 스캔 금지 — `grill.md` D2.
- D3 커밋↔티켓 연결 = 티켓 토큰(선택적 Closes/Ticket trailer) — `grill.md` D3.
- D4 트리거는 재검증기에 매단다 + clone fetch, 기준 SHA 는 추적 remote 브랜치 — `grill.md` D4.
- D5 하이브리드 폴백: 문서/검수 티켓은 문서 상태 줄(문서가 SoT) — `grill.md` D5.
- D6 전이 자연스러움(기존 landed 티켓은 커밋에 티켓 토큰 있어 자동 완료) — `grill.md` D6.

## Existing seams / integration points
- 읽기 전용 git CLI 위임 층 — 새 헬퍼(범위 내 커밋 메시지 읽기 + fetch)를 여기에 둔다.
- 상태 조인 모듈 — 신관례 티켓 상태를 조인한다. 여기서 리졸버로 교체한다.
- 백그라운드 재검증기 — 재검증 트리거. 여기에 fetch + 리졸버 훅.
- 기능/티켓 파서 — 신관례 티켓을 읽는다(상태 없음). 여기서 선택적 상태 줄을 더 읽는다(구관례
  파서가 쓰는 상태 파서 재사용).
- 호출처(대시보드·터미널 보드·머리글 배지 검증) — 모두 상태 조인 모듈을 호출하므로 한 곳만 바꾸면
  리졸버 경로를 탄다.

## Data and migration
- 새 캐시 파일: 영구 스냅샷 저장소 아래 — `{ remoteSha, done: Record<"${slug}#${num}", true> }`.
- 기존 백로그 기록은 그대로. 완료 판정만 원천이 바뀐다. 마이그레이션 없음(전이 자연스러움, D6).

## Security / authorization
- git 작업은 전부 읽기 전용(log/rev-parse) + fetch(로컬 추적 상태 비파괴). 로컬 커밋·브랜치는
  건드리지 않는다.

## Compatibility / rollout
- 구관례 경로는 변경 없음 — 회귀 없음.
- 직렬 배포: 리졸버 → 트리거 → 대시보드 전환 순으로 붙으면 중간 상태에서도 기존 백로그 조인이
  리졸버로 점진 치환된다. 폴백(문서 상태)은 리졸버와 평행.

## Acceptance criteria
- 신관례 티켓: 추적 remote 브랜치에 티켓 토큰 커밋이 reachable 이면 대시보드 완료, 아니면 미완료.
- 앱 재기동 후 캐시에서 완료 상태 복원(풀 스캔 없음).
- 추적 remote 브랜치 SHA 불변 시 git 작업 0(캐시 히트).
- 새 커밋 1개 착지 → 그 커밋만 증분 스캔.
- 문서/검수 티켓: 문서 명시 상태 있으면 완료, 없으면 git 판정.
- 구관례 티켓 완료 판정은 변함없이 문서 기준.

## Verification strategy
- routine: 프로젝트 검증 태스크(typecheck + 전체 테스트) 통과.
- elevated: 상태 조인 테스트(조인 교체), 티켓 파서 테스트(상태 줄), 재검증기 테스트(fetch 훅) 새 케이스.
- critical: 직접 검증 — 테스트 커밋(티켓 토큰)을 기본 브랜치에 올리고 대시보드 완료 전환 확인,
  앱 재기동 후 캐시 복원 확인.

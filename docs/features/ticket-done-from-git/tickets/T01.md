# T01 - git 기반 티켓 완료 리졸버

## Goal
`origin/main` git 히스토리에서 티켓 완료를 파생하는 리졸버를 만든다. `(repo, slug, num)` 을
받아 해당 티켓이 main 에 착지했는지(= `T<NN>` 을 가진 커밋이 `origin/main` 에 reachable) bool 로
돌려주고, 결과를 디스크에 캐시하며 `origin/main` SHA 로 게이트한다.

## Why this slice
완료 판정의 핵심 엔진. T02(트리거)·T03(대시보드 전환)·T04(폴백) 모두 이 리졸버의 done-set 을
소비한다. 이게 없으면 나머지는 붙일 곳이 없다.

## Produces
- `resolveTicketDone(repo, slug, num): boolean` — `origin/main` 에 `T<NN>` 을 가진 커밋이 reachable 이면 true.
  - 디스크 캐시 `ticket-git-status.json`: `{ shas: Record<repo, string|null>, done: Record<repo, Record<num, true>> }` — repo(Clone 경로)별 격리, 키는 num 만(`slug` 는 git 신호에 없음, grill D3).
- 캐시 갱신 함수 `revalidateTicketGitStatus(repo)`: `origin/main` SHA 가 바뀌면
  `git log <lastSha>..origin/main` 으로 새 커밋 메시지에서 `T<NN>` 토큰을 추출해 done 에 추가.

## Consumers
- `applyBacklogStatus`(T03) — 신관례 티켓 상태를 이 리졸버에서 읽는다.
- `snapshot-revalidator`(T02) — `origin/main` 이 움직이면 `revalidateTicketGitStatus` 를 부른다.
- 대시보드 머리글 배지(`deriveHeaderBadge`) — 티켓 done 집합에서 파생.

## Touched surfaces
  - 신규 `code/web/core-io/src/ticket-git-status.ts`(리졸버 + 캐시). 🔴 `core` 가 아니라 `core-io` — `core-io` 가 이미 `core` 를 의존하므로 `core` 가 `core-io` 를 되의존하면 순환 의존+레이어링 위반. git 헬퍼와 동행해야 해서 `core-io` 가 올바른 층.
  - `code/web/core-io/src/git.ts` — 새 헬퍼 `commitMessagesInRange(repo, range): string[]`
    (`git log <range> --format=%H%x1f%B` 로 해시+**전체본문** — `%s`(제목)가 아니라 `%B`(본문)로 읽어 `Closes:`/`Ticket:` trailer 도 매칭, grill D3), `originMainSha(repo): string | null`
    (`git rev-parse origin/main`).

## Explicitly out of scope
- 대시보드 배선(T03), fetch/트리거(T02), 문서 상태 폴백(T04) — 이 티켓은 순수 리졸버+캐시만.
- 되돌림(revert) 감지.

## Locked decisions
- D1 완료 = `origin/main` reachable(`grill.md` D1).
- D2 증분 스캔(`<lastSha>..origin/main`), SHA 게이트, 디스크 캐시(`grill.md` D2).
- D3 연결 규칙 `T<NN>` 토큰 + `Closes:`/`Ticket:` trailer(`grill.md` D3).
- 기준 SHA 는 로컬 HEAD(`headCommit`)가 아닌 `origin/main`(`grill.md` D4).

## Scope
- `resolveTicketDone` + `revalidateTicketGitStatus` + 캐시 직렬화/역직렬화.
- `commitMessagesInRange`, `originMainSha` 헬퍼 추가(`core-io/src/git.ts`).

## Implementation notes
- `originMainSha` 가 null 이면(remote 없음/미 fetch) 리졸버는 false 를 돌리고 캐시를 안 건드린다
  (안전: 백로그 조인이 사라진 티켓이 갑퀴 완료로 안 뜨게).
- 토큰 매칭: `\bT(\d{1,3})\b` 를 커밋 메시지에서 찾고, 티켓 `num` 과 대조. 대소문자 구분 안 함.
- 캐시 파일은 `snapshot.ts` 의 `dataDir` 아래에 둔다(영구 스냅샷 저장소와 같은 수명).

## Acceptance criteria
- `origin/main` 에 `T05` 커밋이 있으면 `resolveTicketDone(repo, slug, "05")` = true.
- `origin/main` SHA 동일 → `revalidateTicketGitStatus` 가 `git log` 를 호출하지 않는다(캐시 히트).
- SHA 변경 → 마지막 SHA 이후 커밋만 스캔해 done 갱신.
- `origin/main` 를 못 읽으면 예외 대신 false(대시보드 깨짐 방지).

# T03 - 대시보드 상태 원천 전환(백로그 → 리졸버)

## Goal
신관례 티켓의 완료 상태를 firstmate 홈 백로그 조인에서 T01 git 리졸버로 바꾼다. 대시보드가
완료를 보는 경로가 백로그가 아니라 `origin/main` 히스토리가 된다.

## Why this slice
이 티켓이 실제로 "join 없이 캡틴이 스스로 완료 처리" 를 화면에 연결한다. 리졸버(T01)가 있어도
대시보드가 여전히 백로그를 보면 아무것도 안 바뀐다.

## Produces
- `applyBacklogStatus`(및 내부 `joinTicket`)가 신관례 티켓 상태를 `readBacklogTasks` 조인이 아니라
  `resolveTicketDone(repo, slug, num)`(T01) 에서 읽도록 교체.
- 구관례(`issues/`) 경로는 기존대로 문서가 출처(변경 없음).

## Consumers
- `backend/src/app.ts:272`(features 탭), `app.ts:400`(관측 기능), `cli/src/commands.ts:166`
  (terminal 보드), `scripts/verify-header-badge.ts:19`(머리글 배지 검증) — 전부 `applyBacklogStatus`
  호출처라 한 곳만 바꾸면 모두 리졸버 경로를 탄다.

## Touched surfaces
- `code/web/core/src/project/backlog-join.ts` — `applyBacklogStatus`, `joinTicket`,
  `joinTicketBacklog`(신관례 분기만 리졸버로).
- `code/web/core/src/project/features.ts:123`(신관례 상태는 조인 전 항상 pending — 리졸버가 채움).
- 호출처 4곳(`app.ts`, `cli/src/commands.ts`, `scripts/verify-header-badge.ts`) — 시그니처 변경 없이
  내부만 교체(리졸버 의존 주입).

## Explicitly out of scope
- 리졸버 로직(T01), fetch/트리거(T02), 문서 폴백(T04).
- 기획·의존성 추적용 백로그 조인 제거 — 보존(완료 판정 원천만 바뀜).

## Locked decisions
- D1 완료 출처 = git, not backlog(`grill.md` D1). 구관례는 문서 출처 유지.
- D5 하이브리드 폴백은 T04 가 끼워 넣는다 — 이 티켓은 리졸버 경로만 세팅.

## Regression guards

  `features.test.ts`, `frontend/e2e/dashboard.spec.ts`(화면 완료 표시).

## Scope
- `applyBacklogStatus` 내 신관례 분기만 리졸버로 교체. `repo`·`slug`·`num` 은 이미 있다.
- 리졸버 의존은 `applyBacklogStatus` 호출처에서 주입(테스트는 리졸버 stub 로 돌림).

## Implementation notes
- `resolveTicketDone` 이 false(remote 없음/미 fetch)를 돌리면 기존 동작과의 회귀를 막기 위해
  잠깐 pending 으로 두는 게 아니라, 설계대로 미완료로 본다(백로그 조인이 사라진 티켓이 완료로
  안 뜨게 — `grill.md` D1/D5 정신). 단, fetch 실패로 일시적으로 못 읽으면 캐시된 마지막 값을
  유지하는 게 안전할 수 있음 — 구현 시 판단(테스트로 고정).
- `deriveHeaderBadge` 는 티켓 done 집합에서 파생하므로 이 티켓만으로 배지도 따라온다.

## Acceptance criteria
- 신관례 티켓: `origin/main` 에 `T<NN>` reachable 이면 대시보드 완료, 아니면 미완료.
- 구관례 티켓 완료 판정은 문서 기준으로 변함없이 동작.
- 4개 호출처 모두 리졸버 경로를 탐(백로그 조인 신관례 분기 제거).

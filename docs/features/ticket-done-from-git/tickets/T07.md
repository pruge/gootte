# T07 — slug 매칭 범위를 넓혀 광범위 미탐 회귀를 고친다

## Goal

T06(slug 범위 완료 판정)이 오탐(다른 기능의 같은 번호 티켓이 완료로 잘못 뜸)을 고치다가
**광범위 미탐**(진짜 완료된 티켓도 완료로 안 뜸) 회귀를 만들었다. slug 인식 패턴을 실제
커밋 스타일에 맞게 넓혀서 이 회귀를 고친다.

## Bug (T06이 만든 회귀)

T06의 `extractSlugs`는 두 패턴만 인식한다:
1. Conventional commit scope: `type(slug): ...`
2. Trailer: `Ticket:`/`Feature:`/`Scope:` 줄

실측: `origin/main`의 커밋 322개 중 **121개(37%)가 이 패턴에 안 걸려 slug 미인식** →
그 커밋이 가리키는 티켓은 이제 완료로 안 뜬다. 실제 캡틴 커밋 스타일 다수가 안 걸린다:

- `T01: projects 페이로드 캐시 (fix/spinner-spin)` — scope 없이 티켓 번호가 맨 앞
- `core-io: 명부를 실물에 적힌 그대로 읽는다 (T01) (#75)` — scope는 있지만 slug가 아니라 다른 이름
- `one-setting-finds-every-copy T05: 설정은 ... (#86)` — slug가 괄호 없이 맨 앞에 옴
- `docs(features): ticket-time-stamp — plan (grill/spec/tickets T01-T03) (#90)` — scope가 `features`라 실제 slug와 다름

재현 결과 **14개 기능이 영향받음** — `ticket-done-from-git` 자기 자신의 T05조차 완료로 안 뜬다.
(전체 재현 데이터는 이 티켓을 만든 조사 세션의 firstmate 대화 로그 참조 — 재현 스크립트는
아래 Evidence anchors에 절차를 남긴다.)

## Root cause

T06이 "커밋 스타일이 이미 slug를 conventional scope로 쓴다"고 가정했지만, 실제 저장소는
scope 없이 `T<NN>:` 로 시작하거나, scope에 slug 대신 건드린 패키지 이름(`core-io`, `backend`)을
쓰거나, slug가 괄호 없이 자유 위치에 오는 스타일이 훨씬 많다.

## Produces

- slug 매칭을 **"커밋 메시지 어디든 실제 존재하는 기능 slug 문자열이 대소문자 무관하게
  등장하는가"** 방식으로 넓힌다 — `docs/features/` 디렉터리 목록에서 slug 후보를 가져와
  메시지 전체(제목+본문)를 스캔.
- 기존 conventional scope·trailer 매칭은 유지(더 정확한 신호이므로 우선/보강).
- `T<NN>` 토큰과 slug 문자열이 **같은 커밋 메시지 안에** 있으면 그 slug 아래 완료 기록.
- slug 후보 목록은 매 리졸브 시 `docs/features/` 를 다시 읽지 않고, 호출자가 주입하거나
  캐시 무효화 시점에 한 번만 읽는다(성능 — 매 revalidate마다 디렉터리 스캔 금지).

## Explicitly out of scope

- slug 문자열이 정말 커밋 메시지에 전혀 없는 경우(예: 티켓 제목만 의역해서 씀) — 이건
  근본적으로 판정 불가능한 케이스이고 이 티켓 범위 밖. 실측으로는 322개 중 5개 정도만
  남는데, 그 정도는 허용 오차로 남긴다.
- 캐시 스키마 변경 — `done[repo][slug][num]` 구조는 T06 그대로 유지, 매칭 로직만 바꾼다.

## Locked decisions

- 🔴 **회귀 방지 — 실물 커밋 이력 전체를 회귀 시험 픽스처로 고정한다.** T06은 자기가
  지어낸 좁은 픽스처만 검증해서 이 회귀를 못 잡았다. 이 티켓은 `git log origin/main`의
  **전체 커밋 322개**(또는 스냅샷 시점의 전체)를 픽스처로 캡처해 "각 기능의 각 티켓 번호가
  최소 하나의 완료 신호를 갖는가"를 회귀 시험으로 고정한다.
- 🔴 **안전 쪽 오류 유지** — slug를 여전히 하나도 못 뽑으면 기록 안 함(T06 원칙 유지,
  오탐보다 미탐).
- 🔴 **AC1~AC4(T06)는 계속 통과해야 한다** — 이 티켓은 오탐 방지 회귀를 깨지 않는다.
- 매칭은 대소문자 무관, slug 안의 하이픈은 그대로(정규화 없음).

  인식되는지 검증.
- 전체 저장소 스냅샷 대조 시험(가능하면) — 모든 기능의 모든 티켓 번호가 최소 하나의
  완료 신호 경로를 갖는지 확인하는 통합 시험.

## Acceptance criteria

1. `T01: projects 페이로드 캐시 (fix/spinner-spin)` 처럼 scope 없이 번호가 앞에 오는 커밋도
   해당 slug가 메시지 어딘가에 있으면 인식된다(이 예시는 slug가 없으므로 여전히 미인식이
   맞다 — 실제로는 이런 메시지엔 slug가 아예 없다. 진짜 기준은 아래 3.).
2. `one-setting-finds-every-copy T05: 설정은 ...` 처럼 slug가 괄호 없이 맨 앞에 오는 커밋은
   `one-setting-finds-every-copy`의 T05로 인식된다.
3. `core-io: 여러 사본의 기능 문서를 합치고 나중 판을 고른다 (one-setting-finds-every-copy T02) (#81)`
   처럼 slug가 괄호 안 자유 위치에 오는 커밋도 인식된다.
4. T06의 AC1~AC4(오탐 방지)는 계속 통과한다.
5. 실물 커밋 이력 전체 대조 시험에서, 이 수정 전 미인식이었던 14개 기능 중 최소 일부가
   해소됨을 수치로 보여준다(0건까지 안 가더라도 개선폭을 시험이 고정).
6. `pnpm -C code/web verify` green.

## Verification

routine. 실물 `git log` 출력을 픽스처로 캡처해서 쓴다(지어내지 않는다) — 이 조사에서
쓴 재현 방식(전체 커밋 순회 + 기능별 티켓 번호 대조)을 그대로 회귀 시험 골격으로 옮긴다.

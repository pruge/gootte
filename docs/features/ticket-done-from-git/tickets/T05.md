# T05 - 캡틴 검수(종착 티켓)
Time: started=2026-08-28T12:48:41+09:00 finished=2026-08-29T09:38:02+09:00

## Goal
이 기능 전체(T01~T04)가 착지한 결과를 캡틴이 직접 검수한다. 기계가 판정 못 하는 것을 캡틴이
직접 본다 — 대시보드가 git 리졸버로 완료를 보여주는지, 구관례 티켓은 기존처럼 문서 기준인지,
앱 재기동 후 캐시가 유지되는지, 새 push 가 늦지 않게 따라가는지.

## Why this slice
모든 비시각·기계 판정은 T01~T04 가 끝낸다. 남은 것은 캡틴의 눈으로 확인 — 설계가 의도한
"매번 항해사에게 부탁하지 않아도 된다" 가 실제로 성립하는지.

## Produces
- 착지 결과 요약 + 검수 체크리스트(아래 Acceptance 기반).
- 피드백 → 필요 시 T01~T04 중 하나로 follow-up 티켓 파생.

## Consumers
- 캡틴(직접 검수).

- `code/web/core/src/project/backlog-join.ts`(T03)
- `code/web/core/src/parse/feature.ts`(T04)

## Explicitly out of scope

## Locked decisions
- D1~D6 전부 이 기능의 설계 기준(`grill.md`). 검수는 이 기준 충족 여부를 본다.

## Evidence anchors

## Regression guards
- `pnpm -C code/web verify` 전체 통과(T01~T04 의 테스트 포함).

## Scope

## Implementation notes
- 검수 항목: (1) 신관례 티켓이 `origin/main` 에 `T<NN>` 커밋 착지 시 완료로 뜨는가,
  (2) 앱 재기동 후 완료 상태가 캐시에서 복원되는가(풀 스캔 없이),
  (3) 새 push 가 대시보드에 늦지 않게 반영되는가,
  (4) 문서/검수 티켓이 문서 `Status:` 줄로 완료되는가,
  (5) 구관례 티켓 완료 판정이 기존 문서 기준과 동일한가.

## Acceptance criteria
- 위 5항목 캡틴 확인 통과.
- 회귀: 기존 백로그 조인 기반 대시보드 동작(구관례) 유지.

## Verification
- 캡틴 직접 검수 + `pnpm -C code/web verify`.

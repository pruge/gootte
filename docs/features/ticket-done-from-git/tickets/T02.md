# T02 - 배경 트리거 + origin fetch
Time: started=2026-08-28T12:48:41+09:00 finished=2026-08-28T13:14:03+09:00

## Goal
gootte 가 읽는 clone 이 `origin/main` 을 fetch 하고, `origin/main` SHA 가 바뀌면 T01 리졸버
캐시를 무효화·재계산하도록 `snapshot-revalidator` 에 매단다. 캡틴이 push 해도 대시보드가 늦게
못 따라가게 한다.

## Why this slice
리졸버(T01)는 캐시돼 있지만, 캡틴 push 를 clone 이 알지 못하면 `origin/main` SHA 가 안 바뀌고
재계산이 안 일어난다. fetch + 트리거가 "계속 개발해도 부하 없이 따라간다" 는 약속의 반쪽이다.

## Produces
- `snapshot-revalidator.run()` 이 시작 시 `fetchOrigin(repo)` 를 먼저 호출(roots 의 각 repo).
- `origin/main` SHA 가 바뀌면 `revalidateTicketGitStatus(repo)`(T01) 호출 → 리졸버 캐시 갱신.
- 재검증기 `onChange` 체인에 티켓 재검증을 걸어, 화면이 다음 tick 에 새 완료를 본다.

## Consumers
- 리졸버(T01) 캐시 — 이 티켓이 갱신 주체.
- 대시보드(T03) — 갱신된 캐시를 읽어 완료 표시.

## Touched surfaces
- `code/web/backend/src/snapshot-revalidator.ts` — `run()` 에 fetch + 리졸버 훅.
- `code/web/backend/src/snapshot.ts` — `revalidateSnapshot` 이 `headCommit`(로컬 HEAD) 기준인데,
  티켓은 `origin/main` 기준임을 명시(리졸버가 자체 SHA 를 잡으므로 재검증기 변경은 최소).
- `code/web/core-io/src/git.ts` — 새 헬퍼 `fetchOrigin(repo): void`(`git fetch origin`,
  조용히 실패 처리 — remote 없음이면 no-op).

## Explicitly out of scope
- 리졸버 로직(T01), 대시보드 배선(T03), 문서 폴백(T04).
- 로컬 브랜치/커밋 변경 — fetch 만(비파괴).

## Implementation notes
- `fetchOrigin` 은 `git fetch origin` 을 `gitSafe` 스타일로 감싸고, 실패(remote 없음·오프라인)면
  조용히 무시 — 앱 기동을 막지 않는다.
- 재검증기 기존 15초 fallback 폴링 안에서도 fetch 가 돌아가므로, watch 없이도 주기적으로 따라간다.
- 로컬 HEAD(`headCommit`)가 아니라 `origin/main` SHA 를 리졸버가 직접 잡게 해 fetch 만으로
  갱신이 감지되도록 한다(fetch 는 `origin/main` 만 움직임).

## Acceptance criteria
- clone 에 캡틴이 push 하면(그 전 fetch 후) 다음 재검증 tick 에 리졸버 캐시 갱신 → 대시보드 완료.
- `origin/main` 불변 → 재검증 tick 이 리졸버를 부르지 않는다.
- remote 없음 → fetch 가 조용히 no-op, 앱 정상 기동.

## Verification
- 단위: fetch/no-op/SHA-게이트 케이스.
- 수동: 테스트 clone 에 push 후 대시보드가 늦지 않게 완료로 바뀜 확인.

# T04 - 하이브리드 폴백(문서/검수 티켓은 문서 상태)

Status: resolved (2026-08-28)
Time: started=2026-08-28T12:48:41+09:00 finished=2026-08-28T14:07:26+09:00

## Goal
구현 커밋이 없는 문서/검수 티켓(예: `one-setting-finds-every-copy-t06` 종착 검수 티켓)도
백로그 조인 없이 완료 판정되게 한다. 티켓 문서(`tickets/T<NN>.md`)에 선택적 `Status:` 줄을
읽어, 있으면 그것이 출처(문서가 SoT)가 되게 한다.

## Why this slice
#2(git 리졸버) 단독으로는 머지 커밋이 없는 티켓은 자동 완료될 수 없다. 캡틴이 매번 부탁하는
패턴의 절반(검수 티켓)이 남는다. 문서 상태 폴백이 그 반쪽을 막는다.

## Produces
- `parseNewTicket`(feature.ts) 가 티켓 문서에서 선택적 `Status:` 줄을 읽어 `status`/`statusKnown`/
  `completedAt` 을 채운다(구관례 `parseTicket`의 `parseStatusLine` 재사용).
- 리졸버(T01)/`applyBacklogStatus`(T03) 우선순위: 문서에 명시 상태 있으면 그것, 없으면 git 리졸버.

## Consumers
- 리졸버(T01) — 폴백 판정에 문서 상태 포함.
- `applyBacklogStatus`(T03) — 신관례 티켓 상태 조립 시 문서 상태를 고려.

## Touched surfaces
- `code/web/core/src/parse/feature.ts` — `NewTicketDoc` 에 선택적 상태 필드(`status`/`statusKnown`/
  `sourceStatus`/`completedAt`) 추가, `parseNewTicket` 이 `parseStatusLine`/`mapFirstmateStatus` 로 채움
  (줄 없으면 `statusKnown: false`·기본 pending — 리졸버·백로그가 채움, 회귀 없음).
- `code/web/core/src/project/features.ts` — `toNewTicket` 이 문서 상태를 그대로 신관례 `FeatureTicket` 에
  싣는다(명시 상태는 build 시점부터 보존, `applyBacklogStatus` 재판정이 최종).
- `code/web/core/src/project/backlog-join.ts` — `joinTicket` 우선순위: **문서 명시 상태 > git 리졸버 >
  백로그 조인**. `ticket.statusKnown` 이면 문서가 SoT(`backlogStatus` 도 문서 상태로) — 머지 커밋 없이
  `Status: resolved` 만으로 완료, `wontfix` 면 dropped(리졸버 true 여도 문서가 이김, grill D5).

## Explicitly out of scope
- 리졸버 코어(T01), fetch/트리거(T02), 대시보드 배선(T03) — 이 티켓은 파싱+폴백 우선순위만.

## Locked decisions
- D5 하이브리드: 문서/검수 티켓은 문서 `Status:` 줄(문서가 SoT), 코드 티켓은 git(`grill.md` D5).
- 문서 상태 어휘는 구관례와 동일(`resolved`→done, `wontfix`→dropped) — 새 어휘 없음.

## Evidence anchors

  `parseStatusLine`/`mapFirstmateStatus`(구관례가 쓰는 상태 파서 — 그대로 재사용).

## Regression guards

  `backlog-join.test.ts`(신관례=리졸버/문서, 구관례=문서).

## Scope
- `NewTicketDoc` 에 `status`/`statusKnown`/`completedAt`/`sourceStatus` 필드 추가.
- `parseNewTicket` 이 `parseStatusLine` 으로 채움(펜스 밖만, `parseStatusLine` 규칙 그대로).
- 리졸버/조인 병합: 문서 상태 있으면 우선, 없으면 git.

## Implementation notes
- `parseNewTicket` 은 본래 "문서에 상태 없음(SoT 는 백로그)" 이었음 — 이제 선택적 상태를 읽되,
  없으면 기존처럼 리졸버가 채우도록 둔다(회귀 없음).
- 상태 줄 포맷은 구관례와 동일(예: `resolved (2026-08-28)`) — `parseStatusLine`
  이 이미 처리.
- 검수 티켓은 캡틴이 직접 `Status: resolved` 를 적으면 완료(백로그 조인 불필요).

## Acceptance criteria
- 티켓 문서에 `Status: resolved` 있으면 대시보드 완료(머지 커밋 없이도).
- 문서에 상태 없으면 git 리졸버 판정이 적용(기존 #2 동작).
- `wontfix` 등 명시 취소는 dropped 로 반영(구관례와 동일).

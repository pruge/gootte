# T01 — 문서가 사라진 작업 대상 카드가 계획판을 죽이지 않게 한다
Status: resolved (2026-08-26)

## Goal

배치 행이 가리키는 기능의 문서가 없어도 `/api/plan/:slug` 가 500 으로 죽지 않게 한다.
그 카드는 단계·`next` 에서 조용히 빠질 뿐, 판 전체와 다른 카드는 그대로 산다.

## Why this slice

2026-08-26 캡틴이 실물로 겪은 장애다(재현·스택은 spec §실측). 원인은 `indexActiveSteps`
(`core/src/plan/step.ts:29`)의 비-널 단언 하나다 — 고칠 곳이 한 곳이라 한 장으로 충분하다.

## Produces

- `core/src/plan/step.ts` 의 가드: `featureOf.get(slug)` 가 undefined 면 그 slug 를 건너뛴다.
- 회귀 시험 — 반드시 첫 커버:
  1. active 배치 + 문서 없는 slug → `computeDisplaySteps` 이 던지지 않고 결과를 돌려준다
  2. 같은 상황에서 `computeNext` 도 던지지 않는다
  3. 살아 있는 다른 카드의 단계 표시는 그대로다

## Consumers (grep 실측 출력)

즉 화면과 CLI 가 같은 함수를 지난다 — core 가드 하나로 둘 다 막힌다.

## Implementation notes

- 🔴 배치 행을 지우거나 고치지 마라 — 자리는 캡틴 것이다. 읽는 쪽만 견디게 한다.
- 🔴 판정 자리를 새로 만들지 마라 — 여전히 `computeDisplaySteps` 하나(INV).
- 🔴 `splitIntoAreas` 는 이미 문서 없는 배치를 견딘다(실측: 크래시는 그 다음 단계) — 그쪽을 넓히지 마라.
- 시험 자리는 인접 기존 관례를 따른다(`core/src/plan/step.test.ts` 등).

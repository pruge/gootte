## Goal

Read-side consumers that currently call `@gootte/core-io` state-store functions directly are migrated to use `@gootte/time-ledger` package read API. **This is migration of read paths, NOT mutation deletion.** Badge recompute stays in `@gootte/core-io` adapter (not time-ledger).

## Exact scope (what moves to package read API)

- `code/web/core-io/src/features.ts` — `joinTimeRecords`/`readFeaturesWithTime` that call `readTicketRecords` → use package read API
- `code/web/backend/src/routes/time.ts` — `readFeatures`, `joinTimeRecords` → use package read API
- `code/web/backend/src/app.ts` — `recalcProjectState` → badge adapter calls package read
- `code/web/cli/src/migrate-time.ts` — read-side operations → package read API
- `code/web/cli/src/cli.test.ts` — updated for new read paths
- Badge adapter: `code/web/core-io/src/state-store.ts` — `recalcProjectState` modified to call package read (NOT deleted — badge stays in core-io)

**NOT in scope:** `readTicketRecords`, `upsertTicketRecord`, `removeTicketRecord` mutation functions (T06 deletes these). `state-store.ts` overall structure stays.

## Badge adapter decision

Badge recompute is in `@gootte/core-io/src/state-store.ts` (NOT in `@gootte/time-ledger`). T03 modifies the adapter to call `@gootte/time-ledger` package read API for data, but the recompute logic stays in core-io. This means `recalcProjectState` is NOT deleted in T06 — only the old ticket mutation functions are deleted.

## Entry point

Read-side consumers call `@gootte/time-ledger` package read API instead of `@gootte/core-io` state-store directly.

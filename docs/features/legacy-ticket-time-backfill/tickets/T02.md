# T02 — 캡틴 검수 (종착 티켓)

## Goal

T01이 채워 넣은 시각 기록 줄들이 화면에서 올바르게 반영되는지 캡틴이 직접 확인한다.
기계가 판정 못 하는 것을 캡틴이 직접 본다.

## Why this slice

T01은 문서 편집과 근거 조사만 담당한다. 그 결과가 실제 화면에서 자연스럽게 보이는지,
매칭 실패 목록을 어떻게 처리할지는 캡틴의 눈과 판단이 필요하다.

## Produces

- 검수 결과와, 매칭 실패 티켓 처리 방향에 대한 캡틴의 결정.

## Consumers

- 캡틴(직접 검수). 후속 조치가 필요하면 새 follow-up 티켓으로 파생한다.

## Touched surfaces

- 코드 변경 없음. T01이 고친 48개 티켓 문서를 화면에서 확인만 한다.

## Explicitly out of scope

- 추가 문서 편집이나 코드 구현 — 검수만. 피드백은 새 티켓으로.

## Locked decisions

- 캡틴 결정 2026-08-29 (B안)이 이 기능 전체의 설계 기준이다. 검수는 이 기준의 결과물이
  화면에 올바르게 반영됐는지를 본다.

## Evidence anchors

- T01의 진행 보고(근거로 쓴 커밋 해시 목록, 매칭 실패 목록).

## Regression guards

- 없음(문서·화면 검수만, 자동화된 시험 대상 아님).

## 검수 항목

1. T01의 진행 보고에 적힌 "매칭 실패" 목록이 납득할 만한지 (더 조사해서 채울지,
   그대로 pending으로 둘지 결정).
2. plan 탭에서 백필된 몇몇 티켓에 마우스를 올리면 걸린 시간이 자연스럽게 뜨는지.
3. steps 탭에서도 같은 값·같은 문구로 뜨는지.
4. 걸린 시간 값이 터무니없지 않은지(예: 음수, 수백 일처럼 명백히 잘못된 값이 없는지).
5. 건드리지 않아야 할 `ticket-time-stamp/T02.md`가 그대로인지.

# T01 — 착지 완료된 구 티켓들에 git 근거로 시각 기록 줄을 채워 넣는다
Time: started=2026-08-29T16:49:42+09:00 finished=2026-08-29T16:49:42+09:00

## Goal

작업 시각 기록 줄이 없는 신관례 티켓(`docs/features/<slug>/tickets/T<NN>.md`) 48개 전부를
git 이력 근거로 조사해, 이미 실제로 구현·착지된 것은 시작·완료 시각 줄을 정확한 위치·형식으로
삽입한다. 최근 결정(ADR-0001) 이후 완료 판정이 이 줄에만 의존하게 되면서, 이 줄이 없는 옛
티켓들이 전부 "대기"로 잘못 표시되고 있다.

## Why this slice

`gootte start`/`end` 명령은 호출 "그 순간"의 시각만 찍기 때문에 과거 작업을 소급해서 채우는
데 쓸 수 없다(캡틴 결정, B안). 그래서 이 작업은 CLI를 부르는 대신 git 로그에서 직접 시각을
역산해 파일에 써넣는 조사·판단 작업이며, 코드 변경이 전혀 없는 문서 전용 슬라이스로 독립될
수 있다.

## Produces

- 48개 티켓 파일 각각에 (매칭 가능한 경우) `Time: started=<ISO> finished=<ISO>` 한 줄.
- 매칭 실패(근거 불충분) 티켓의 명시적 목록 — 캡틴 검수 티켓(T02)에서 보고할 자료.

## Consumers

- 티켓 파서 — 이 줄을 읽어 시작·완료 시각을 도출하고, 그 값이 완료 판정과 plan/steps 탭의
  걸린 시간 툴팁으로 이어진다. 새 코드를 쓰지 않는다 — 기존 소비자가 이미 이 줄을 읽는다.

## Touched surfaces

아래 24개 기능 디렉터리의, 이미 시각 기록 줄이 있는 것만 제외한 티켓 파일 전부
(총 48개 — 2026-08-29 조사 기준). 정확한 목록은 아래 명령으로 재확인한다:

```
cd projects/gootte  # 또는 크루 워크트리
find docs/features -path '*/tickets/T*.md' | sort | while read f; do
  grep -q '^Time:' "$f" || echo "$f"
done
```

해당 기능들: `a-quoted-path-is-not-a-parent`, `a-ticket-tells-how-long-it-took`,
`a-vanished-card-breaks-nothing`, `both-conventions-are-first-class`,
`every-home-reports-its-status`, `fast-cold-start`, `one-setting-finds-every-copy`,
`steps-start-from-dependencies`, `tauri-desktop-app`,
`the-header-agrees-with-its-tickets`, `the-roster-line-as-written`,
`the-terminal-agrees-with-the-screen`, `ticket-done-from-git`, `ticket-time-stamp`
(T01/T03/T04/T05만 — T02는 이미 시각 기록 줄이 있으므로 건드리지 않음).

## Explicitly out of scope

- 구관례 티켓 (파서가 안 읽음, 이 결정과 무관).
- 이미 시각 기록 줄이 있는 `ticket-time-stamp/T02.md`.
- `docs/features/` 아래 `tickets/` 디렉터리 자체가 없는 기능(spec만 있거나 구관례):
  `a-long-list-stays-usable`, `development-order`, `feature-doc-browser`,
  `firstmate-migration`, `firstmate-project-source`, `plan-board`,
  `status-colors-tell-apart`, `the-eye-mark-comes-from-one-place`,
  `ticket-row-repair`, `unread-tickets-show-themselves`, `work-claims-its-ticket`.
- 코드 변경 전부. 이 티켓은 마크다운 파일만 고친다.

## Locked decisions

- 캡틴 결정 2026-08-29 (B안): git 이력에서 역산한 실제 시각을 쓴다. CLI로 지금 시각을
  찍지 않는다.
- 시각 기록 줄의 정확한 형식과 삽입 위치는 기존 CLI가 이미 정한 계약이다 — 그 형식을
  그대로 따른다: 제목(`# ...`) 줄 바로 다음, 빈 줄이나 다른 메타 줄보다 앞. 한 줄에
  `Time: started=<ISO> finished=<ISO>` (그 사이 다른 텍스트 없음). ISO 형식은
  `YYYY-MM-DDTHH:MM:SS+09:00`(콜론 포함 오프셋), 예: `2026-08-29T15:22:46+09:00`.

## Evidence anchors

- `bin/gootte`의 시각 기록 명령 구현부 — 정확히 베껴야 할 줄 형식·삽입 위치 계약.
- 이미 채워진 실물 예시: `docs/features/ticket-time-stamp/tickets/T02.md`의 시각 기록 줄.
- 일부 티켓은 문서 안에 사람이 이미 적어 둔 완료 시각 메모가 있다 — 이런 티켓은 그 문서
  자체가 완료 시각의 1차 근거다.

## Regression guards

- 티켓 파서 시험(코드 변경이 없으므로 새로 실패할 것은 없지만, 새로 채운 줄을 실제로
  파싱 성공하는지 로컬에서 한 번 확인).
- 시간 기록 CLI 자체 계약 시험 — 이 작업으로 건드리지 않지만, 형식이 어긋나면 이 시험이
  참고 기준이 된다.

## Scope

48개 파일 각각에 대해 반복하는 절차 (판단이 필요한 조사 작업):

1. **완료 시각을 정한다.**
   a. 티켓 문서 자체에 이미 사람이 적은 완료 메모(날짜, 시:분 포함)가 있으면 그 값을
      1차로 쓴다(시:분이 없으면 그 커밋의 시각으로 보완).
   b. 없으면 전체 git 이력에서 그 티켓을 실제로 구현한 커밋을 찾는다 — 커밋 메시지가
      보통 티켓 번호로 시작하거나 티켓 제목의 핵심 단어를 포함한다(제목과 커밋 메시지를
      직접 대조해 확인). 그 커밋의 작성 시각을 완료 시각으로 쓴다.
   c. 확신이 서는 커밋을 못 찾으면 이 티켓은 건드리지 않고 목록에 "매칭 실패"로 적는다.
2. **시작 시각을 정한다.** 그 티켓 파일이 처음 저장소에 들어온 커밋의 시각을 쓴다 —
   이 시점이 실질적으로 그 티켓이 "기획·발주"된 시점이다. (당시엔 시작 시각을 별도로
   남기지 않았으므로 완벽한 값은 없다 — 이것이 최선의 근거다.)
3. **정확한 형식으로 삽입한다.** 제목 줄 바로 다음 줄에 시각 기록 줄을 추가한다. 기존에
   다른 메타 줄이 있으면 그 위(제목 바로 다음)에 넣는다 — 기존 CLI의 삽입 규칙과 동일.
4. 근거로 쓴 커밋 해시를 진행 상황 메모(작업 로그, PR 본문 등)에 남긴다 — 캡틴이 나중에
   검증할 수 있게.

## Implementation notes

- 순수 텍스트 편집 — 빌드나 서버 재시작이 필요 없다. 직접 줄을 넣거나 파일을 다시 써도
  된다. 새 코드를 만들지 않는다.
- 매칭이 애매한 티켓(예: 한 커밋이 여러 티켓을 동시에 구현, 또는 제목이 여러 후보와
  비슷)은 가장 근거가 명확한 것을 고르고 그 판단 이유를 진행 메모에 짧게 남긴다.
  그래도 확신이 서지 않으면 건드리지 말고 T02 캡틴 검수에 넘긴다.
- 시각대는 이 저장소의 다른 시각 기록 값과 마찬가지로 KST를 쓴다.
- 이 작업은 화면 스크린샷·이미지 확인이 필요 없다(문서 편집뿐) — 시각 확인은 T02가
  전담한다.

## Acceptance criteria

- Touched surfaces에 열거된 48개 파일 중, 근거가 있는 파일은 전부 정확한 형식의 시각
  기록 줄을 얻었다.
- 근거 불충분으로 건드리지 않은 파일은 진행 보고에 명시적으로 나열되어 있다.
- 기존에 시각 기록 줄이 있던 파일(`ticket-time-stamp/T02.md` 포함)은 바이트 단위로
  그대로다.
- 새로 채운 값 중 하나 이상을 골라 인용한 커밋 해시로 그 커밋의 작성 시각을 직접
  검증했을 때 실제로 그 시각·그 티켓 내용과 맞는다.

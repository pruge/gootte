# T01 — 신관례 티켓의 의존을 읽는다

## Goal

`tickets/T<NN>.md` 의 `## Depends on` 절을 파싱해, 신관례 티켓도 옛 관례와 똑같이 막힘·착수 가능 판정을 받게 한다.

## Why this slice

의존을 읽지 못하면 단계를 계산할 입력 자체가 없다(T02 의 선행).
그 자체로도 화면에 보이는 개선이다 — 지금 신관례 티켓은 전부 "착수 가능"으로 표시되고, 실제로 선행이 있어도 그 사실이 화면 어디에도 없다.

## Produces

신관례 티켓의 `blockedBy` 값.
지금은 `toNewTicket`(`core/src/project/features.ts:50`)이 무조건 빈 배열을 넣는다.

## Consumers

`blockedBy` 를 읽어 파생값을 만들거나 화면에 그리는 기존 자리 전부:

- `core/src/project/features.ts` `waitingOn()` (105행 부근) — 선행 중 아직 안 끝난 것을 고른다. 신관례 티켓은 지금 이 계산을 아예 안 거친다(`toNewTicket` 이 `waitingOn: []` 을 직접 넣는다).
- `core/src/project/features.ts` `toNewTicket()` (39~59행) — 배정해야 할 값이 세 칸이다: `blockedBy`, `waitingOn`, `startable`. 지금 세 칸 모두 고정값이다(`[]`, `[]`, `true`).
- `core/src/project/features.ts` `buildFeature()` (150행 부근) — `doneNums` 와 `crossIndex` 를 만들어 `toTicket` 에 넘긴다. 신관례 티켓도 같은 색인을 받아야 한다.
- `core/src/project/features.ts` `buildCrossFeatureIndex()` (74행 부근) — 지금 `docs.tickets`(옛 관례)만 훑는다. 신관례 티켓의 번호·완료 여부도 색인에 들어가야 기능 간 참조가 어긋나지 않는다.
- `frontend/src/components/features/TicketRow.tsx:56~63` `Stage` 판정 — `waitingOn.length > 0` 이면 "대기", 아니면 `startable` 로 "착수 가능". 신관례 티켓이 처음으로 "대기"로 뜰 수 있게 된다.
- `frontend/src/components/features/TicketRow.tsx:211~213` — `waitingOn` 목록을 `→ 01, 02` 형태로 그린다.
- `frontend/src/components/features/FeatureCard.tsx:19` — `startable` 개수를 센다. 신관례 티켓이 이 집계에 실제 값으로 들어간다.
- `core/src/plan/fixtures.ts:47~50` — 테스트가 쓰는 티켓 생성기. `blockedBy: []`·`waitingOn: []`·`startable: true` 를 **고정값으로 박아** 만든다. 의존을 표현할 방법이 없어 T02 의 배정 테스트를 쓸 수 없다. `TicketSpec`(7행)에 의존 칸을 더해 표현 가능하게 만든다. 🔴 이 파일은 `plan/` 의 테스트 7개(`process`·`board`·`move`·`close`·`step`·`next`·`backlog-join`)가 공유하므로, 기본값을 바꾸면 그 전부가 흔들린다 — **칸을 더하되 기본 동작은 지금과 같아야 한다.**

## Locked decisions

- F2(`grill.md`): 옛 관례 `Blocked by:` 와 신관례 `Depends on` 은 **같은 개념의 두 표기**다. 새 모델 개념을 만들지 말고 같은 `blockedBy` 칸을 채운다.
- `docs/agents/issue-tracker.md:38`: 의존은 **같은 기능 폴더 안의 티켓 번호**에 대한 구조적 의존이다. 이 정의를 바꾸지 않는다.
- INV-4: 문서가 말하지 않은 것을 지어내지 않는다. `## Depends on` 절이 없으면 의존 없음이 아니라 **모른다**로 다루되, 기존 옛 관례 파서가 "없음" 선언을 어떻게 다루는지(`NO_DEPS` 정규식, `parse/feature.ts:70` 부근)와 일관되게 처리한다.

## Implementation notes

신관례 티켓 본문의 절 형태는 실물이 이렇다(`tauri-desktop-app/tickets/T04.md` 끝부분):

```markdown
## Depends on
- T02 (경로 설정값)

## Can run in parallel with
- nothing
```

옛 관례는 한 줄짜리 `**Blocked by:** 01, 02` 이고 신관례는 **여러 줄 목록**이다 — 파서를 재사용하지 말고 신관례 전용으로 쓰되, 결과는 같은 칸에 싣는다.
항목은 `T02`·`T02 (사유)`·`none`·`nothing` 형태가 실재한다.
번호 추출은 옛 관례의 `LEADING_NUM` 과 같은 규율을 따르되 `T` 접두를 받는다.

## Acceptance criteria

1. `## Depends on` 에 `- T02` 가 있으면 그 티켓의 의존에 `02` 가 실린다.
2. `- none`·`- nothing` 같은 없음 선언은 의존 없음으로 읽힌다.
3. 선행이 완료면 착수 가능, 미완이면 대기로 판정된다 — 옛 관례와 같은 계산을 거친다.
4. 존재하지 않는 번호를 가리키면 계속 막힌 채 남는다(옛 관례와 같은 규율).
5. 신관례 티켓 줄이 화면에서 "대기 → 02" 형태로 선행을 보여준다.
6. 기능 카드의 착수 가능 개수에 신관례 티켓이 실제 값으로 반영된다.
7. 옛 관례 동작에 회귀가 없다.

# T05 — 설정은 firstmate 홈 한 칸, 나머지 뿌리는 파생한다

## Goal

설정 화면에서 `projects` 칸을 없애고 **firstmate 홈 하나**만 고르게 한다.
감시 뿌리는 그 홈에서 파생한다 — 지도부 `projects` 와 명부에 등록된 모든 항해사 홈의 `projects`.
이 티켓이 앞선 넷을 **활성화**한다.

## Why this slice

T01~T04 는 사본이 여럿일 때의 거동을 만들지만 뿌리가 하나씩만 오므로 화면이 안 변한다.
이 슬라이스가 뿌리를 늘려 전부 켜지고, 동시에 캡틴이 직접 요구하신 설정 단순화를 완성한다.
반드시 마지막이어야 한다 — 먼저 켜면 그 사이 목록이 실제로 중복된다.

## Produces

`firstmateHome` 하나에서 파생되는 **감시 뿌리 목록**. 설정 계약에서 `watchRoot` 소멸.

## Implementation notes

- 파생 함수는 `core-io` 에 **하나**만 둔다: 홈 → `[<홈>/projects, ...명부 홈들의 projects]`.
  백엔드와 CLI 가 같은 함수를 쓴다(`the-terminal-agrees-with-the-screen` 의 규율).
- 홈 미설정이면 지금처럼 `effectiveProjectRoots()` 기본값으로 떨어진다 — 화면이 죽지 않는다.
- 명부 없음·읽기 실패는 빈 목록으로 흡수(기존 `readSecondmateHomes` 계약 그대로).
- 존재하지 않는 뿌리는 `discoverProjects` 가 이미 건너뛴다.
- `onWatchRootChange` 는 없애고, `onFirstmateHomeChange` 하나가 문서 감시기와 백로그 감시기를
  **둘 다** 다시 묶는다 — 홈이 곧 두 목록의 출처가 되므로.
- 설정 화면의 남는 입력은 하나이고, 기존 존재 경고(`firstmateHomeExists`)와 추천 경로
  (`firstmateHomeSuggestion`)는 그대로 산다.

## Acceptance criteria

1. 설정 화면에 입력이 하나뿐이다(firstmate 홈).
2. 홈을 저장하면 그 홈의 `projects` 와 명부 항해사 홈들의 `projects` 가 모두 감시 뿌리가 된다.
3. 홈을 바꿔 저장하면 문서 감시기와 백로그 감시기가 **둘 다** 새 홈으로 다시 묶인다.
4. 실물 홈으로 켰을 때 같은 프로젝트가 한 줄만 뜨고, 항해사 사본에만 있는 기능이 보인다.
5. 홈 미설정이어도 화면이 뜬다.
6. 저장 파일에 남아 있는 옛 `watchRoot` 값이 있어도 무시되고 오류가 없다.
7. 명부 홈 경로 하나가 없어도 나머지가 그대로 뜬다.
8. `pnpm -C code/web verify` green.

# T01 — 같은 이름의 사본을 하나로 묶는다

## Goal

`discoverProjects` 가 같은 slug 의 여러 사본을 **한 프로젝트**로 묶어 낸다.
목록에 같은 이름이 두 번 뜨지 않는다 — 이것이 뒤엎는 옛 결정이 두려워한 바로 그 상태다(ADR-0001).

## Why this slice

뿌리를 늘리기(T05) **전에** 묶기가 먼저 들어가야 한다. 순서가 반대면 그 사이에 목록이 실제로
중복돼 화면이 거짓말을 한다. 이 티켓만으로는 화면이 하나도 안 변한다 — 지금 뿌리는 사본을
하나씩만 주기 때문이다(안전한 기반 슬라이스).

## Produces

`Project.copies: string[]` — 그 slug 로 발견된 **모든 사본의 절대 경로**, 뿌리 순서 그대로.
`Project.path` 는 **대표 경로**로 남는다(= `copies[0]`) — 기존 소비처를 깨지 않는 호환 칸.

## Implementation notes

- 묶는 키는 `basename(dir)`. 뿌리 순서가 곧 `copies` 순서이고, 첫 것이 대표다.
- `pickBySlug` 의 `ambiguous` 플래그와 stderr 경고는 **없앤다** — 중복이 정상 상태가 되므로
  경고가 매 요청 울리면 소음이다. 진짜 갈라짐 경고는 T03 이 다른 자리에서 소유한다.
- `projectOf` 는 모든 사본 경로를 후보로 놓고 최장 접두로 고른다(지금 알고리즘 그대로, 입력만 늘어난다).

## Acceptance criteria

1. 같은 slug 의 사본이 둘 있는 뿌리 집합을 주면 목록에 **1개**가 뜨고 `copies` 가 2개다.
2. 대표 경로(`path`)는 뿌리 순서상 첫 사본이다.
3. 사본이 하나뿐인 기존 상황에서 `path`·목록·CLI 출력이 **한 글자도 안 바뀐다**.
4. 어느 사본 안의 경로를 주어도 `projectOf` 가 같은 slug 를 답한다.
5. `pnpm -C code/web verify` green.

# Specification — one-setting-finds-every-copy

Status: ready-for-agent (2026-08-27)

심문 기록과 결정 원문은 [`grill.md`](grill.md). 이 사양은 그 결정을 구현 계약으로 옮긴 것이고,
결정의 substance 를 복사하지 않는다 — 근거가 필요하면 `grill.md` 를 본다.

## Goal

캡틴이 firstmate 홈 **하나**만 고르면, 지도부와 등록된 모든 항해사 홈의 프로젝트 사본이
자동으로 감시 대상이 되고, 같은 프로젝트의 여러 사본에 흩어진 기능 문서가 **한 벌로 합쳐져**
화면에 뜬다. 항해사가 문서를 쓰는 즉시 캡틴이 본다 — 지도부 사본이 갱신되기를 기다리지 않는다.

## User stories

1. 캡틴이 설정을 열면 고를 칸이 **firstmate 홈 하나**뿐이다.
2. 그 홈을 고르면 `<홈>/projects` 가 감시 대상이 된다 — 캡틴이 따로 적지 않는다.
3. 명부에 등록된 항해사 홈의 `projects` 도 함께 감시 대상이 된다 — 캡틴이 따로 적지 않는다.
4. 항해사 홈이 명부에 추가되면 설정을 다시 저장할 때 그 홈의 사본도 감시 대상에 들어온다.
5. 같은 프로젝트가 여러 홈에 있어도 목록에는 **한 줄**만 뜬다.
6. 그 프로젝트를 열면 어느 사본에 있든 기능이 **전부** 보인다 — 한쪽에만 있는 기능도 포함.
7. 같은 기능이 여러 사본에 있으면 **나중 판**의 내용이 보인다.
8. 어느 판이 나중인지는 저장소 이력이 답한다 — 사람이 고른 우선순위 표가 없다.
9. 어느 사본에도 커밋되지 않은 작업 중 문서가 그대로 보인다.
10. 같은 파일이 한쪽에서만 커밋 안 된 채 고쳐졌으면 그 고친 판이 보인다.
11. 아직 착지하지 않은 문서에는 **표식**이 붙어 확정된 문서와 구분된다.
12. 저장소가 추적에서 뺀 버리는 설계 시안은 화면에 뜨지 않는다.
13. 두 사본이 진짜로 갈라져 어느 쪽도 나중이라 말할 수 없으면, 화면이 **갈라졌다고 말한다** — 조용히 하나를 고르지 않는다.
14. 항해사 홈 하나가 사라지거나 못 읽어도 나머지 홈의 문서는 그대로 보인다.
15. firstmate 홈이 미설정이면 지금처럼 기본 뿌리로 떨어지고 화면이 죽지 않는다.

## Scope

- 설정 계약에서 `watchRoot` 제거, `firstmateHome` 단수 유지.
- firstmate 홈 → 감시 뿌리 목록 파생(지도부 + 명부의 항해사 홈).
- 같은 slug 의 여러 사본을 하나의 프로젝트로 묶기.
- 기능 문서 합집합과 나중 판 판정.
- 미착지 표식.
- 추적 제외 파일(버리는 시안) 화면에서 제외.

## Out of scope

- `git fetch`·`git pull` 등 원격을 당겨오는 동작 — INV-2 위반이고 이 기능의 목적도 아니다.
  사본이 뒤처지는 문제는 함대 규율(병합 후 즉시 갱신)이 이미 소유한다.
- 어느 사본에서 온 문서인지 화면에 상시 표시 — 합집합이 출처를 감추는 것이 이 설계의 목적이다(캡틴 결정 Q4).
- 항해사 홈의 **백로그** 읽기 — 이미 동작한다(`every-home-reports-its-status`). 이 기능은 문서 쪽만 다룬다.
- 사본별 목록 분리 표시 — 캡틴이 합집합을 고르셨다(Q1).

## Decisions

이 사양이 닿는 이 프로젝트의 항구적 규칙(`AGENTS.md` §제품 불변식):

- **INV-1 파생물만** — 사본 목록·합집합 결과·나중 판 판정을 **어디에도 저장하지 않는다.**
  매 요청 재계산한다. 캐시는 기존 discover TTL 캐시(프로젝트 목록) 하나뿐이고 이 기능이
  새 캐시를 만들지 않는다.
- **INV-2 관리대상은 읽기 전용** — 어느 사본에도 쓰지 않는다. `git` 은 읽기 명령만 쓴다
  (`merge-base`, `status`, `check-ignore`). 기존 `core-io/src/git.ts` 의 읽기 전용 규율을 따른다.
- **INV-3 stale 뷰 금지** — 이 기능의 존재 이유. 모든 사본의 `docs/features` 를 감시한다.
- **INV-4 결정적·LLM-free** — 🔴 나중 판 판정은 **저장소가 답하는 사실**이어야 한다.
  파일 시각·크기·"더 최신 같아 보임" 류의 추정은 이 불변식 위반이다.

🔴 **이 사양은 `every-home-reports-its-status/spec.md` §결정의 한 조항을 뒤집는다** —
"보여줄 저장소는 지도부 사본 하나뿐이다". 그 조항을 세운 유일한 이유가 이름 충돌이었고,
이 사양의 합집합 규칙이 그 이유를 해소한다. 번복이므로 [`adr/0001-union-of-copies.md`](adr/0001-union-of-copies.md)
를 남긴다(캡틴 상시 규칙 2026-08-26: 기록된 결정을 뒤집을 때만 ADR).

### 나중 판 판정 규칙 (INV-4 를 지키는 결정 절차)

파일 하나가 여러 사본에 있을 때, 순서대로 판정한다:

1. 내용이 바이트로 같으면 아무거나 — 고를 일이 없다.
2. 한쪽에만 커밋 안 된 변경이 있으면 **그쪽**이 나중 판이다(작업 중인 판이 곧 나중 판).
3. 양쪽 다 커밋 상태면 HEAD 조상 관계를 본다 — **후손 쪽**이 나중 판이다.
4. 조상 관계가 어느 방향으로도 성립하지 않으면(진짜 갈라짐) **고르지 않는다.**
   그 기능을 갈라진 것으로 표시한다.

## Existing seams / integration points

기존 seam 만 쓴다. 새 계층도 새 저장소도 만들지 않는다.

| seam | 지금 하는 일 | 이 기능이 바꾸는 것 |
|---|---|---|
| `core-io/src/discover.ts` | 뿌리 목록 → 프로젝트 목록 | 뿌리 파생 자리 하나 추가, 사본 묶기 |
| `core-io/src/secondmates.ts` | 명부에서 홈 경로 목록 | **그대로 재사용** — 이미 있다 |
| `core-io/src/features.ts` | 사본 하나 → 기능 목록 | 사본 여럿 → 합쳐진 기능 목록 |
| `core-io/src/git.ts` | 읽기 전용 git 위임 | 조상 판정·추적 여부 질의 추가 |
| `backend/src/discover-cache.ts` | slug → 사본 하나(first-match + 경고) | slug → 사본 **묶음** |
| `backend/src/app.ts` `effectiveRoots()` | `watchRoot` 우선 | firstmate 홈에서 파생 |
| `backend/src/watchers.ts` | 문서 감시 뿌리 하나 | 파생된 뿌리 전부 |
| `contract/src/index.ts` `Settings` | 두 칸 | 한 칸 |
| `frontend/.../SettingsDialog.tsx` | 두 입력 | 한 입력 |

## Data and migration

저장된 설정에 남아 있는 `watchRoot` 값은 **무시한다** — 읽지도 쓰지도 않는다.
지우는 마이그레이션도 하지 않는다(설정 파일은 잃어도 되는 물건이고, 남은 칸은 무해하다).
실측상 현재 값이 정확히 `<firstmateHome>/projects` 라 버려도 잃는 것이 없다(`grill.md` F1·F2).

## Security / authorization

없음 — 전부 로컬 읽기. 다만 `readFeatureDoc` 의 경로 탈출 차단은 **사본이 늘어난 뒤에도**
같은 강도로 유지되어야 한다(사본마다 base 가 다르므로 판정도 사본별로).

## Compatibility / rollout

한 번에 바뀐다. 켜고 끄는 스위치를 두지 않는다 — 설정 칸이 사라지는 변경이라
두 모드를 동시에 유지하면 어느 칸이 진짜인지 다시 모호해진다.

## Acceptance criteria

1. 설정 화면에 firstmate 홈 칸 하나만 있다.
2. 홈을 저장하면 `<홈>/projects` 와 명부의 모든 항해사 홈 `projects` 가 감시 뿌리가 된다.
3. 같은 slug 의 사본이 여럿이어도 프로젝트 목록에 한 번만 뜬다.
4. 한쪽 사본에만 있는 기능이 목록에 뜬다.
5. 양쪽에 있고 내용이 다른 기능은 나중 판 내용이 뜬다(판정 규칙 §Decisions).
6. 커밋 안 된 작업 중 문서가 뜬다.
7. 미착지 문서에 표식이 붙는다.
8. 추적 제외된 `design/*.html` 이 문서 트리에 뜨지 않는다.
9. 진짜 갈라진 경우 화면이 갈라졌다고 말하고, 조용히 한쪽을 고르지 않는다.
10. 항해사 홈 경로가 없거나 못 읽어도 나머지가 그대로 뜬다.
11. firstmate 홈 미설정이어도 화면이 죽지 않는다.
12. `pnpm -C code/web verify` green.

## Verification strategy

- **routine** — 티켓마다 단위 시험. 픽스처는 실물에서 떠 온다(learnings 2026-08-26: 지어낸
  픽스처가 착지 후 한 번도 동작 안 한 기능을 통과시킨 전례). 특히 명부 줄과 `git status`
  출력 모양은 실물 파일·실물 저장소에서 잘라 온다.
- **실물 대조** — 착지 후 실제 네 쌍(gootte·jinwooauto·QuicMic·voice-to-iterm)으로 대조한다.
  지도부에만 있는 문서 0건, 항해사에만 있는 문서 11건이 실측값이다(`grill.md` F14·F15).
- **no-mistakes 생략** — 캡틴 지시 2026-08-27. 배달은 direct-PR.

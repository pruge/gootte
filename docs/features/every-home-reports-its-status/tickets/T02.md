# T02 — 등록된 세컨드메이트 홈의 백로그까지 함께 읽는다
Time: started=2026-08-26T13:24:15+09:00 finished=2026-08-26T13:21:03+09:00

## Goal

`readBacklogTasks` 가 지도부 홈뿐 아니라 **명부에 등록된 세컨드메이트 홈**의 백로그도 읽어
하나의 목록으로 합친다. 지도부 항목이 항상 앞에 온다(T01 의 부모 우선순위 계약).

## Why this slice

캡틴이 고르신 A안의 본체다. 지금은 세컨드메이트가 한 일이 캡틴 화면에서 상태 미표시다
(spec §문제의 실측: mate 홈 3건이 아예 안 읽힌다).

읽기는 `readBacklogTasks` 한 자리로 모여 있다 — 소비처 4곳은 그 함수만 부르므로 **손대지 않아도 된다.**
감시는 홈 하나를 전제하므로 홈 수만큼 늘려야 한다.

## Produces

- **홈 발견**: `<firstmateHome>/data/secondmates.md` 에서 `home: <경로>` 값을 뽑는 결정적 파서.
  실물 두 줄(2026-08-26):

      home: /Users/pruge/.treehouse/firstmate2-4b2429/1/firstmate2
      home: /Users/pruge/.treehouse/firstmate2-4b2429/2/firstmate2

- **병합 순서**: 지도부(live→archived) → 세컨드메이트 홈(명부 순, 각 홈 live→archived).
  같은 id 는 먼저 온 것이 이긴다(기존 live 우선 규칙의 자연스러운 확장).
- **감시**: 발견된 홈마다 기존 `watchBacklog` 를 건다. 설정이 바뀌면 전부 다시 묶는다.

## Implementation notes

- 🔴 **설정 계약을 바꾸지 마라.** `contract/src/index.ts` 의 `firstmateHome` 은 단수 문자열 그대로다.
  홈 목록은 그 홈 안의 명부에서 **파생**되는 값이지 사용자가 정하는 값이 아니다(INV-1).
- 🔴 명부 없음·읽기 실패·경로 부재는 **조용히 건너뛴다** — 지도부 홈만으로 계속 동작한다(INV-U1).
  세컨드메이트 홈 하나가 사라져도 판과 명령은 죽지 않는다.
- 🔴 세컨드메이트 홈의 `projects/` 는 보지 않는다(spec §결정: 문서는 한 벌).
- 감시기 수가 홈 수만큼 는다 — 기존 `rebindBacklog` 경로를 재사용하고 새 통로를 만들지 마라.

# T01 — 부모 판정을 견고하게 한다 (홈을 늘리기 전에 먼저)
Time: started=2026-08-26T13:24:15+09:00 finished=2026-08-26T13:08:32+09:00

## Goal

`findParentId` 가 **부모 모양인 항목만** 후보로 삼고, 후보가 여럿이면 **지도부 홈 우선**으로 고르게 한다.
홈을 늘리기 전에 이것부터 선다 — 안 그러면 홈이 늘어나는 순간 지금 잘 뜨는 상태가 사라진다.

## Why this slice

지금 규칙은 "메모에 `docs/features/<slug>/` 문자열이 있는 **첫** 항목"이다. 그 문자열은 산문 인용에도
등장하므로, 읽는 목록이 늘어나면 엉뚱한 항목이 부모로 뽑힌다.

실측(같은 데이터, 합치는 순서만 바꿔 돌림):

    needle = docs/features/both-conventions-are-first-class/
    MAIN 보유: gootte-both-conventions, -t03, -t02, -t01   (진짜 부모와 자식들)
    MATE 보유: gootte-backlog-join                          (메모 산문이 그 경로를 인용할 뿐)

    main-first → parent=gootte-both-conventions → T01 done
    mate-first → parent=gootte-backlog-join     → T01 NULL   🔴 상태 소실

T02(홈 늘리기)가 먼저 들어가면 이 소실이 실제로 일어난다. 그래서 순서가 이 티켓이 앞이다.

## Produces

부모 선택 규칙 두 가지:

1. **자식 모양 배제** — id 가 `<무엇>-t<숫자>` 로 끝나는 항목은 부모 후보가 아니다.
   (D4 규약상 자식 id 모양이며, 자식 메모는 자기 티켓 경로를 인용하므로 반드시 걸린다.)
2. **후보가 여럿이면 결정적으로 하나** — 목록에서 먼저 오는 것을 그대로 쓰되,
   호출자가 지도부 홈 항목을 앞에 놓는 계약을 문서화한다(T02 가 그 순서를 보장한다).

🔴 후보가 0개면 지금처럼 `null` 이다 — 추측하지 않는다.

# 04 — 옛 문서 형식을 읽던 경로를 걷어낸다

**What to build:** 은퇴한 워크플로우의 문서를 발견하고 파싱하고 상태를 계산하던 경로를 제거한다.
앞의 세 티켓이 새 경로를 세워 놓았으므로 이제 옛 경로는 아무도 쓰지 않는 코드다.

**Blocked by:** 01, 02, 03

**Status:** ready-for-agent

## 완료 시 시연 가능한 것

캡틴이 보기에 **화면은 어제와 똑같다.** 프로젝트가 뜨고, 할일이 뜨고, 처리중이 표시된다.
달라진 것은 그 뒤에서 두 벌로 돌던 읽기 경로가 한 벌이 된 것뿐이다.

## 완료 조건

- 옛 설정 파일을 근거로 프로젝트를 찾던 판정이 없다.
- 옛 문서 종류(기획·할일·스프린트)를 읽고 파싱하고 상태를 계산하던 경로가 없다.
  그 형식에만 쓰이던 계약 타입도 함께 없앤다.
- 관리대상 프로젝트에서 그 폴더들을 더 이상 읽지 않는다.
- contract codegen 재실행 후 `git diff` 0.
- `pnpm verify` green.
- 대시보드가 앞 세 티켓과 동일하게 동작한다.

## 테스트

**새 테스트를 만들지 않는다.** 이 티켓은 제거이고, 옛 형식의 파서 테스트도 함께 사라진다.
**커버리지 숫자가 내려가는 것은 회귀가 아니라 삭제의 결과다.**

남는 검증은 앞 세 티켓이 만들어 둔 테스트가 전부 green 을 유지하는 것 —
그것이 "새 경로만으로 충분하다" 의 증거다.

## 순서 메모

자매 기능 `firstmate-migration` 의 티켓 06(`.cling/` 삭제) 이 착지한 뒤가 자연스럽다.
반대 순서도 **안전하다** — 그 구간에는 아무도 안 쓰는 코드가 잠시 남을 뿐이다.
위험한 방향은 없다.

## 이 티켓이 하지 않는 것

- 화면 재설계. 보이는 것은 그대로다.
- 저장소 자신의 문서 삭제 — 자매 기능이 한다.
- 옛 형식을 나중에 되살릴 수 있게 남겨두기. **되살릴 일이 생기면 그것은 새 결정이다.**

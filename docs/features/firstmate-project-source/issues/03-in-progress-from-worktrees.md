# 03 — 지금 붙들려 있는 일을 표시한다

**What to build:** 어떤 티켓이 **지금 누군가 작업 중인지**를 화면에 표시한다.
그 사실은 문서에 적혀 있지 않다 — 상태 어휘에 "처리중" 이 아예 없다. 그건 결함이 아니라 설계다.
누가 무엇을 붙들고 있는지는 **격리 작업 사본을 관측해서** 안다.

**Blocked by:** 02

**Status:** resolved (2026-08-09)

## 완료 시 시연 가능한 것

캡틴이 대시보드에서 프로젝트를 고르면, 지금 작업이 진행 중인 티켓에 **처리중 표시**가 붙어 있다.
아무도 안 붙든 티켓에는 안 붙는다. 그리고 작업은 진행 중인데 어느 티켓인지 못 밝힌 경우
**"티켓 미상 · 작업중" 으로 따로 세어 보인다** — 조용히 빠지지 않는다.

## 완료 조건

- 격리 사본 뿌리를 스캔한다. 기본값은 `~/.treehouse` 이고, **환경변수로 덮어쓸 수 있어야 한다** —
  기계마다 다를 수 있으므로 경로를 코드에 못 박지 않는다.
- 각 사본의 상태 판정: **작업 중인 가지에 올라가 있으면 작업중, 아니면 유휴.**
- 그 작업을 티켓에 잇는 규칙: **그 가지의 커밋이 건드린 티켓 파일**로 역추적한다.
  규칙 기반이어야 하며, 이름이 비슷하니 아마 이 티켓일 것이라는 식의 추정은 쓰지 않는다.
- 이어진 티켓은 앞 티켓이 만든 상태에서 **처리중**으로 계산된다. 이 값은 저장하지 않는다.
- 🔴 **이어지지 않은 작업중 사본은 감추지 않는다.** "티켓 미상" 으로 세어 화면에 드러낸다.
- 관리대상 프로젝트에는 아무것도 쓰지 않는다.
- `pnpm verify` green.

## 테스트

**이 티켓이 이 판정을 처음 덮는다.** 전례가 없다.

IO 계층에서 임시 저장소 픽스처로 덮는다. 반드시 포함할 경우:

| 픽스처 | 기대 |
|---|---|
| 사본이 작업 가지에 있고 커밋이 티켓 파일을 건드림 | 그 티켓이 처리중 |
| 사본이 유휴 상태 | 아무 티켓도 처리중이 아니다 |
| **사본이 작업 중인데 티켓 파일을 안 건드림** | **"티켓 미상 · 작업중" 으로 세어진다. 사라지지 않는다** |
| 격리 사본 뿌리가 없음 | 빈 결과. 예외로 죽지 않는다 |
| 한 티켓을 두 사본이 붙들고 있음 | 중복으로 두 번 세지 않는다 |

세 번째가 이 티켓의 본체다. 매핑 실패를 조용히 삼키면 화면이 **"아무도 아무것도 안 하는 중"** 이라고
거짓말하고, 캡틴은 이미 진행 중인 일을 다시 배정하게 된다.

## 이 티켓이 하지 않는 것

- 작업 관리 도구의 사설 기록 읽기. 남의 사설 영역에 손을 뻗지 않고, 그 방식은 이 기계에만 통한다.
- 가지 이름에 티켓 번호를 넣는 규약 만들기. 그건 이 저장소가 정할 수 없는 규약이고,
  나중에 생기면 여기에 규칙 하나를 더 얹으면 된다.
- 처리중 상태를 티켓 파일에 적어 넣기. **관측한 것을 파일에 되쓰지 않는다** — 그 순간
  손으로 유지되는 두 번째 기록이 생긴다.

## 실행 모델

기본 작업자 등급을 넘는다.

**이유:** 이 화면에 보이는 "처리중" 이 틀리면 사람이 같은 일을 두 번 한다.
어디까지를 확실히 이어졌다고 볼지, 무엇을 미상으로 남길지의 경계는 실제 작업 사본들의 모양을
보고서야 정해진다 — 계획 단계에서 닫을 수 없었던 것이 그 경계다.

## 캡틴 확인

- **어디서** — gootte 대시보드를 띄운다 (`pnpm dev`).
- **무엇을** — 지금 작업이 돌고 있는 프로젝트를 고르고 할일 목록을 본다.
- **무엇이 보여야 하나** — 실제로 진행 중인 그 일에 처리중 표시가 붙어 있다.
  나머지에는 안 붙는다. 이어지지 않은 작업이 있으면 "티켓 미상" 으로 따로 보인다.

표시가 맞는지는 지금 무슨 일이 도는지 아는 사람만 판정할 수 있어 캡틴 눈이 필요하다.

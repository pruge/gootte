# 01 — firstmate 프로젝트를 찾는다

**What to build:** 관리 대상을 찾는 규칙을 바꾼다. 지금은 은퇴한 워크플로우의 설정 파일이 있는 곳만
프로젝트로 세기 때문에, **캡틴의 프로젝트가 하나도 잡히지 않는다.**
`~/Documents/ai2/projects` 아래에서 **루트에 `AGENTS.md` 가 있고 `docs/features/` 디렉토리가 있는 곳**을
프로젝트로 센다.

**Blocked by:** 없음 — **즉시 착수 가능**

**Status:** resolved (2026-08-09)

## 완료 시 시연 가능한 것

캡틴이 대시보드를 띄우면 **왼쪽 프로젝트 목록에 jinwooauto 와 gootte 가 뜬다.**
지금은 아무것도 안 뜬다. 프로젝트를 고르면 기존 화면들이 그 프로젝트를 대상으로 그려진다.

## 완료 조건

- 스캔 뿌리 기본값이 `~/Documents/ai2/projects` 다. 기존 환경변수로 덮어쓰는 성질은 그대로 둔다.
- 프로젝트 판정 = **루트 `AGENTS.md` 와 `docs/features/` 디렉토리가 둘 다 있음.**
  둘 다 요구하는 이유를 코드 주석이 아니라 `AGENTS.md` 나 사양에 남긴다 —
  하나만 보면 firstmate 저장소 자신과 각종 격리 사본이 딸려 들어오거나,
  아직 firstmate 관리가 아닌 저장소가 섞인다.
- 옛 발견 규칙은 **아직 지우지 않는다.** 둘이 공존해도 무방하다 — 제거는 티켓 04.
- `pnpm verify` green.

## 테스트

**이 티켓이 이 판정을 처음 덮는다.**

IO 계층에 임시 디렉토리 픽스처로 단위 테스트를 둔다. 반드시 포함할 경우:

| 픽스처 | 기대 |
|---|---|
| `AGENTS.md` + `docs/features/` 둘 다 | 프로젝트로 센다 |
| `AGENTS.md` 만 | 세지 않는다 |
| `docs/features/` 만 | 세지 않는다 |
| 뿌리가 아예 없음 | 빈 목록. 예외로 죽지 않는다 |

화면 쪽은 목록이 뜨는지까지만 얇게 덮는다. 그 이상은 깨지기 쉽다.

## 이 티켓이 하지 않는 것

- 기능·티켓 내용 읽기 — 티켓 02. 이 티켓은 **프로젝트가 목록에 뜨는 데까지**다.
- 처리중 판정 — 티켓 03.
- 옛 발견·파싱 경로 제거 — 티켓 04.
- 관리대상 문서에 쓰기. 이 제품은 관리대상을 읽기만 한다.

## 실행 모델

기본 작업자 등급을 넘는다.

**이유:** 발견은 이 제품의 입구이고, 그 아래 파싱·상태 계산이 전부 그 결과에 매달린다.
지금 계층 경계(순수 계산 / 파일 읽기)를 어디에 다시 그을지가 이후 세 티켓의 난이도를 결정하는데,
그 판단은 코드를 놓고서야 선다.

**완료 조건에 반드시 포함할 것:** **발견·파싱 계층의 구조와, 새 문서 종류를 하나 더 읽으려면
무엇을 건드려야 하는지의 절차**를 문서로 남긴다. 이것이 빠지면 티켓 02·03 이 코드를 역추적하게 된다.

# T02 — 내부 전용 export 축소 (38개)

**Blocked by:** T01

**Time:** started=2026-09-08T04:51:45+09:00 finished=2026-09-08T04:58:45+09:00

## Goal

파일 내부에서만 사용되는 38개 심볼의 `export` 키워드를 제거하여 모듈 경계를 명확히 한다.

## Why this slice

과도한 export는 모듈의 공유 API 표면을 불필요하게 넓히고, import 구조를 이해하기 어렵게 만든다. `export`만 제거하므로 동작 변경이 없는 기계적 리팩토링이다.

## Produces

38개 심볼이 모듈 내부 전용으로 전환됨. 외부 API 표면이 축소됨.

## Consumers

이 심볼들은 전부 **파일 내부에서만 사용**되므로 외부 소비처가 없다. 제거해도任何한 import가 깨지지 않는다.

## Explicitly out of scope

- 프로덕션에서 실제로 사용되는 export 유지
- barrel index.ts에서의 re-export 정리는 이 티켓 범위 밖 (각 모듈의 export 키워드만 제거)

## Locked decisions

- 모든 대상 심볼은 파일 내부에서만 사용됨이 확인됨 (이전 조사 완료)
- `export` 키워드만 제거, 함수/타입 본문은 변경 없음

## Evidence anchors

- 각 파일의 export 선언부 (위 표의 파일 목록)
- 소비처 검증: 각 심볼에 대해 전체 코드베이스 import 검색 완료

## Regression guards

- `pnpm verify` (전체 회귀)
- TypeScript 컴파일 (tsc --noEmit)

## Scope

1단계: 각 파일에서 `export` 키워드만 제거
2단계: barrel index.ts에서 re-export가 깨지는지 확인
3단계: `pnpm verify`

## Implementation notes

- 기계적 변경이므로 자동화 가능하나, 각 심볼마다 정확히 `export`만 제거해야 함
- TypeScript의 `export type`도 해당되면 제거 대상
- barrel(`index.ts`)에서 `export * from` 으로 re-export하고 있다면, 해당 모듈에서 `export`를 제거해도 barrel은 영향 없음 (내부 심볼이므로)

- 38개 심볼 모두 `export` 키워드 제거됨
- `pnpm verify` 통과
- 기존 테스트 전부 통과

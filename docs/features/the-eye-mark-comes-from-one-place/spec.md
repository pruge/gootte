# the-eye-mark-comes-from-one-place — 캡틴 눈 표시가 한 자리에서만 나온다

Status: ready-for-agent (2026-08-14) · 티켓 1장 · 열린 결정 1

## 요청 (firstmate 경유, 2026-08-14)

> gootte 가 '이 티켓은 캡틴 눈이 필요한가' 를 스스로 판정하게 하는 기획이다 — 지금은 firstmate 쪽
> 개인 도구가 티켓 제목을 따로 읽어 판정하고 있고 그게 두 번 틀렸다.

## 🔴 전제 정정 — 실측이 요청을 뒤집었다

요청은 "gootte 는 어느 티켓이 캡틴 눈을 필요로 하는지 모른다" 로 시작한다. 그 도구 자신도 주석에
**"캡틴 눈(👁) 표시는 gootte 가 모르는 것이라 이 도구가 티켓 문서를 읽어 붙인다"** 고 적어 두었다.

**둘 다 틀렸다. gootte 는 이미 판정한다.**

- 판정 함수가 있다 — `parseNeedsCaptainEye`.
- 계약에 필드가 있다 — `FeatureTicket.needsCaptainEye`.
- 티켓을 읽을 때마다 채운다 — 모든 응답이 이 값을 싣고 있다.
- 🔴 **보고된 오판 둘을 이미 다 피한다.** 제목 앞 표식을 걷어내고 읽으며(2026-08-14 오판),
  "없음" 이 붙은 절은 세지 않는다(2026-08-12 오판).

그래서 이 일은 **"gootte 에게 판정을 가르치는 일" 이 아니다.** gootte 는 답을 갖고 있는데
**아무한테도 안 알려준다** — 그래서 옆에서 다시 계산했고, 다시 계산한 쪽이 틀렸다.

## 실측 (2026-08-14, 기본 가지 `main` = `2cfdf47`)

두 프로젝트의 티켓 **137장 전부**에 두 규칙을 나란히 돌려 대조했다 — gootte 의 규칙과, 고쳐 둔
도구의 규칙.

🟢 **한 장도 안 갈렸다.** 137장 전부 같은 답이다. 캡틴 눈이 걸린 티켓은 90장.

즉 고쳐 둔 도구는 **gootte 가 이미 내놓고 있던 답을 손으로 다시 만들어 낸 것**이다.
지금 화면이 맞는 이유는 두 규칙이 우연히 같아서지, 한 자리에서 나와서가 아니다.

## 🔴 열린 결정 — 캡틴 몫

**서식을 어디까지 자유롭게 둘 것인가.** 두 갈래는 결과가 다르다.

| | 갈래 | 무엇이 따라오나 |
|---|---|---|
| 가 | **지금처럼 자유 서문을 두고 gootte 가 관대하게 읽는다** | 티켓 쓰는 사람은 아무것도 안 바꾼다. 🔴 대신 새 서식이 나올 때마다 판정이 **조용히** 틀린다 — 두 번의 오판이 정확히 그렇게 났다. 규칙은 계속 자란다 |
| 나 | **기계가 읽을 표시를 서식으로 정한다** | 한 번 정하면 안 틀린다. 🔴 대신 서식 문서를 고치고, 이미 있는 137장 중 어긋난 것을 손봐야 한다 |

같이 닫아야 할 물음 하나 — **사후 기록만 있는 티켓(F7·F8)은 눈이 필요한가.**
캡틴이 이미 확인을 마치셨다는 기록이니 "아니다" 가 자연스럽지만, 지금 시험은 "그렇다" 로 박혀 있고
누구도 그렇게 정한 적이 없다. **닫히기 전에는 오늘 동작을 바꾸지 않는다** — 오늘 갈리는 티켓이 0장이라
서두를 이유가 없고, 말없이 뒤집으면 캡틴 배차 수가 또 조용히 달라진다.

## 불변식

- **INV-E1 — 판정 자리는 하나다.** 어느 티켓이 캡틴 눈을 필요로 하는지는 gootte 만 정한다.
  🔴 다른 도구가 티켓 문서를 다시 읽어 같은 답을 만들지 않는다. 이 사양의 존재 이유가 이것이다.
- **INV-E2 — 절이 있나 없나로만 정한다.** 절 안 내용은 안 읽는다(기존 INV-4 그대로).
  뜻을 짐작하기 시작하면 규칙이 티켓마다 자란다.
- **INV-E3 — 실측에서 나온 관례만 담는다.** 있지도 않은 서식을 미리 받아 주지 않는다.
  받아 준 서식은 **어느 티켓에서 봤는지** 함께 적는다(지금 코드가 이미 그렇게 한다).
- **INV-E4 — 답을 밖으로 내놓는다.** 계약에만 실려 있고 아무도 못 보는 값은 없는 값과 같다.
  🔴 F5 가 이 사양이 생긴 직접적 원인이다.

## 범위 밖

- **firstmate 쪽 도구를 고치는 일.** 2026-08-14 에 이미 고쳐졌고 지금 화면은 맞다.
- **👁 표시 자체를 바꾸는 일.** 표시가 아니라 **판정 자리**를 옮기는 이야기다.
- **137장 티켓의 제목 손질.** 위 열린 결정이 "나" 로 닫히면 그때 별 일감이다.
- **사후 기록 판정 뒤집기.** 열린 결정이 닫히기 전에는 오늘 동작을 유지한다.

## 🔴 저장소 밖 후속 — 티켓 번호가 없다

이 사양이 착지해도 **도구 쪽의 중복 읽기를 지워야 일이 끝난다.** 그 도구는 firstmate 의
개인 도구라 어느 프로젝트의 티켓 목록에도 속하지 않는다 — **받아 줄 티켓 번호가 없다.**

그래서 여기 적어 둔다: 01 이 착지하면 firstmate 가 그 도구의 자체 판정을 지우고 gootte 가 주는
값을 그대로 쓰게 해야 한다. 🔴 그때까지는 판정 자리가 여전히 둘이고, INV-E1 은 아직 안 지켜진 것이다.

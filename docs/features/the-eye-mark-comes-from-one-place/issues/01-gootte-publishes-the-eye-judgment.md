# 01 — gootte 가 자기 판정을 밖으로 내놓는다

**What to build:** gootte 는 어느 티켓이 캡틴 눈을 필요로 하는지 **이미 안다.** 그 답을 계획을 묻는
사람에게 **내놓는다** — 그래야 옆에서 티켓 파일을 다시 읽는 자리가 없어진다.

**Blocked by:** 🟢 없음 — 지금 착수 가능

**Status:** ready

## 🔴 착수 전에 — 이 티켓은 새 판정을 만드는 일이 아니다

[사양의 "이미 서 있는 것"](../spec.md) 을 먼저 읽어라. **다음은 전부 이미 돈다:**

- 판정 함수 — `parseNeedsCaptainEye`. 절이 있나 없나로만 정한다.
- 표식 접두 걷어내기 — `## 🔴 캡틴 확인 …` 을 이미 알아본다.
- "없음" 제외 — `## 캡틴 확인 — 없음` 을 이미 안 센다.
- 계약 필드 — 모든 응답이 티켓마다 이 값을 이미 싣는다.

🔴 **보고된 오판 둘 다 gootte 쪽에는 없다.** 두 프로젝트 티켓 137장 전부를 대조했고 **한 장도
안 갈렸다.** 판정 로직을 다시 쓰지 마라 — 고칠 것이 없다.

**빠진 것은 하나뿐이다 — 그 답을 아무도 못 본다.** 계약에만 실려 있고, 화면도 CLI 도 안 쓴다.
그래서 옆에서 티켓 파일을 손으로 열어 제목을 훑고, 그 자리가 두 번 틀렸다.

## 무엇을 하나

### 1. 계획을 묻는 답에 캡틴 눈이 실린다

지금 계획 순서를 묻는 답은 "무엇을 나란히 갈 수 있나" 만 말한다. 거기에 **그 티켓이 캡틴 눈을
필요로 하는지**를 함께 싣는다.

- 🔴 **판정을 다시 하지 마라.** 이미 계산된 값을 그대로 실어라. 두 번 계산하는 것이 이 사양이
  없애려는 바로 그것이다(INV-E1).
- 🔴 **읽는 쪽이 다시 안 세게 하라.** 값 하나를 그대로 쓰면 되는 모양이어야 한다. 받는 쪽이
  제목을 다시 뒤져야 한다면 자리를 안 옮긴 것이다.

### 2. 시험 이름을 실제로 정하는 것에 맞춘다

`"이모지 접두는 걷어내고 읽는다"` 라는 시험이 하필 **`## 🟢 캡틴 확인 완료 (날짜)`** 를 예시로
써서, 아무도 결정한 적 없는 물음 — **사후 기록을 요청으로 세느냐** — 에 답을 박아 두었다.

- 🔴 **동작은 바꾸지 마라.** 그 물음은 캡틴 몫으로 열려 있다(사양 §열린 결정). 오늘 갈리는 티켓은
  0장이고, 말없이 뒤집으면 캡틴 배차 수가 조용히 달라진다.
- **표식 접두를 검사하는 시험은 사후 기록이 아닌 예시로 바꿔라** — `## 🔴 캡틴 확인 — 눈으로
  봐야 한다` 가 실제로 쓰이는 서식이다.
- **사후 기록만 있는 경우는 오늘 동작을 그대로 적은 별 시험으로 남겨라**, 그 답이 아직 열려
  있다는 것과 함께. 🔴 열린 물음이 시험 안에 숨어 있으면 다음 사람이 또 모르고 지나간다.

## 완료 시 시연되는 것

**누가 무엇을 하나:** 계획 순서를 묻는 사람(firstmate 또는 캡틴)이 "지금 나란히 갈 수 있는 것" 을
물으면, 돌아온 목록의 각 줄이 **그 티켓에 캡틴 눈이 걸렸는지 스스로 말한다.**

묻는 쪽은 티켓 파일을 한 장도 열지 않는다.

🟢 **그 자리는 오늘 있다** — 계획 순서를 묻는 창구는 이미 쓰이고 있고, 캡틴 눈 표시도 이미 화면에
붙어 있다. 이 티켓은 그 표시가 **어디서 오는지**만 바꾼다.

## 완료 조건

- 🔴 계획 순서를 묻는 답이 티켓마다 **캡틴 눈 여부를 싣는다.**
- 🔴 그 값은 **이미 계산된 판정 그대로**다. 새로 세지 않는다(INV-E1).
- 🔴 두 프로젝트 티켓 **137장에 대해 오늘과 똑같은 답**이 나온다. 캡틴 눈이 걸린 티켓 **90장**.
  숫자가 달라지면 판정을 건드린 것이다 — 멈추고 왜 그런지 적어라.
- 🔴 **판정 로직은 한 줄도 안 바뀐다.** 열린 결정이 닫히기 전에는 동작을 유지한다.
- 시험 이름이 그 시험이 실제로 정하는 것과 맞는다.
- 사후 기록 판정이 **열린 물음이라는 표시와 함께** 시험에 남는다.

## 테스트

| 상황 | 기대 | 어디 |
|---|---|---|
| 🔴 계획 답을 받는다 | 티켓마다 캡틴 눈 여부가 실려 있다 | 계획 출력 |
| 눈이 필요한 티켓 / 아닌 티켓 | 각각 맞게 실린다 | 계획 출력 |
| `## 🔴 캡틴 확인 — 눈으로 봐야 한다` | true — **표식 접두 시험의 새 예시** | 판정 |
| `## 캡틴 확인 — 없음` | false (그대로) | 판정 |
| `### 캡틴 확인 결과 (날짜)` | false (그대로) | 판정 |
| 🔴 사후 기록만 있고 요청 절 없음 | 오늘 동작 그대로 + **열린 물음 표시** | 판정 |

판정 시험은 이미 있다
([`code/web/core/src/parse/feature.test.ts`](../../../../code/web/core/src/parse/feature.test.ts) 351~375행) —
🔴 **거기에 얹어라, 새 파일을 만들지 마라.**
계획 출력에 값이 실리는 것은 **이 티켓이 처음 덮는다.**

## 이 티켓이 하지 않는 것

- 🔴 **판정 규칙 고치기.** 두 오판 다 gootte 쪽에는 없다. 137장 대조로 확인했다.
- 🔴 **사후 기록 판정 뒤집기.** 캡틴 몫으로 열려 있다.
- 🔴 **옆 도구 고치기.** 저장소 밖이고 이미 고쳐졌다. 이 티켓이 착지한 **뒤에** 그쪽의 중복 읽기를
  지우는 것이 남은 일이다 — 사양 §저장소 밖 후속.
- **👁 표시 모양 바꾸기.** 표시가 아니라 판정 자리를 옮기는 일이다.
- **137장 제목 손질.** 열린 결정이 닫히면 그때.

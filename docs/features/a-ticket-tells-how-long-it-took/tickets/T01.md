# T01 — 기록된 시각에서 걸린 시간을 파생한다

## Goal

백로그 메모의 `time:` 줄을 읽어 티켓마다 **사람이 읽는 어림 문구**(`약 14분`)를 파생한다.
화면은 아직 안 바뀐다 — 이 티켓은 값을 만들어 계약에 싣는 데까지다.

## Why this slice

두 탭이 **같은 문구**를 보여야 한다(수용 기준 2). 계산 자리가 둘이면 그 순간 갈라진다.
그래서 파싱과 어림을 먼저 한 자리에 세우고, T02 가 그 값을 두 곳에 옮기기만 한다.

- `FeatureTicket` 에 실리는 걸린 시간 **문구** 한 칸. 모르면 없음.

## Implementation notes

- `time:` 줄은 메모 안 어디에 있어도 된다 — 기존 메모와 나란히 살기 때문이다.
  줄이 여러 번이면 **첫 줄**이 이긴다(기존 `Status:` 파싱과 같은 규율).
- 시각 문자열은 ISO 8601 로 파싱한다. 파싱 실패는 **모름**으로 접는다 — 예외로 죽지 않는다.
- `finished` 없음 = 진행 중. `started` 없음 = 아무것도 모름(문구 없음).
- 완료가 착수보다 이르면(시계 되돌아감 등) 모름으로 접는다 — 음수 시간을 화면에 내지 않는다.
- 어림 함수는 **순수**하고 인자로 두 시각을 받는다. 진행 중 계산에 쓰는 현재 시각도
  인자로 받는다 — 그래야 시험이 시계에 흔들리지 않는다.

## Acceptance criteria

1. `time: started=... finished=...` 메모가 있는 티켓의 문구가 `약 N분` 이다.
2. 1시간 이상이면 `약 H시간 M분`, 분이 0이면 `약 H시간`.
3. 59초는 `약 1분` 이다(0분 아님).
4. `finished` 가 없으면 진행 중임이 문구에 드러난다.
5. `time:` 줄이 없으면 문구 칸이 비어 있다.
6. 망가진 시각·역전된 시각은 문구 없음으로 접히고 예외가 나지 않는다.
7. 기존 메모(티켓 경로)가 함께 있어도 둘 다 정상 파싱된다.
8. `pnpm -C code/web verify` green.

## Verification

routine. 🔴 파싱 픽스처는 **실물 백로그 줄 모양**에서 떠 온다 — 티켓 경로 메모와 `time:` 줄이
나란히 있는 실제 모양. 어림 규칙은 경계값(59초·60초·3600초·3660초)을 시험으로 고정한다.

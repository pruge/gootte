# T06 — 콜드 스캔의 git 하위프로세스 배치화

**캡틴 확인:** 필요 없음

**Status:** resolved (2026-08-28)

## Goal

스캔(또는 프로젝트 재계산) 한 번이 돌리는 git 하위프로세스 수를 줄인다.
`readFeatures` 는 기능 폴더·사본마다 `checkIgnored` + `unlandedPaths` 를 각각 spawn 해서
jinwooauto 실측 36 기능 × 2 사본 ≈ 72 회 — 13초의 본질이다.

## Why this slice

영구 스냅샷(adr/0001)은 스캔을 "평생 몇 번" 으로 줄이지만, 그 몇 번(F1 최초 스캔 · F3/F4 의
프로젝트 단위 재계산)이 여전히 13초면 첫 실행과 커밋 직후 반영이 여전히 느리다.
캐시가 무효화되는 순간의 고통을 줄이는 조각이다.

## Design

- `checkIgnored`(`git.ts:91`)는 이미 `--stdin` 일괄 인터페이스다 — 호출측(readFeatures 경로)에서
  폴더마다 부르지 말고 **유니크 경로 모아 한 번** 부르도록 모은다.
- `unlandedPaths`(`git.ts:112`)도 같은 일괄화를 검토한다(subprocess 를 아예 안 돌릴 방법이
  있으면 그쪽이 이긴다).
- `walkSlug` 가 파일 상대경로를 이미 모으므로, "폴더당 호출" → "프로젝트 사본당 호출" 로
  퍼즐만 다시 끼우는 작업이다.

## Explicitly out of scope

- git 외부 명령 대체(노드 라이브러리 등) — 정확성 근거가 git 자체라 바꾸지 않는다(INV-4).
- plan.db 읽기 등 gootte 자기 데이터 최적화.

## Evidence anchors

- `code/web/core-io/src/git.ts:91`(checkIgnored) · `:112`(unlandedPaths)
- `code/web/core-io/src/features.ts` — walkSlug/readFeatures 호출 구조

## Acceptance criteria

1. 동일 픽스처에서 readFeatures 의 git spawn 횟수가 유니크 경로 수 규모로 감소한다(실측 숫자를
   이 티켓 Comments 에 남긴다).
2. 계산 결과가 배치화 전과 같다 — 판정값 변화 없음(INV-4).
3. `pnpm verify` green.

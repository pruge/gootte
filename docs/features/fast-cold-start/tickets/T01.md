# T01 — projects 페이로드 캐시 (스피너 멈춤의 절반)
Status: resolved (2026-08-27)

## 목표

`/api/projects` 가 매 요청마다 사본마다 `git` 하위프로세스를 도는 `readFeatures` 를 다시 부르지 않게 한다.  
5초 TTL 의 projectsPayload 캐시를 discover 캐시와 같은 자리(`discover-cache.ts`)에 두고,
같은 무효화 신호(`clearDiscoverCache`)에 묶어 stale 폭을 폴백 폴링 주기(15초) 이하로 유지한다.

## 왜 이 조각인가

`/api/projects` 가 사본마다 `readFeatures` 를 다시 부르면 **콜드 13초, 두 번째도 13초**가 돼
5초 주기 폴백 폴링이 두 번째 요청을 또 큐에 넣어 스피너가 forever spinning 된다.  
discover 캐시(슬러그→사본 경로 묶기)는 이미 들어갔지만, **`projects` 페이로드 전체**(백로그 조인 + openFeatures) 캐시는
없어 그 자리에서 매번 git 하위프로세스가 돈다. 그 자리만 캐시하면 폴백 폴링이 5초마다 다시
읽어도 <100ms 로 떨어진다.

## Produces

`getProjectsPayload(roots, build)` — `discover-cache.ts` 에 추가.  
- 캐시 미스 시 `build(roots)` 호출, 결과를 5초 캐시.
- 캐시 히트 시 빌드 호출 없이 직렬화된 결과 반환.
- `clearDiscoverCache()` 와 같은 무효화 신호 — `kind === "projects"` ChangeEvent, settings 변경, 사본 변경 등.

## Consumers

- `code/web/backend/src/app.ts` — `/api/projects` 핸들러가 `getProjectsPayload(effectiveRoots(), () => …)` 로 감싸 호출. `build` 안에서 `readBacklogTasks` → `getProjects` → `openFeatures` 계산.

## Touched surfaces

- `code/web/backend/src/discover-cache.ts` — `getProjectsPayload` 신설, `DISCOVER_TTL_MS` 재사용.
- `code/web/backend/src/app.ts` — `/api/projects` 핸들러가 `getProjectsPayload` 사용.
- `code/web/backend/src/index.ts` — `getProjectsPayload` export.

## Explicitly out of scope

- 폴백 폴링에서 `projects` 제외 + 15초로 조정 — T02.
- `live.ts` 의 `setFallbackPolling` / `onmessage` — T02.
- `FALLBACK_POLL_MS` 값 — T02.
- watcher 가 닫힌 환경(서버가 디스크를 직접 감시하는 모드)이 아니라, 브라우저 탭이 닫힌 환경.

## Locked decisions

- 캐시 TTL 은 `DISCOVER_TTL_MS`(=5초)와 같다. 별도 상수를 두지 않는다.
- 무효화 신호는 `clearDiscoverCache` 와 같다. discover 캐시와 별도로 무효화하지 않는다.
- `build` 는 캐시 미스 시에만 호출된다. 호출자가 side effect 를 기대하지 않는다.
- INV-1: 캐시 결과도 저장하지 않는다. 매 TTL 만료 후 재계산.
- INV-2: 캐시 무효화 신호는 `watch-fallback` 의 `projects` ChangeEvent 와 `clearDiscoverCache` 가 부르는 자리뿐이다.

# T02 — Fallback polling 제외 projects 쿼리 + TTL 조절 (스피너 멈춤)

## 목표
폴백 폴링(Fallback Polling) 모드에서 `projects` 쿼리를 제외하고, 15초 주기로 조정하여 스피너가 반복되지 않도록 함.

## 왜 이 조각인가
이전 `live.ts` 에서는 `watch-fallback` 이 활성화되면 `qc.invalidateQueries()` 를 호출해 **전체 쿼리(including `projects`)를 5초마다 다시 가져오려 했습니다.** 그런데 `/api/projects` 가 13초씩 걸리니 스피너가 forever spinning 되버립니다.

**핵심 insight**: `projects` 목록은 doc change event 로 바로 업데이트 하면 되므로, 폴백 폴링에서 제외해도 됩니다. 대신 `projects` kind 의 ChangeEvent 가 올 때만 invalidate 시켜야 합니다.

## 설계
`live.ts` `setFallbackPolling` 함수에서 `projects` 쿼리를 제외하고 폴백 폴링을 진행하도록 수정합니다.

### `setFallbackPolling` 수정
```ts
const setFallbackPolling = (active: boolean): void => {
  if (active && !pollTimer) {
    // 🔴 `projects` 목록은 무거워 폴백 폴링에서 제외 — 문서 변경 신호가 올 때만 갱신한다.
    // 감시가 닫힌 환경에서 5초마다 목록을 다시 읽으면 스피너가 멈추지 않는다(fix/projects-listing-spin).
    pollTimer = setInterval(
      () =>
        void qc.invalidateQueries({
          predicate: (q) => !(Array.isArray(q.queryKey) && q.queryKey[0] === "projects"),
        }),
      FALLBACK_POLL_MS;
    } else if (!active && pollTimer) {
      clearInterval(pollTimer);
      pollTimer = null;
    }
  };
```

### `onmessage` 수정
이미 `if (ev.kind === "projects")` 에서 `qc.invalidateQueries({ queryKey: ["projects"] })` 로 처리되므로, 별도 처리는 불필요하지만 **폴백 폴링 중에도 이 신호는 정당하므로 유지**합니다.

### `FALLBACK_POLL_MS` 조정
`5_000` → `15_000` 로 조정하여 빈도를 낮춥니다(선택사항이나 권장).

## 수락 기준
1. 폴백 폴링이 `projects` 쿼리를 제외하고 `invalidateQueries` 를 호출합니다.
2. `projects` kind 의 ChangeEvent 가 올 때 `projects` 쿼리 무효화가 일어납니다.
3. `pnpm -C code/web verify` green.
4. 스피너가 폴백 폴링으로 인해 멈추지 않게 됩니다.

## 검증
- `curl -s http://localhost:8804/api/projects` 첫 호출: 12-15초.
- 두 번째 호출(15초 이내): <100ms (캐시 적중).
- `pnpm -C code/web verify` green.
- 스피너가 폴백 폴링으로 인해 멈추지 않게 됩니다.

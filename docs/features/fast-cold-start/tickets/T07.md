# T07 — 캡틴 확인: 재부팅해도 첫 화면이 즉시인가

**캡틴 확인:** 필요 — 아래 수용 시나리오의 화면 실측

## Goal

T03~T06 이 착지한 뒤, 캡틴이 직접 앱을 껐다 켜 보고 이 기능의 완료를 판정한다.

## 캡틴 지시 기준 시나리오

1. **첫 실행(스냅샷 없음):** 스캔이 돌고(느려도 된다), 끝나면 목록이 뜬다. 스냅샷 파일이
   생겼는지 확인.
2. **재부팅:** 앱을 완전히 끄고 다시 킨다. 첫 `/api/projects` 가 **즉시(<100ms)** 답하고
   스피너가 사실상 안 보인다.
3. **커밋 등록 후 재부팅:** 관리대상 프로젝트에서 커밋을 하나 만들고 재부팅한다. 첫 화면은
   스캔 시점으로 빠르게 뜨고, 잠시 뒤 그 프로젝트 내용이 갱신된다.
4. **켜져 있는 상태에서 편집:** 문서를 고치면 해당 프로젝트만 곧바로 갱신된다.
5. **격리 사본 사건 재발 방지 🔴:** 격리 사본 dev 서버가 `GOOTTE_DATA_DIR` 을 따로 두었을 때
   캡틴 스냅샷을 읽어 오지 않는다.

## Acceptance criteria (종결 조건)

- 위 시나리오 5개 중 실패가 없거나, 요청 변경사항이 새 티켓으로 갈라져 나간다.
- `pnpm verify` green.
- spec.md 의 수용 조건 1~4가 전부 참이다.

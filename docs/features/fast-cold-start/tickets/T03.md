# T03 — 영구 discover 스냅샷: 저장하고 부팅에 즉시 서빙

**Blocked by:** 없음 — 즉시 착수 가능
**Status:** resolved (2026-08-27 21:35)
**캡틴 확인:** 필요 없음

## Goal

discover + `readFeatures` 스캔 결과를 디스크에 영구 저장하고, 백엔드 재시작 직후 첫
`/api/projects` 요청이 <100ms 로 답하게 한다. 지금은 캐시 생애가 프로세스와 같아
**재시작할 때마다 첫 요청이 ~13초** 다.

## Why this slice

T01 이 만든 `getProjectsPayload` 캐시(`discover-cache.ts`)는 5초 TTL 만료마다 값을 **버리고**
재계산한다. 캡틴 지시(2026-08-27)의 본질은 "읽어온 정보를 버리지 마라 — git 위치와 함께
영구히 갖고 있어라" 이다(adr/0001). 저장 자리만 바꾸면 F1(스캔→저장)과 F2(즉시 서빙)가
한 조각으로 착지한다.

## Produces

**`GOOTTE_DATA_DIR` 아래의 스냅샷 파일 + 그것을 읽고 쓰는 모듈.**

- 스키마는 zod, backend 내부에 둔다(경계 넘는 공유 타입이 아니라 backend 단독 저장 포맷이라
  contract 가 아니라 discover-cache 옆). `version` 필드로 포맷 진화에 대비한다.
- 내용: `scannedAt`, 프로젝트별 `{ slug, root, copies, stamps: [{ repo, head }],
  features: readFeatures(copies) 결과 }`. `features` 는 verbatim 직렬화(INV-4) —
  `/api/projects` 페이로드와 `/api/features/:slug` 가 함께 먹는 단일 소스다.
- 읽기: 부팅 시 zod 검증 → 통과면 메모리로 올린다. 실패하면(깨짐·포맷 불일치) 파생물을
  버리고 재스캔하는 게 정상 경로다(INV-1).
- 쓰기: 스캔 직후·갱신 직후(write-through는 T05 몫).

## Consumers

- `code/web/backend/src/app.ts:285` — `getProjectsPayload` 의 build가 아니라 스냅샷에서 답한다.
- `/api/features/:slug`(`app.ts` 여러 곳) — `readFeatures(proj.copies)` 대신 스냅샷의 해당
  프로젝트 `features` 를 답한다.
- T04(검증) · T05(증분 갱신) — 이 조각이 만든 저장소 위에서 산다.

## Explicitly out of scope

- HEAD 비교·재검증 — **T04 의 몫이다.** 이 조각은 스탬프를 기록할 뿐 비교하지 않는다.
- watcher 배선 변경 — T05.
- 스캔 속도 줄이기 — T06.

## Locked decisions

- 저장 위치는 `planDataDir()` 해석 값을 따른다(`app.ts:79-82`) — 새 env 를 만들지 않는다.
- 격리 사본 주의 🔴 — GOOTTE_DATA_DIR 은 포트처럼 안 갈라지므로, 스냅샷도 사본별 값 분리가
  없으면 격리 사본 dev 서버가 캡틴 스냅샷을 읽어 버린다. **해석된 dataDir 경로가 SoT 인 것처럼,
  스냅샷은 그 dir 안에 있으므로 사본이 다른 dir 을 보면 자연히 다른 스냅샷을 본다.**
  (폴더만 잘 따르면 구조적으로 안전 — 파일을 강제로 공유하지 않게 한다.)
- INV-2 — 관리대상에는 여전히 아무것도 쓴다 하지 않는다.
- INV-5 경계 판정은 adr/0001 — 파생 데이터 memoize 를 허용했다.

## Acceptance criteria

1. 스냅샷이 있는 상태에서 백엔드 재시작 → 첫 `/api/projects` <100ms, git 하위프로세스 0건.
2. 스냅샷이 없으면 전체 스캔 후 파일이 저장되고, 재시작 뒤부터 1이 된다.
3. 스냅샷 파일을 손상시키면 앱은 크지 않고 재스캔으로 회복한다.
4. `/api/features/:slug` 도 스냅샷이 있을 때 git 하위프로세스를 돌리지 않는다.
5. `pnpm verify` green.

# T05 — Git subprocess reduction in readFeatures

## Goal
Reduce the number of git subprocess calls per feature folder per copy. Currently `readFeatures` calls `checkIgnored` and `unlandedPaths` per feature folder per copy, which is the primary cause of the ~13s delay. The fix is to batch these calls or cache results per feature folder.

## Why this slice
Previously `readFeatures` called git subprocesses per feature folder per copy, and `/api/projects` called it for every project on every request, uncached. The cumulative git subprocesses across all projects and copies caused ~13s delay. Reducing subprocess calls per feature folder per copy is the most impactful fix.

## Why this slice
Previously `readFeatures` makes git subprocess calls per feature folder per copy — `checkIgnored` + `unlandedPaths` per folder. With 36 features × 2 copies = 72 subprocesses for jinwooauto alone, this is the primary cause of the 13s delay in `/api/projects`. Reducing these calls is the most impactful fix.

## Why this slice
Previously `readFeatures` called git subprocesses per feature folder per copy. The fix batches or reduces these calls. The `CopyResolver` already has caching per copy pair; extend that to the `readFeatures` path. Also `walkSlug` can avoid re-reading files already seen.

## Design
- Add `checkIgnoredBatch(paths)` that does one git invocation per root instead of per file.
- Add `unlandedPathsBatch(paths)` similarly.
- In `readFeatures`, use the batch versions when available.
- The `CopyResolver` already has per-copy caching; extend its lifetime or expose it.
- `walkSlug` collects file paths then does one `checkIgnored` per unique path instead of per feature folder.

## Acceptance criteria
1. `readFeatures` for 36 features × 2 copies: subprocess calls reduced from ~72 to ~36 (one per unique path).
2. `getProjectsPayload` (or `/api/projects`) returns in <5s after first load (cache hit).
3. `pnpm -C code/web verify` green — no regression in feature read logic.

## Verification
- Profile git subprocess calls before and after: `git check-ignored` count.
- `pnpm -C code/web verify` green.
- Profile `readFeatures` time before and after.

## Sprint note
This is the most impactful micro-optimisation — reducing git subprocess spawns. The `CopyResolver` already has caching; extending it to `readFeatures` gives the biggest bang for buck. Subsequent T05/T06 tickets build on this.

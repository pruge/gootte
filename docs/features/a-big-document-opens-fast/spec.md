# 큰 문서도 빠르게 열린다

## 문제

read-path 재설계(`read-path-redesign`)로 **서버 쪽 읽기 경로는 끝났다** — 문서 API 는 1.2~1.5ms 다.
그런데 큰 문서는 작은 문서보다 눈에 띄게 늦게 뜬다 — **남은 시간이 전부 브라우저 안에서 쓰인다.**

T08 검수에서 실측한 것(2026-09-04, `read-path-redesign/tickets/T08.md`)은 API 3~5ms 에
큰 문서 클릭 → 표시 **311~331ms** 였다.

🔴 **T01 이 다시 재 보니 그 값이 재현되지 않았다**(→ [`measurement-2026-09-04.md`](measurement-2026-09-04.md)).
`perf-*` trace 를 켠 채 잰 것이 부풀린 값이었을 가능성이 높다 — T01 도 trace 직후 표본에서 347.9ms 를
한 번 봤고, trace 없이 재면 아래 값이 나온다.

| 무엇 | 실측(프로덕션 빌드, Chrome, 2026-09-04) |
|---|---|
| 문서 API 단독 | **1.2~1.5ms** |
| 작은 문서(1,300자) 클릭 → 표시 | **13~15ms** (첫 열기 50.9ms) |
| 큰 문서(21,044자) 클릭 → 표시 | **82~87ms** (첫 열기 124.2ms) |

**차이의 성질은 그대로다** — 서버는 끝났고 남은 시간은 전부 브라우저 안이며 문서 크기에 비례한다.
**크기만 열 배 작다.**

## 지금 구조 (실측)

`code/web/frontend/src/components/features/DocDrawer.tsx` 가 본문을 그린다.

```tsx
<ReactMarkdown remarkPlugins={[remarkGfm]} components={MD_COMPONENTS}>
  {data.content}
</ReactMarkdown>
```

- 렌더러 = `react-markdown@9` + `remark-gfm@4` (`code/web/frontend/package.json`)
- 문서 전체를 **한 번의 동기 렌더**로 파싱 + 리액트 트리 생성 + 커밋한다.
- 서랍이 열리는 커밋과 본문이 그려지는 커밋이 같다 — 그래서 파싱이 끝날 때까지 화면이 안 움직인다.

T01 이 이 비용을 갈랐다 — **파싱 23~39ms · DOM+레이아웃 15~28ms · React 재조정 ~20~40ms.**
근거와 방법은 [`measurement-2026-09-04.md`](measurement-2026-09-04.md).

## 목적

**큰 문서를 클릭했을 때도 즉시 무언가가 보이고, 본문이 곧 따라온다.**
"전부 준비될 때까지 아무것도 안 보인다" 를 끝내는 것이 목적이지, 렌더 시간 자체를 0 으로 만드는
것이 목적이 아니다.

## T01 이 확정한 것 — 지배 구간이 없다

warm 82~87ms 는 셋으로 고르게 갈린다: **마크다운 파이프라인 23~39ms · DOM+레이아웃 15~28ms ·
React 재조정 ~20~40ms.** 🔴 **하나를 고쳐도 3분의 1만 준다** — 그래서 T01 은 처방 티켓을 내지 않았다.
지금 값에서 더 깎는 것은 **비용 대비 이득이 없다**는 것이 T01 의 판단이다.

남은 진짜 공백은 하나다: 위 숫자는 전부 **Chrome** 것이고, 캡틴이 쓰는 것은
**Tauri = WKWebView** 다. 엔진이 다르면 결론이 달라질 수 있다 → **T02**.

## 불변식 점검

- **INV-3(stale 뷰 금지)** — 무엇을 늦게 그리든 **결국 그려지는 것은 현재 SoT** 여야 한다.
  본문 일부만 그리고 마는 최적화는 금지.
- **INV-4(read-path 는 결정적)** — 마크다운을 요약하거나 잘라 보여주지 않는다. **verbatim 릴레이.**
- INV-1·INV-2·INV-5 는 해당 없다(이 작업은 아무것도 저장하지 않고 관리대상을 건드리지 않는다).

## 범위 밖

- 서버 읽기 경로 — 이미 1.2~1.5ms 다.
- 문서 목록·뱃지·감시 체계 — `read-path-redesign` 이 갖는다.
- 마크다운 렌더러를 바꾸는 결정 자체 — **측정 결과가 그것을 가리키면 그때 ADR 로 끊는다.**

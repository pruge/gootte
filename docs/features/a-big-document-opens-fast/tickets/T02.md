# T02 — 캡틴이 실제로 쓰는 엔진(Tauri · WKWebView)에서 다시 잰다

**Blocked by:** T01

**Status:** wontfix (2026-09-04 16:24)

## Goal

T01 의 숫자는 전부 **Chrome** 에서 나왔다. 캡틴이 쓰는 것은 **Tauri 데스크톱 앱 = WKWebView
(Safari 엔진)** 다. **같은 문서를 그 엔진에서 재서**, T01 의 결론(지배 구간 없음 · warm 82~87ms)이
거기서도 유지되는지 확인한다.

## Why this slice

T01 이 "고칠 것이 없다" 고 결론지었는데, 그 결론이 **캡틴이 보지 않는 엔진에서만 참일 수 있다.**
마크다운 파싱은 순수 JS 라 엔진 차이가 크게 나는 자리이고(JSC vs V8), DOM·레이아웃도 다르다.
🔴 **틀린 안심은 안 재는 것보다 나쁘다** — 이 저장소는 "화면이 고장난 게 아니라 문서가 그렇게 말하고
있었다" 는 사고를 이미 겪었다.

## Produces

- WKWebView 실측을 `measurement-2026-09-04.md` 옆에 덧붙인 기록(같은 표 모양으로 비교 가능하게)
- Chrome 대비 차이가 **유의미하면** 그것을 고치는 후속 티켓, **아니면** 이 기능을 닫는 판단

## Consumers

캡틴 · 이 기능을 닫을지 이어갈지 정하는 사람.

## Touched surfaces

측정만이다. 제품 코드는 건드리지 않는다.

## Explicitly out of scope

- 번들 단일 청크(578.87kB) — 첫 진입 비용이지 문서 렌더가 아니다. **별개 기능으로 다룬다.**

  🔴 방법이 다르면 두 숫자를 비교할 수 없다.
- **캡틴 서버(`:8804`/`:5304`)를 뺏지 않는다** — 스킬 `gootte-dev-server` 대로 자기 포트·자기
  `GOOTTE_DATA_DIR` 로 띄운다.

## Regression guards

동작을 바꾸지 않는다 — `git status --porcelain code/web` 가 비어 있는 것이 가드다.

## Scope

1. `pnpm dev:tauri` 로 띄운다(캡틴 앱이 떠 있으면 그것부터 정리 여부를 캡틴에게 묻는다 —
   🔴 임의로 죽이지 않는다).
2. WKWebView 에 **LoAF 가 없을 수 있다.** 없으면 대체 계측을 쓰고 **무엇으로 갈랐는지 적는다**
   (`performance.now()` 구간 · `PerformanceObserver` 의 `event`/`paint` 엔트리 등).
   🔴 갈리지 않는 축은 **갈리지 않았다고 적는다.**
3. 두 문서 × 4회를 재고 T01 표와 나란히 놓는다.
4. 차이가 유의미하면(예: 큰 문서가 2배 이상) **그 구간을 고치는 티켓**을, 아니면
   **이 기능을 닫는 판단**을 spec 에 적는다.

## Implementation notes

- Tauri 는 `localhost` 가 아니라 커스텀 스킴으로 자산을 낼 수 있다 — Resource Timing 의 이름이
  다를 수 있으니 필터를 확인하고 적는다.
- Safari 계열은 개발자 도구 연결 경로가 Chrome 과 다르다. `chrome-devtools-axi` 는 **여기에 못 붙는다** —
  in-page `eval` 을 쓸 수 없으면 **계측 코드를 임시로 넣고 이 티켓이 끝날 때 되돌린다**(그 사실을 적는다).

## Acceptance criteria

- AC1 — WKWebView 에서 두 문서의 click→paint 가 각 4회씩 기록되어 있다(1회차/warm 분리).
- AC2 — 어떤 도구로 어떻게 쟀는지, Chrome 때와 **무엇이 달랐는지**가 적혀 있다.
- AC3 — Chrome 기준선과의 차이가 **수치로** 비교되어 있다.
- AC4 — 그 차이에 대한 판단(후속 티켓 / 이 기능 닫기)이 spec 에 반영되어 있다.
- AC5 — 제품 코드에 계측 잔재가 없다.
- AC6 — `pnpm verify` green.

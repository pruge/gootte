# T04 — legacy git·백로그 완료 처리 전부 제거, `Time:` 줄만으로 판정 (ADR-0001)

## Goal

`ticket-done-from-git` 기능(T01·T02·T03·T06·T07)이 만든 git 기반 완료 리졸버와, 백로그 조인이
만든 완료 판정 경로를 **완전히 제거**한다. 신관례(`tickets/T<NN>.md`) 티켓의 상태는 이제
티켓 문서 자체의 `Time:` 줄에서만 파생한다:

```
finishedAt 있음         → done
startedAt 만 있음        → in_progress
둘 다 없음(Time: 줄 없음) → pending(queue)
```

결정 근거: [`adr/0001-time-line-replaces-git-backlog-completion.md`](../adr/0001-time-line-replaces-git-backlog-completion.md).

## Why this slice

T01(CLI `start`/`end`)과 T02(파서가 `Time:` 줄 읽기)가 이미 착지했다. 이 티켓은 그 위에서
**기존 완료 판정 경로(git·백로그)를 걷어내** `Time:` 줄이 유일한 진실이 되게 한다.
지금은 3단 우선순위(`Status:` 문서 → git 리졸버 → 백로그)가 공존해 캡틴이 신고하신 버그
(오탐→미탐 반복, 2026-08-29)가 계속 재발했다 — 근본 원인은 "커밋 메시지 텍스트에서 완료를
추론"하는 접근 자체다. 이 티켓이 그 접근을 완전히 걷어낸다.

## Produces

- `joinTicket`(backlog-join.ts) — 새 3단 규칙(`finishedAt`/`startedAt`/없음)만으로 신관례
  티켓 상태를 정한다. git 호출도 백로그 조인 호출도 없다.
- 코드 삭제(아래 Explicitly removed 참조).

## Locked decisions

- 🔴 **`Time:` 줄만으로 판정** — git 리졸버도 백로그 조인도 완료 판정에 관여하지 않는다.
- 🔴 **구관례는 건드리지 않는다** — `issues/` 티켓의 `Status:` 기반 판정은 그대로.
- 🔴 **검수 전용 티켓(구현 코드 없는 티켓)은 `gootte start`+`end`를 형식적으로 호출해야 완료된다**
  — 이 티켓은 그 워크플로를 만들지 않는다, 규칙만 spec.md에 문서화(완료).
- 죽은 배선(`ticketDone` 쿼리 무효화 — 그 쿼리 자체가 어디에도 정의 안 됨)도 같이 정리한다.

## Acceptance criteria

1. `resolveTicketDone`/`ticketDoneResolver`/`setTicketDoneResolver` 코드베이스에서 완전히 사라짐
   (`grep -rn "resolveTicketDone\|ticketDoneResolver" code/web` 결과 0).
2. `ticket-git-status.ts` 파일 존재하지 않음.
3. `Time: finished=...`가 있는 티켓 → done으로 뜬다(git 커밋 없어도).
4. `Time: started=...`만 있는 티켓 → in_progress로 뜬다.
5. `Time:` 줄이 없는 티켓 → pending(queue)으로 뜬다(백로그 상태와 무관).
6. 구관례(`issues/`) 티켓 판정은 회귀 없음(그대로 `Status:` 기반).
7. `pnpm -C code/web verify` green.

## Verification

routine. `finishedAt`/`startedAt`/없음 세 갈래를 실물 티켓 문서 모양 픽스처로 고정하고,
구관례 회귀 시험(`feature.test.ts`의 `parseTicket` 케이스)이 그대로 통과하는지 확인한다.

# T02 — 파서가 `Time:` 줄을 읽고 백로그 `time:` 경로를 제거한다
Time: started=2026-08-29T15:22:46+09:00 finished=2026-08-29T15:22:48+09:00

## Goal

신관례 티켓 파서가 `Time:` 줄을 읽어 `startedAt`/`finishedAt`을 싣고, 걸린 시간 문구를
티켓 문서 시각에서 파생하도록 경로를 전환한다. 동시에 백로그 메모의 `time:` 줄 파싱과
그 경로의 elapsed 계산을 제거한다(grill D2 — 완전 교체).

## Why this slice

T01이 `Time:` 줄을 **쓰는** CLI를 만들었다. 이 티켓은 그 줄을 **읽어서** 대시보드에
걸린 시간을 보여주는 경로를 완성하고, 동시에 옛 경로를 걷어낸다.

## Produces

- 신관례 티켓 파서(`parseNewTicket`)가 `Time:` 줄에서 `startedAt`/`finishedAt` 파싱.
- `joinTicket`이 티켓 자체의 시각에서 `elapsedPhrase`로 문구 계산.
- 백로그 파서에서 `time:` 줄 파싱(`TIME_LINE`, `startedAt`, `finishedAt`) 제거.
- `joinTicketBacklog`에서 `elapsed` 계산 제거.

## Consumers

  a-ticket-tells-how-long-it-took에서 이미 배선됨, 입력 원천만 바뀜)
- `code/web/frontend/src/components/process/ProcessView.tsx` — 같음

## Touched surfaces

- `code/web/core/src/parse/feature.ts` — `parseNewTicket`에 `Time:` 줄 파싱 추가,
  `NewTicketDoc`에 `startedAt`/`finishedAt` 칸
- `code/web/core/src/parse/backlog.ts` — `TIME_LINE` 정규식, `startedAt`/`finishedAt` 칸,
  파싱 로직 **제거**
- `code/web/core/src/project/backlog-join.ts` — `joinTicketBacklog`에서 elapsed 제거,
  `joinTicket`에서 티켓 시각 기반 elapsed 계산으로 전환
- `code/web/contract/src/index.ts` — `FeatureTicket`에 `startedAt`/`finishedAt` 선택 칸 추가
  (elapsed는 기존 칸 그대로)

## Explicitly out of scope

- `elapsedPhrase` 함수 자체의 변경 — 그대로 재사용.
- 구관례(`issues/`) 티켓의 시간 기록.
- 크루 자동화 규칙.

## Locked decisions

- 🔴 **완전 교체** — 백로그 `time:` 줄은 더 이상 읽지 않는다(grill D2).
- 🔴 **`Time:` 줄 파싱은 펜스 밖에서만** — `Status:` 줄과 같은 원리.
- 🔴 **파싱 픽스처는 실물 티켓 문서에서 떠 온다** — 지어내지 않는다.
- elapsed 우선순위: 티켓 문서 `Time:` 줄 → 없으면 없음.

## Acceptance criteria

1. 티켓 문서에 `Time: started=... finished=...`가 있으면 대시보드 hover에 `약 N분` 뜸.
2. `Time:` 줄이 없으면 시간 안 뜸.
3. `finished`가 없으면 `약 N분 진행 중`.
4. 백로그 메모에 `time:` 줄이 있어도 무시됨(파싱 코드 제거).
5. 기존 백로그의 다른 칸(url, section 등)은 영향 없음.
6. `pnpm -C code/web verify` green.

있는 실제 파일 모양.

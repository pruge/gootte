# T01 — 독립 셸 스크립트 `gootte start`/`end` 명령으로 티켓에 시각 기록
Status: resolved (2026-08-29)

## Goal

`gootte start <feature-slug> <ticket>` / `gootte end <feature-slug> <ticket>`을
**gootte TS 모노레포(`@gootte/core`, `@gootte/core-io` 등)를 전혀 참조하지 않는 독립 bash
스크립트**로 만들어, 신관례 티켓 문서(`tickets/T<NN>.md`)에 `Time:` 줄을 삽입·갱신한다.
`npm i -g`로 어느 프로젝트에서든 전역 호출 가능해야 한다.
커밋은 하지 않는다 — PR에 묻어간다(grill D3).

## Why this slice

시간 기록의 **쓰기** 쪽이다. T02가 이 줄을 gootte TS 파서로 **읽어서** 대시보드에
보여주는 쪽이다. 쓰기를 먼저 만들어야 읽기를 실물 파일로 검증할 수 있다.

## Why independent shell script (grill D5)

캡틴 원문: "gootte의 다른 코드를 참조하면 안되고, 단독 sh bin으로 만들어야지, md파일읽어서
status, time을 기록만하면되잖아?" / "gootte로 명칭하게해, gootte start, gootte end 로
하면되잖아. 명령어를 호출한 곳에서 docs를 찾아 수정하게하면 되니까."

이전 구현(PR #92, TS CLI `@gootte/cli` 안에 통합)은 폐기됐다. TS 워크스페이스 의존
(`workspace:*` 프로토콜)이 있으면 `npm i -g`로 모노레포 밖에서 전역 설치가 안 된다
(번들링 필요, `bin` 필드 없음, 의존성 해석 문제). md 파일만 읽고 쓰는 독립 스크립트면
이 문제가 통째로 사라진다.

## Produces

- `bin/gootte` (또는 `bin/gootte-start`/`bin/gootte-end` 두 개, 구현 중 택일) — 순수 bash.
  `gootte start <feature-slug> <ticket>` → 티켓 파일에 `Time: started=<ISO>` 줄 삽입.
  `gootte end <feature-slug> <ticket>` → 같은 줄에 `finished=<ISO>` 추가.
- gootte 루트 `package.json`의 `bin` 필드 — `npm i -g .`로 전역 설치 가능하게.

## Touched surfaces

- `bin/gootte` (신규) — 독립 bash 진입점. `start`/`end` 서브커맨드 라우팅.
- `package.json` (gootte 루트) — `bin` 필드 추가.
- `scripts/tests/gootte-time.test.sh` (신규) — 셸 시험. `scripts/tests/gootte-wrapper.test.sh`와
  같은 패턴(임시 디렉터리 fixture로 검증).

## Explicitly out of scope

- gootte TS 파서가 `Time:` 줄을 읽는 것 — T02 (그쪽은 `@gootte/core` 안에서 정상 구현).
- 대시보드 표시 — T02.
- 백로그 `time:` 줄 제거 — T02.
- `board`/`step`/`next` 등 다른 gootte 명령을 전역 설치 가능하게 만드는 것 — 범위 밖.
- 크루 자동화 규칙 — firstmate 쪽, 별도.

## Locked decisions

- 🔴 **gootte TS 코드 무의존** — `@gootte/core`, `@gootte/core-io`, `@gootte/contract`,
  `tsx` 등 어떤 워크스페이스 패키지도 import/require 하지 않는다. md 파일을 직접
  `cat`/`sed`/`grep`/`awk`로 읽고 쓴다.
- 🔴 **커밋 안 함** — 파일만 편집한다(grill D3).
- 🔴 **중복 방지** — 이미 `Time:` 줄이 있으면 `start` 에러. 이미 `finished`가 있으면 `end` 에러.
  `Time:` 줄이 없는데 `end` 호출해도 에러.
- 🔴 **프로젝트 인자 없음** — `<프로젝트>` 인자를 받지 않는다. 실행 위치(cwd)에서
  `docs/features/<feature-slug>/tickets/T<NN>.md`를 직접 찾는다(git 루트 탐색 또는
  cwd 상대 경로 — 둘 중 구현이 정한다. 이전 구현의 `resolveProjectPath`류 로직 재사용 금지,
  독립적으로 구현).
- 형식: `Time: started=2026-08-29T10:30:00+09:00 finished=2026-08-29T11:15:00+09:00`
  — `Status:` 줄과 같은 위치(제목 뒤, 본문 앞).
- 티켓 파일이 없으면 에러.
- 티켓 인자는 `T01` 또는 `01` 둘 다 지원(파일명 `T<NN>.md`로 정규화).

## Evidence anchors

- `scripts/gootte.sh` — 기존 독립 bash 진입점 패턴(tsx 존재 확인 후 위임) — 이번엔 위임 없이
  스크립트 자체가 로직을 갖는다.
- `scripts/tests/gootte-wrapper.test.sh` — 셸 스크립트 시험 패턴(임시 fixture, `fail()` 헬퍼).
- `docs/features/ticket-time-stamp/spec.md` §CLI 명령 — 정확한 계약.

## Regression guards

- `scripts/tests/gootte-time.test.sh` (신규)
- `pnpm test:ports`에 새 시험 스크립트 추가(기존 `ports.test.sh && gootte-wrapper.test.sh`
  체인에 이어 붙임) 또는 별도 `pnpm run test:gootte-time` — 구현이 정함.

## Acceptance criteria

1. `gootte start ticket-done-from-git T01` (프로젝트 루트에서 실행) → 티켓 파일에
   `Time: started=<ISO>` 삽입됨.
2. `gootte end ticket-done-from-git T01` → 같은 줄에 `finished=<ISO>` 추가됨.
3. 이미 시작된 티켓에 `start` → 에러 메시지(stderr), exit 0이 아님, 파일 안 바뀜.
4. 시작 안 된 티켓에 `end` → 에러 메시지, 파일 안 바뀜.
5. 없는 기능/티켓 → 에러.
6. `bash -n bin/gootte` 구문 검사 통과.
7. `npm i -g .` (또는 `npm link`)로 전역 설치 후 다른 디렉터리에서 `gootte start ...` 호출
   가능함을 확인.
8. `@gootte/*` 워크스페이스 패키지를 import/require하지 않음 — `grep -n "@gootte" bin/gootte`
   결과 없음.

## Verification

routine. 셸 스크립트 단위 시험 — 임시 디렉터리에 실물 티켓 모양의 파일을 만들고
`start`/`end` 후 내용을 `grep`/`diff`로 단언한다. `pnpm -C code/web verify`는 이 티켓
범위 밖(TS 코드를 안 건드리므로)이지만, 회귀 확인 삼아 한 번 돌려도 된다.

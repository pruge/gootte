# ADR-0001 — `Time:` 줄이 완료 판정의 유일한 출처가 된다 (git·백로그 완료 처리 폐기)

Status: accepted (2026-08-29)

## 무엇을 뒤집는가

`ticket-done-from-git` grill.md의 **D1**을 뒤집는다:

> D1 — 완료의 단일 출처는 git 이지 백로그가 아니다.
> 확정: 티켓 완료 여부 = `origin/main` 에 그 티켓을 가리키는 커밋이 도달 가능(reachable)한가.

새 결정: **완료 여부는 티켓 문서의 `Time:` 줄에서만 파생한다.**

```
finishedAt 있음 → done
startedAt 만 있음 → in_progress
둘 다 없음 → pending(queue)
```

git 리졸버(`resolveTicketDone`)와 백로그 조인(`joinTicketBacklog`)은 완료 판정에서 완전히 빠진다.
`ticket-done-from-git` 기능의 T01·T02·T03·T06·T07이 만든 완료 판정 경로 전체가 폐기된다.
D4(하이브리드 폴백, 문서 `Status:` 줄)도 함께 폐기된다 — `Time:` 줄 하나로 통일한다.

## 원래 규칙이 있었던 이유

grill.md 원문: "캡틴이 외부 클론에서 개발해 main 에 머지하면 gootte 대시보드가 알아서 완료로 바뀌고,
항해사(secondmate)에게 매번 완료 처리를 부탁할 필요가 없다." — 완료 처리 자동화가 목적이었다.

## 그 이유가 여전히 유효한가

부분적으로 유효하다 — "매번 부탁할 필요 없음"은 여전히 원하는 성질이다.
하지만 실제 구현이 그 목적을 달성하지 못했다:

- **번호만 매칭(원 D3)** → 오탐: 다른 기능의 커밋이 내 기능 티켓을 완료로 잘못 표시(2026-08-29 캡틴 신고).
- **slug+번호 매칭(T06)** → 미탐: slug가 커밋 메시지에 안 적히면(흔한 커밋 스타일) 놓침 — 원래 신고
  대상(`ticket-time-stamp`) 자신도 여전히 안 뜸.
- **slug 넓힌 매칭(T07)** → 미탐 축소되지만 근본 한계 여전(커밋 메시지 텍스트에 없는 정보는
  텍스트 매칭으로 못 만든다). 322개 커밋 중 19개 여전히 미탐.
- 세 번의 반복 수정(T01→T06→T07)이 전부 "커밋 메시지 텍스트에서 완료 신호를 추론"이라는
  같은 접근 안에서 패턴만 넓힌 것이라, 구조적으로 오탐/미탐 딜레마를 벗어나지 못했다.

## 왜 지금 뒤집는가

- `ticket-time-stamp` 기능(T01)이 `gootte start`/`gootte end` CLI로 티켓 문서에 **명시적** 시각을
  기록하는 경로를 이미 만들었다 — 커밋 메시지를 추론할 필요가 없다.
- 캡틴 결정(2026-08-29): "start, end로만 판단한다" — 크루가 작업을 시작·완료할 때 CLI를 호출하는
  것이 자동화의 실제 형태가 된다(원래 D1이 원했던 "매번 부탁할 필요 없음"을 다른 경로로 달성).
- 텍스트 매칭의 오탐/미탐 딜레마 자체가 사라진다 — `Time:` 줄은 추론이 아니라 사실 기록이다.

## 대가

- 검수 전용 티켓(구현 코드 없이 캡틴이 화면을 보고 판단하는 티켓, 예: `ticket-time-stamp-t03`)도
  `gootte start`+`end`를 형식적으로 호출해야 완료로 뜬다 — 이전엔 `Status: resolved` 한 줄로
  충분했다. 이 규율을 캡틴 워크플로에 알려야 한다.
- git 커밋만으로는 더 이상 완료가 안 뜬다 — 캡틴이 외부 클론에서 개발해 머지해도, `gootte start`/`end`를
  안 부르면 화면에 안 뜬다. 원래 D1의 "그냥 머지만 하면 자동으로 뜬다"는 편의는 사라진다.

## 캡틴 원문

> "1. git, backlog로 완료 처리/등 하는것 모두 제거햇으면 해, 영향범위 보고해. 싹 걷어냈으면해."
> "2. 문서에 gootte로 모든 ticket 에 start,end 적용하게햇으면해, 단 미개발한 티켓은 제외하고"
> "1. 앞으로 gootte start, end로 ticket에 시작시간과 끝시간을 기록하게한다.
>  2. 아직 시간 기록이 없으면 queue , 시작 시간만 있으면 in progress, 끝 시간이 있으면 done 으로 처리한다."
> "a 안으로 가자. 자세히 살펴서 legacy 코드 남지않게해. start, end로만 판단한다."

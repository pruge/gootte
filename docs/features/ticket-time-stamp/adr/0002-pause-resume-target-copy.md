# ADR-0002 — `pause`/`resume`: 여러 사본 중 Time 줄을 기록할 문서 결정

Status: accepted (2026-09-01)

## 문제

`gootte start`/`end`/`pause`/`resume`은 티켓 문서의 `Time:` 줄에 시각을 기록한다.
그런데 같은 slug의 티켓이 **여러 사본**(main + treehouse + Claude Code worktree)에
존재할 수 있다 — `readFeatures`는 이들을 병합해 하나의 화면으로 보여준다.

CLI(`bin/gootte`)는 **cwd**(실행 위치)가 곧 "어느 사본"인지 결정하므로 모호함이 없다.
그러나 앱(웹 UI)에서 버튼으로 기록할 때는 프로젝트 slug만 알고 있어 "어느 사본의
티켓 파일에 Time 줄을 쓸 것인가"가 모호해진다.

## 결정

두 가지 원칙으로 푼다:

### 1. 자동 선택(예측 가능한 경우)

- **같은 티켓에 `started=`가 이미 기록된 사본이 있으면** 그 사본에 이어서 기록한다
  (pause/resume/end가 같은 Time 줄의 연속이므로).
- **`started=`가 없으면(새 start)** "지금 누가 무엇을 붙들고 있나"에서 **working 상태인
  worktree 사본** 우선, 없으면 **대표 사본**(`copies[0]`, main)에 기록한다.
- worktree가 여러 개 working 상태면(드문 경우) **모호함**으로 간주한다.

### 2. 모호함 → dialog

자동 선택이 불가능할 때(여러 working worktree, 또는 판단 불가)는 앱이 **모든 사본의
경로 목록을 dialog로 띄워 사용자가 선택**하게 한다.

### INV-2(관리대상 읽기 전용)와의 관계

`gootte start`/`end` CLI는 사람이 명시적으로 실행하는 명령으로서 예외적으로 티켓 문서에
`Time:` 줄을 기록한다(INV-5: 사람만 아는 계획은 저장할 자격이 있다). 앱 버튼도
사람이 누르는 것이므로 CLI와 동등한 예외로 본다 — 단, 앱이 자동으로 기록하지는 않는다
(사용자 버튼 클릭을 통해서만 기록한다).

## 캡틴 원문

> "애매모호하면 dialog로 모든 폴더 목록을 보여주고 사용자가 선택하게한다.
>  최대한 예측 가능하면 자동으로 선택한다. 가령 start 시간이 있다면 그 문서를 기준으로 삼는다."

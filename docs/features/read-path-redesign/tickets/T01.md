**🔴 AC5 — 정직한 수치**

같은 사본 3개·같은 벤치로 stash 를 써서 HEAD 와 나란히 쟀다:

| | 1회차 | 2회차 | 3회차 |
|---|---|---|---|
| HEAD | 5,056ms | 4,467ms | 3,425ms |
| T01 | 4,711ms | 4,176ms | 3,482ms |

**차이가 실행 간 편차 안에 있다.** 제거한 작업을 따로 재면 `unlandedPaths` 3회 = **286ms** 로,
`readFeatures` ~4,000ms 의 7% 다.

spec 에 적었던 *"측정 22회 2.2초"* 는 **내 측정 오류였다** — git 시간을 PATH 셸 shim 으로 쟀는데
그 shim 이 호출마다 python 을 두 번 띄워 per-call 비용을 ~7배 부풀렸다. spec §3 에 정정을 적었다.

**그 정정이 밝힌 것 (다음 티켓들에 영향)**

`readFeatures` 4,000ms 의 정체는 **git 하위프로세스 35회 × ~80ms ≈ 2,800ms** 다. 파일 읽기는
299ms 뿐이다. 그리고 그 80ms 중 git 이 실제로 하는 일은 없다 — 셸에서 `git --version` 은 12ms,
plain node 에서 25ms, **`tsx` 아래에서 80ms** 다(dev 서버가 `tsx watch` 를 쓴다).

🔴 **지렛대 순서가 바뀐다: T06(git 호출 개수) 이 압도적 1위이고, T02(파일 읽기)는 163ms 다.**
캡틴께 보고하고 순서 조정 여부를 받는다.

**이 티켓의 값어치는 성능이 아니라 표면 축소다** — 유령 필드 둘과 죽은 배지 컴포넌트가 사라져
T04·T06·T07 이 다룰 대상이 작아졌다. 그렇게 적는 것이 정직하다.

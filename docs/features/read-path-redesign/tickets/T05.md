# T05 — 감시 축을 둘로 재편한다

**Blocked by:** T04

**Time:** started=2026-09-04T11:53:08+09:00 finished=2026-09-04T11:58:11+09:00

## Goal

지금 서로를 모르는 채 겹쳐 도는 다섯 개 트리거를 **두 축**으로 줄이고, 이벤트가 무효화하는
단위를 **기능 폴더 하나**로 내린다.

## Why this slice

T04 가 폴더 단위 무효화 창구를 만들었으므로, 이제 그 창구를 정확히 한 번씩 두드리는 배선이 필요하다.
지금은 같은 변경 하나에 부팅 스윕·15초 재검증·chokidar·새 폴더 우회가 동시에 반응해 풀스캔이 겹쳐 돈다.

## Produces

- 축 1 — `docs/features/**` 파일 감시. **모든 사본**(discover 사본 + Claude Code worktree + BB worktree).
  이벤트 → 그 기능 폴더 하나만 무효화.
- 축 2 — 사본 구성 · `.gitignore` 변경 이벤트(T06 이 쓴다).
- 안전망으로 강등된 주기 타이머 — 감시가 **안 붙는 환경에서만**, 무효화 단위는 여전히 폴더.

## Consumers

T06(git 을 이벤트로만) — 축 2 를 소비한다.

## Touched surfaces

`core-io/src/watch.ts` · `backend/src/watchers.ts` · `backend/src/server.ts` ·
`backend/src/snapshot-revalidator.ts`

## Explicitly out of scope

- git 질의 자체의 축소(T06).
- 워커 분리(T07).
- WS 이벤트 어휘 변경 — `kind:"project"` 등 지금 어휘를 그대로 쓴다(프론트 `live.ts` 안 건드림).

## Locked decisions

- **D4** — 주기 폴링 축을 없앤다. git 은 이벤트로만 묻는다(캡틴, 2026-09-04, spec §5.1).

## Evidence anchors

- `spec.md` §6 — 지금 트리거 다섯 개의 표와 목표 두 축.
- `core-io/src/watch.ts:79` `contentPaths` — discover 사본만 본다. worktree 는 감시 대상이 아니다.
- `backend/src/server.ts:129` · `:138` — 부팅부터 15초 재검증기를 켜고, listen 직후 풀스윕을 돌린다.
- `backend/src/snapshot.ts:123` — `updateProjectSnapshot` 이 스탬프 확인 없이 전체를 다시 읽는다.

## Regression guards

- 🔴 **worktree 의 untracked 새 티켓이 잡혀야 한다** — 지금 이것이 커밋 전까지 어느 경로로도 안
  잡히는 구멍이다(캡틴 확인 2026-09-04). 이 티켓이 그 구멍을 메운다.
- 🔴 **새 기능 폴더가 잡혀야 한다** — 지금 `sameFeatureFolders` 우회가 하던 일을 축 1 의 `add`
  이벤트가 대신한다. 우회를 지우기 **전에** 이벤트가 실제로 잡는지 확인한다.
- 🔴 **감시 실패가 서버를 죽이지 않는다** — `watch.ts` 의 `onWatchError` 규율을 유지한다(실측 결함 이력).
- 🔴 **감시가 안 붙는 환경에서 화면이 멈추지 않는다** — 안전망 타이머가 그 경우를 덮는다.
- 🔴 worktree 가 생기고 사라질 때 감시기가 따라붙고 떨어져야 한다 — 붙기만 하면 경로 누수다.

## Scope

1. 감시 대상에 worktree 의 `docs/features` 를 더한다(사본 목록 = T04 의 캐시 키와 같은 목록).
2. 이벤트 경로 → 기능 폴더 slug 로 접는 판정을 넣고, 그 폴더만 무효화한다.
3. `scheduleProjectUpdate` 를 폴더 단위로 바꾼다(무조건 프로젝트 풀스캔을 없앤다).
4. 부팅 풀스윕(`setImmediate`)을 감시기 초기 스캔에 흡수한다.
5. `sameFeatureFolders` 우회를 제거한다 — 축 1 이 대신한다.
6. 15초 재검증기를 **감시 실패 시에만** 도는 안전망으로 되돌린다.
   🔴 그 전에 `.git/HEAD`·`refs` 감시를 축 2 에 넣어라 — 위 T06 조사 결과 때문이다.

## Implementation notes

- 🔴 4·5·6 은 **하나씩** 하고 각각 확인해라. 셋을 같이 지우면 무엇이 구멍을 냈는지 못 가린다.
- 사본 목록은 T04 와 같은 자리에서 와야 한다 — 두 곳에서 따로 만들면 어긋난다.
- `.ports.worktree` 처럼 이 저장소가 **읽기만 하는** 파일은 감시 대상이 아니다.

## Acceptance criteria

- AC1 — 기능 폴더 하나의 문서를 고치면 그 폴더만 무효화되고 WS 로 알려진다.
- AC2 — worktree 안에 **커밋 안 된 새 티켓 파일**을 만들면 잡힌다.
- AC3 — 새 기능 폴더를 만들면 잡힌다.
- AC4 — 감시가 붙은 정상 환경에서 주기 타이머가 돌지 않는다.
- AC5 — 감시를 일부러 실패시키면 안전망이 켜지고 화면이 계속 갱신된다.
- AC6 — worktree 를 지우면 그 감시가 떨어진다.

## Verification

`pnpm verify` + 감시 배선 테스트(임시 디렉토리 픽스처). AC2·AC3·AC5 는 실제 dev 서버에서 확인한다.

## Comments

### 2026-09-04 — 완료. 구멍 둘을 막고 15초 주기를 안전망으로 내렸다.

**한 일**

1. **축 1 이 worktree 도 본다.** `contentPaths` 가 `copyPathsOf` = discover 사본 + `extraWorktreeRoots`
   를 쓴다. `projectOf`(경로 → slug 접기)도 같은 목록을 후보로 놓는다.
   🔴 이것이 캡틴이 물었던 구멍이다 — **worktree 안의 커밋 안 된 새 티켓**은 감시도 안 보고
   스탬프 비교도 untracked 를 일부러 빼서, 커밋 전까지 어느 경로로도 안 잡혔다.
2. **축 2 = 커밋 감시** 신설(`gitRefPaths` + `gitW`). 사본마다 `HEAD` 와 `refs/` **두 경로만** 콕
   집어 건다 — `.git` 전체를 거는 것과 다르다(그건 무겁고 소켓을 끌어들여 백엔드를 죽인 전례가 있다).
   worktree 는 `.git` 이 파일이라 그 안의 `gitdir:` 을 따라간다.
3. **15초 재검증기를 안전망으로 강등.** `setFallbackPolling(watchFallbackActive)` — 감시가 붙으면
   안 돈다. 부팅 시 무조건 켜던 줄도 없앴다.

**왜 3번이 안전해졌나**

예전에 항상 켜 둔 이유는 *"커밋은 작업트리 파일을 안 바꾸니 감시 이벤트가 안 떨어진다"* 였고 맞는
말이었다. 이제 **축 2 가 그 구멍을 막는다.** 항상 켜 두면 누가 worktree 에서 작업하는 동안
`sameStamps` 가 매번 거짓이 되어 **15초마다 프로젝트 전체 재계산**이 돌았다 — 이 대시보드가 제일
쓸모 있는 순간에 제일 느려지는 구조였다.

**🔴 Scope 에서 **안 한 것** 둘 — 이유를 남긴다**

- **`sameFeatureFolders` 우회 제거(Scope 5) — 안 했다.** T04 이후 그 검사는 `readdir` 한 번이라
  싸고, 새 폴더에 대한 **두 번째 방어선**이다. 지우면 위험만 늘고 얻는 게 없다.
- **부팅 풀스윕(`setImmediate(snapshotRevalidator.run)`) 흡수(Scope 4) — 안 했다.** 그것은 사라진
  프로젝트를 스냅샷에서 지우는 청소도 겸한다. 감시 초기 스캔이 그 청소까지 대신하지는 않는다.
  🔴 **그래서 "앱 켜고 처음" 의 stall 은 아직 남아 있다** — 콜드 프로세스는 폴더 캐시가 비어
  jinwooauto 기준 ~2.6초를 먹는다. 이것을 **막지 않게** 하는 것은 T07(워커)의 몫이다.

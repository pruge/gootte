## Goal

`readFeatures` 가 부르는 git 하위프로세스 **개수**를 줄인다 — 남은 질의를 캐시하거나
**정말 필요할 때만** 부르도록 조건부로 만든다.

## Why this slice

🔴 **이 티켓이 이 기능의 가장 큰 지렛대다**(spec §3 정정, 캡틴 결정 2026-09-04로 순서를 앞으로 당김).
재측정 결과 `readFeatures` ~4,000ms 의 정체는 **git 하위프로세스 35회 × ~80ms ≈ 2,800ms**(비용의 70%)
이고, 파일 읽기는 299ms 뿐이었다. 그리고 그 80ms 중 **git 이 실제로 하는 일은 없다** — 셸에서
`git --version` 은 12ms 다. 비용이 **호출 개수에 선형**이므로, 개수를 줄이는 것이 유일하게 큰 레버다.

캡틴 질문(spec §5.1)이 그 방법을 정했다: `Time:` 이 티켓의 상태·시각을 이미 git 없이 정하므로,
git 이 남아서 답하는 것은 셋뿐이고 셋 다 **시간이 지나면 변하는 값이 아니다.**

T04·T05 를 기다리지 않는다 — 여기서 줄이는 것은 **한 번의 `readFeatures` 안에서 몇 번 부르는가**라
폴더 단위 캐시(T04)나 감시 축(T05)과 독립이다. 주기 재검증기 제거는 T05 Scope 6 이 갖는다.

- 없어진 주기 스탬프 폴링

## Regression guards

- 🔴 **갈라짐 배지가 지금 뜨는 경우에 그대로 뜬다** — 판정 시점을 옮기는 것이지 약화가 아니다.
  옮기기 전에 지금 어떤 입력에서 뜨는지 픽스처로 고정하고, 옮긴 뒤 같은 픽스처로 확인한다.
- 🔴 **추적 제외된 파일이 계속 트리에서 숨는다** — `design/*.html` 이 다시 나타나면 회귀다.
- 🔴 **`.gitignore` 를 고치면 반영된다** — 캐시했으니 무효화 경로가 있어야 한다.
- 🔴 **git 이 답하지 않는 사본은 표식 없이 그대로 보인다**(`features.test.ts` AC6) — 이 성질을 유지한다.
- 🔴 **커밋만 해도 화면이 갱신되던 성질을 잃지 않는다** — 지금 15초 재검증기의 존재 이유가 그것이다
  (`server.ts:112-116` 주석). 미착지를 버렸으므로 **커밋으로만 바뀌는 화면 값이 아직 남아 있는지
  먼저 세어라.** 남아 있지 않다면 그 이유를 티켓 코멘트에 적고 폴링을 지운다. 남아 있다면 그 값을
  이벤트로 얻을 길(`.git/HEAD`·`refs` 감시)을 함께 넣는다.

## Scope

1. 위 마지막 가드부터 — **커밋으로만 바뀌는 화면 값이 남아 있는지 센다.** 결과를 코멘트에 적는다.
2. `check-ignore` 결과를 사본별로 캐시하고 `.gitignore` 변경 이벤트(축 2)로만 무효화한다.
3. `isRepo` 를 사본 구성 변경 시에만 확인한다.
4. 갈라짐 판정을 "같은 파일의 바이트가 실제로 다를 때" 로 한정한다(지금도 그런지 확인하고, 아니면 그렇게 만든다).
5. 줄인 뒤 **호출 개수를 다시 세어** spec §3 에 적는다.

**한 일 (세 군데)**

1. **`isRepo` 를 경로당 한 번만 묻는다** (`git.ts` `repoCache` + `clearRepoCache()`).
   `headCommit` 이 매번 `isRepo` 를 앞세워 부르는 바람에 `rev-parse --git-dir` 가 사본 수의

2. **파일마다 부르던 `git status` 를 사본당 한 번의 배치로** (`uncommittedPathsUnder`).
   `CopyResolver.uncommitted` 가 그 사본을 **처음 물을 때만** `docs/features` 아래 미커밋 경로를

   아예 안 부른다**. 11회 → 3회.
3. **`revExists` 를 (사본, 커밋)당 한 번만** (`CopyResolver.hasRev`). `isAncestor` 가 두 커밋을
   모두 가진 사본을 찾느라 같은 질문을 반복했다.

**🔴 가드가 실제 회귀를 잡았다 — 기록해 둔다**

`uncommittedPathsUnder` 를 처음엔 `gitSafe` 로 썼는데, **`gitSafe` 는 선두 공백을 지운다.**
porcelain 의 `" M path"`(수정만 되고 staged 안 됨)는 상태 코드 첫 칸이 공백이라, 트림되면

**AC6 — "커밋으로만 바뀌는 화면 값이 남아 있는가" 조사 결과**

`resolveFile` 이 HEAD 조상 관계로 "나중 판" 을 고르므로, 한쪽 사본이 커밋하면 그 결과가 뒤집힐 수 있다.
🔴 **따라서 "미착지를 버렸으니 커밋은 이제 화면과 무관하다" 는 가설은 거짓이다.** T05 가 15초 주기
재검증기를 안전망으로 강등할 때 이 사실을 반드시 반영해야 한다 — 갈라짐이 커밋으로 바뀌는 것을
잡을 길(`.git/HEAD`·`refs` 감시)이 축 2 에 있어야 한다. T05 에 이 조사 결과를 옮겨 적었다.

# T09 — `tsx` 아래에서 git spawn 이 3배가 되는 원인을 밝힌다

**Blocked by:** 없음 — 즉시 착수 가능

**Time:** started=2026-09-04T11:58:11+09:00 finished=2026-09-04T12:00:40+09:00

## Goal

같은 `execFileSync("git", ...)` 가 plain node 에서 25ms, `tsx` 아래에서 80ms 인 이유를 밝히고,
고칠 수 있으면 고친다. 못 고치면 **왜 못 고치는지를 기록**해 다음 사람이 다시 파지 않게 한다.

## Why this slice

dev 서버가 `tsx watch` 로 돈다(`scripts/dev-backend.sh`). 그래서 캡틴이 실제로 겪는 화면은
**항상 3배 비싼 spawn** 위에서 돈다. T06 이 호출 개수를 줄여도 남는 호출마다 이 배수가 곱해진다.
🔴 **이것은 프로덕션 번들에는 없는 문제라 측정에서 놓치기 쉽다** — 캡틴이 쓰는 것은 dev 다.

## Produces

- 3배의 원인을 지목하는 측정 기록
- 고칠 수 있으면 그 변경, 못 고치면 사유와 대안(예: dev 에서도 build 된 backend 를 쓰는 길)

## Consumers

없음 — 결과는 T08 검수의 실측 조건을 바꾼다.

## Touched surfaces

`scripts/dev-backend.sh` · `code/web/backend/package.json` · (원인에 따라) `core-io/src/git.ts`

## Explicitly out of scope

- git 호출 **개수** 줄이기(T06).
- 프로덕션 번들(Tauri) 경로 — 거기서는 이 배수가 없다(실측 25ms).
- `tsx` 를 다른 러너로 갈아치우는 결정 — 원인을 밝힌 뒤 **캡틴이 정한다.**

## Locked decisions

- **캡틴 결정 2026-09-04** — "같이 본다 — 원인을 파고 티켓을 추가한다".

## Evidence anchors

`spec.md` §3 정정 표(2026-09-04 실측):

| 무엇 | 시간 |
|---|---|
| 셸에서 `git --version` ×10 | 12ms/회 |
| plain node `execFileSync("/bin/echo")` | 3ms/회 |
| plain node `execFileSync("git", ["--version"])` | 25ms/회 |
| **`npx tsx` 아래 같은 호출** | **80ms/회** |

`/bin/echo` 가 3ms 인 것이 중요하다 — **Node 의 spawn 자체는 싸다.** 커지는 것은 git 을 띄울 때뿐이고,
`tsx` 가 그것을 다시 3배로 만든다.

## Regression guards

- 🔴 **`tsx watch` 의 자동 재시작을 잃지 않는다** — dev 편의가 사라지면 그건 고친 게 아니다.
- 🔴 **측정은 코드 안에서 한다** — PATH 셸 shim 은 per-call 비용을 부풀린다(T01 에서 겪었다).
- 🔴 원인을 못 찾으면 **찾은 척하지 않는다.** "이러이러한 가설을 이렇게 배제했다" 를 적는다.

## Scope

1. 가설을 세우고 하나씩 배제한다. 후보:
   - `tsx` 의 ESM 로더 훅이 child_process 경로에 끼어드는가
   - `NODE_OPTIONS`/`--import` 가 자식에게 상속돼 **자식마다 로더가 다시 뜨는가**
     (🔴 유력 — git 은 Node 가 아니지만, 상속된 환경변수가 spawn 준비 비용을 늘릴 수 있다)
   - 부모 프로세스의 힙/파일디스크립터 수가 spawn 비용에 미치는 영향
   - macOS 코드서명·보안 검사(git 은 큰 바이너리, `/bin/echo` 는 작다)
2. 원인이 잡히면 고친다.
3. 못 고치면 대안을 적는다 — 예: dev 에서도 backend 는 빌드본으로 돌리고 watch 는 재빌드만 하는 길.
4. 결과를 spec §3 정정 표 아래에 덧붙인다.

## Implementation notes

- 재현 최소 코드는 이미 있다(§Evidence anchors 의 네 줄). 그것을 `tsx` 안팎에서 돌려 비교한다.
- `env -i` 로 환경을 비우고 재보면 환경변수 가설이 빨리 갈린다.

## Acceptance criteria

- AC1 — 3배의 원인이 지목됐거나, 어떤 가설들을 어떻게 배제했는지가 적혀 있다.
- AC2 — 고칠 수 있는 것이면 고쳐졌고, `tsx` 아래 `git --version` 이 plain node 수준(~25ms)에 가깝다.
- AC3 — 못 고치는 것이면 사유와 대안이 적혀 있다.
- AC4 — `pnpm dev` 의 자동 재시작이 그대로 동작한다.
- AC5 — 결과가 spec §3 에 적혔다.

## Verification

## Comments

### 2026-09-04 — 완료. **원인은 `tsx` 가 아니라 `npx` 였다. 그리고 dev 서버에는 그 문제가 없다.**

**가설을 하나씩 배제했다**

| 가설 | 결과 |
|---|---|
| `tsx` 의 ESM 로더 훅이 child_process 에 끼어든다 | ❌ `node --import tsx` = **9.2ms**(plain node 9.3ms 와 같다) |
| `NODE_OPTIONS` 상속 | ❌ `NODE_OPTIONS=` 로 비워도 81.4ms 그대로 |
| Node 의 spawn 자체가 비싸다 | ❌ `/bin/echo` 는 **양쪽 다 1.8ms** — git 만 느려진다 |
| macOS 보안 검사(큰 바이너리) | ❌ 같은 바이너리를 **절대 경로**로 부르면 `npx` 아래에서도 9.5ms |
| **`npx` 가 앞에 붙이는 PATH** | ✅ **원인** |

**결정적 표**

| 하네스 | bare `git --version` | 절대 경로 `/opt/homebrew/bin/git` |
|---|---|---|
| plain node | 9.3ms | 8.9ms |
| `node --import tsx` | 9.2ms | 8.8ms |
| **`pnpm run <script>` (실제 dev 경로)** | **9.7ms** | 9.4ms |
| `npx tsx` | **79.9ms** | 9.5ms |

`npx` 아래에서 PATH 앞에 `node_modules/.bin` 이 **두 번** 붙는다(항목은 5개뿐이고 그 안에 `git` 은 없다).
절대 경로면 안 느려지므로 **bare 이름 해소 경로**의 값이다.

# 01 — 처리중은 지금 붙들려 있는 것에만 붙는다

**What to build:** 끝난 티켓에 처리중 표시가 붙지 않게 하고, "아직 안 올라간 일" 의 기준을
뒤처진 로컬 `main` 이 아니라 remote 로 잡는다. 그래서 **머리글의 수와 줄의 표시가 같은 말을 한다.**

**Blocked by:** 없음 — 지금 착수 가능

**Status:** resolved (2026-08-09)

## 무엇이 잘못돼 있나 (사양 §실측)

원인이 둘이고 층이 다르다. **둘 다 고쳐야 한다** — 하나만으로는 거짓말이 남는다(사양 §원인은 둘이고).

| | 무엇 | 어디 |
|---|---|---|
| **A** | 끝난 티켓에도 붙들린 가지를 실어 두고, 줄이 그걸로 처리중을 그린다 | `core` + `frontend` |
| **B** | "아직 안 올라간 일" 의 기준을 뒤처진 로컬 `main` 으로 잡는다 | `core-io` |

🔴 **A 는 예외 상황이 아니라 완료의 정상 경로다.** 티켓을 끝내는 커밋이 그 티켓 파일의 상태 줄을
같이 고치는 것이 관례이므로(사양 F10), **어떤 티켓이든 그것을 끝낸 가지가 기준선에 들어가기 전까지는
붙들려 있는 것으로 관측된다.**

## 완료 시 시연 가능한 것

캡틴이 대시보드에서 jinwooauto 의 `studio-action-registry` 를 연다.
**`resolved` 라고 적힌 티켓에는 처리중 표시가 하나도 없다.** 지금 실제로 돌고 있는 그 하나에만 붙는다.
🔴 **머리글이 세는 수와 줄에 붙은 표시의 개수가 같다.**

## 완료 조건

### A. 처리중을 정하는 곳을 하나로 (사양 §설계 1)

- **끝나거나 취소된 티켓에는 붙들린 가지를 싣지 않는다.** 상태를 지키는 것만으로는 부족했다 —
  값이 실려 있으면 화면이 그걸로 그린다.
- **줄도 상태를 보고 처리중을 그린다.** 붙들린 가지가 있다는 사실만으로 그리지 않는다.
- 🔴 **두 곳 다 고친다.** 한쪽만 고치면 다른 쪽이 같은 모순을 다시 만들 수 있고,
  **머리글과 줄이 어긋난 것 자체가 이번 결함의 형태**였다.
- 🟢 **끝나지 않은 티켓의 처리중 표시는 지금 그대로다** — 어느 가지가 붙들었는지 이름까지 계속 보인다.
  이 티켓은 **끝난 것에서만** 걷어낸다.

### B. 기준 가지는 remote 를 먼저 본다 (사양 §설계 2)

- 기준 가지 후보를 **remote 를 먼저 보도록** 뒤집는다. "올라갔다" 는 remote 가 정하는 사실이다.
- 🔴 **remote 가 없는 저장소는 로컬로 떨어진다.** 지금 되던 것이 안 되게 만들지 않는다.
- 🔴 **기준 가지를 하나도 못 찾으면 지금처럼 빈 목록이다.** 전체 이력을 훑어 아무 티켓에나
  갖다 붙이지 않는다 — 원래 규율을 잃지 마라.
- 🔴 **관리대상 저장소에 아무것도 쓰지 않는다. fetch 하지 않는다**(INV-2).
  `origin` 이 오래된 경우가 남는 것은 **알고 남기는 구멍**이다(사양 §설계 2).

### 공통

- 🔴 **"못 읽음"·"티켓 미상" 을 조용히 삼키지 않는다.** 원래 티켓의 본체가 그것이었다 —
  이 수리가 그걸 깨뜨리면 화면이 반대 방향으로 거짓말한다.
- `pnpm verify` green.

## 테스트

**이 티켓이 셋 다 처음 덮는다**(사양 §검증 상태). 기존 테스트 *"끝난 일은 다시 처리중이 되지
않는다"* 는 **상태만** 보고 붙들린 가지는 안 봐서 이 결함을 그냥 통과시켰다.
🔴 **그 테스트를 고치지 말고 옆에 하나 더 세워라** — 그 테스트가 지키던 것도 여전히 참이다.

| 상황 | 기대 |
|---|---|
| 🔴 끝난 티켓의 파일을 그 가지의 커밋이 건드렸다 | 처리중이 **안 붙는다.** 붙들린 가지도 비어 있다 |
| 🔴 취소된 티켓도 같다 | 같다 |
| 안 끝난 티켓의 파일을 건드렸다 | 지금처럼 처리중이 붙고 **가지 이름도 그대로 보인다** |
| 🔴 한 기능에 끝난 티켓과 안 끝난 티켓이 섞여 있다 | **머리글이 센 수와 줄에 붙은 표시 개수가 같다** |
| 🔴 로컬 `main` 은 뒤처졌고 `origin/main` 은 최신이다 | `origin/main` 을 기준으로 삼는다. 이미 올라간 커밋이 이 가지의 일로 세어지지 않는다 |
| 🔴 remote 가 없는 저장소 | 로컬 `main` 으로 떨어진다. 빈 목록이 되지 않는다 |
| 기준 가지 후보가 하나도 없다 | 지금처럼 빈 목록. 전체 이력을 훑지 않는다 |
| 사본이 유휴다 | 아무 티켓도 처리중이 아니다 |
| 작업 중인데 티켓 파일을 안 건드렸다 | 지금처럼 **"티켓 미상 · 작업중"** 으로 세어진다 |
| 저장소를 못 읽는다 | 지금처럼 **"못 읽음"** 으로 세어진다 |

🔴 **네 번째 줄이 이 티켓의 안전망이다.** 머리글과 줄을 **같이** 보는 테스트가 없었다는 것이
이번 결함이 빠져나온 틈이고, 그 틈을 막는 것이 그 한 줄이다.

🔴 **마지막 세 줄은 잃지 않기 위한 것이다.** 이 수리는 "덜 보여주는" 방향이라 과하게 걷어내면
원래 티켓이 지키던 것(미상·못 읽음을 감추지 않는다)이 조용히 사라질 수 있다.

## 이 티켓이 하지 않는 것

- **날짜 칸 자리 잡기.** [02](02-date-keeps-its-place.md) 가 한다.
- **관리대상에 fetch 하기.** INV-2 를 깬다.
- **가지 이름으로 티켓 추정하기.** 원래 티켓이 명시적으로 거절한 길이다.
- **머리글 세는 방식 바꾸기.** 머리글은 처음부터 맞았다.
- **줄을 표로 바꾸기.** 사양 §열린 결정 Q1 이 캡틴에게 열려 있다.

## 캡틴 확인

- **어디서** — gootte 대시보드를 띄우고(`pnpm dev`) jinwooauto 의 `studio-action-registry` 를 연다.
- **무엇을** — 머리글의 **처리중 수**를 읽고, 그다음 줄에 붙은 **처리중 표시를 센다.**
- **무엇이 보여야 하나**
  - `resolved` 라고 적힌 티켓에 처리중 표시가 **하나도 없다.**
  - 🔴 **머리글의 수와 줄에 붙은 표시 개수가 같다.**
  - 지금 실제로 돌고 있는 그 일에는 **여전히 붙어 있고, 가지 이름도 그대로 보인다.**

🔴 **표시가 맞는지는 지금 무슨 일이 도는지 아는 사람만 판정할 수 있어 캡틴 눈이 필요하다.**
잘못된 방향으로 과하게 걷어내면 화면이 "아무도 아무것도 안 하는 중" 이라고 반대로 거짓말한다.

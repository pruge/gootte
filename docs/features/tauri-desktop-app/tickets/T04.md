# T04 — 신관례 문서 표시 + 백로그 상태 조인

## Goal
tickets/TNN.md·grill.md·design/·wayfinder.md를 트리에 실재하는 만큼 표시하고, 티켓 상태를 firstmate 백ログ과 조인해 보여준다.

## Why this slice
features/tickets 신관례 지원(D4) 본체. 상태 단일 출처는 백로그(사관장 확정 b안).

## Scope
- core-io: 리더 확장 - tickets/, grill.md, design/, wayfinder.md 노드화(INV-4: 실재하는 파일만); 결정적 파서 유지
- core-io: firstmate 홈 백로그 리더(결정적) - `<parent>-t<NN>` id와 tickets/T<NN> 매핑, 상태 조인
- frontend: 트리 노드 확장 + 드로어 열람(기존 경로 재사용), 티켓 줄에 상태 배지

## Implementation notes
- INV-2: 백로그는 읽기만.
- 조인 실패(미매칭) 시 상태 미표시 - 추측 금지.

## Acceptance criteria
신관례 feature 폴더가 전 항목 표시 + 원문 열람; 상태 조인 표시; 미매칭 안전 렌더; 기존 issues 관례 회귀 없음.

## Verification
vitest(리더·조인) + 수동.

  깨져 있던 결함 — `newTickets`(tickets/ 신관례)를 더한 소비처가 있고 빠뜨린 소비처가 있어서
  두 관례가 화면마다 다르게 취급됐다. 전부 고쳤다:
  1. `features` 탭 카드 머리글(`남은 일`)·정렬·사이드바 `openFeatures` 집계가 `feature.tickets`
     (구관례)만 세고 `newTickets` 를 안 세서, `tickets/` 만 쓰는 기능은 "남은 일 0" 으로 보이고
     `plan` 버튼도 안 뜨고 정렬 맨 뒤로 밀렸다 — `core/src/project/features.ts` 에 `allTickets()`
     를 export 해 `countOpenFeatures`·`sortFeatures`·`FeatureCard` 세 곳에서 합쳐 세도록 고침.
  2. 같은 결함이 `plan` 탭에도 있었다 — `BoardCard`·`CardDialog` 도 `feature.tickets` 만 세서
     신관례만 쓰는 카드가 "티켓 0 · 티켓이 없습니다" 로 보였다. 같은 `allTickets()` 로 고침.
  3. `plan`/`process` 탭에서 티켓 줄을 누르면 문서가 안 열렸다 — `ticketDocPath()` 가
     `issues/<slug>.md` 를 **재조립**하고 있었다(신관례가 생기기 전 코드, 캡틴 결정 2026-08-12
     당시엔 관례가 하나뿐이었다). 서버가 이미 주는 `ticket.path` 를 그대로 쓰도록 고치고
     (`ProcessRow` 에도 `path` 필드를 태워), 이제 쓸모없어진 `ticketDocPath()` 는 지웠다.
  - 회귀 테스트는 core(`features.test.ts`)·frontend(`feature-tree.test.tsx`·`plan.test.tsx`)에
    추가. `pnpm verify` + 커버리지 게이트 green, 데스크톱 앱 실측 확인.
  4. (캡틴 지시로 이어서 닫음) `applyBacklogStatus` 조인이 `/api/features/:slug` 에만 걸려 있고
     `plan`/`process` 탭 라우트(`/api/plan/:slug`, move·step)엔 안 걸려 있어서, 그 탭의 신관례
     티켓은 상태 배지가 항상 "상태 줄 없음" 으로 보였다 — `backend/src/app.ts` 에 `withReadState`·
     `withInProgress` 와 같은 자리에 `withBacklogStatus` 를 추가해 세 라우트(`GET /api/plan/:slug`·
     `/move`·`/step`) 모두에 태웠다(`withInProgress` 뒤, `readBoard` 앞 — `/api/features/:slug` 와
     같은 상대 순서). 회귀 테스트는 `backend/test/app.test.ts`("GET /api/plan/:slug 도 같은 백로그

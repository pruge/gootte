# 0001 — 메모를 중앙(`~/.gootte/memos/`)이 아니라 `<프로젝트>/.gootte/memo.json` 에 산다

**Status:** accepted (2026-09-14, 캡틴 승인)

## 맥락

`memo-pad` 이후 메모는 gootte 자기 저장소의 중앙 파일
(`GOOTTE_DATA_DIR/memos/<slug>.json`, 기본 `~/.gootte/memos/`) 에 살았다. `memos-read-from-any-session`
(T01) 으로 어떤 세션에서든 `gootte memo` 로 읽을 수 있게 됐지만, **저장소는 여전히 중앙**이었다.

캡틴 지적(2026-09-14, 원문):

> 각 프로젝트는 github 에서 관리되는데 메모만 중앙관리되어서야. 다른 곳에서는 메모를 볼 수가 없다.
> 메모는 `.gootte` 밑에 개별적으로 `memo.json` 으로 존재해야. 그래야 다른 곳에서도 경험을 유지하지.

문제는 두 개였다.

1. **경험이 저장소를 안 이동한다.** 클론·다른 기계의 세션은 같은 생각을 못 본다. 프로젝트는
   git 으로 이동하는데 메모만 중앙에 남는다.
2. **원장이 남의 것과 한 곳에 섞여 있다.** `~/.gootte` 는 이미 사고가 난 자리다 — 작업 사본 하나가
   무격리로 `db migrate` 를 돌려 같은 집의 `plan.db` 단계 18행이 날아갔다(2026-08-14 실사례,
   `grill.md` Facts). `memos/` 는 그 다음 차례였다.

## 결정

- **한 자리**: `<메인 프로젝트>/.gootte/memo.json`. 내용은 지금까지와 같은 `Memo[]` 배열 하나
  (래퍼 객체 없음). `Memo`·`MemosResponse` contract 는 그대로 — `id` 규약(`<epochMs>-<counter>`) 이
  원래 프로젝트 단위라 파일이 옮겨도 충돌하지 않는다. 응답의 `project` 값은 **slug 유지**(경로를
  화면에 흘리지 않는다).
- **메인 사본 규칙**: 시간 기록과 같은 판 — cwd 가 worktree 면(`.git` 이 파일) 메인으로 승격,
  `.git` 이 디렉토리면 자기 자신. 화면(백엔드)은 discover 대표 경로를 쓰고, CLI 읽기는
  `.gootte/config.json` 을 **판독**한다(`mainRootOf`).
- **폴백 없음**: 전환 뒤에도 central 을 읽지 않는다. 그래서 **순서가 강제**된다 — 이관
  (`gootte memo migrate`, T01) → 읽기 전환(T02). 읽기를 먼저 돌리면 미이관 프로젝트의 메모가
  화면에서 사라진 것처럼 보인다.
- **읽기는 아무것도 만들지 않는다**: `.gootte/` 는 쓰는 쪽(`writeMemoFile`)만 만든다. 빈 목록을
  읽는 실행(화면 GET, `gootte memo`) 이 격리 사본에 디렉토리를 떨구면 안 된다.
- **이관은 원본 유지가 기본**: `migrate` 는 읽고 쓴다. 지우는 일(`--purge`) 은 명시할 때만 —
  되돌릴 수 없는 쪽은 사람의 손으로 남긴다.

## 왜 이것이 INV-2 예외의 **새 예외가 아니라 같은 예외의 확장**인가

INV-2("관리대상은 읽기 전용")가 지키는 것은 **관리대상의 SoT 문서** — `docs/features/` 의
spec·티켓·adr 이다. 이 결정은 그 파일들에 한 글자도 쓰지 않는다.

쓰는 자리는 `<프로젝트>/.gootte/` — 이미 gootte 자기 산출물의 네임스페이스다. 시간·상태 기록이
같은 자리에 사는 예외는 캡틴 승인으로 존재했다(2026-09-09, `time-records-to-state-store`):
`gootte start/end` 가 적는 시각은 write-time 캡처라 원본을 지운 뒤 재생성할 수 없는 INV-5 값이다.

메모는 그보다 더 직접적으로 INV-5 의 저장 대상이다 — **어디 문서에도 적혀 있지 않고 사람만 아는
값**이고, 다른 어디를 다시 읽어도 돌아오지 않는다. 판단 기준 한 줄("다른 어디에도 없는 것만
저장할 자격이 있다")은 그대로고, 이 표에서 바뀐 것은 **저장의 자격이 아니라 좌표**다.

그래서 `AGENTS.md` 불변식 칸(INV-2·INV-5)에 한 줄을 더하고 이 ADR 을 남긴다 — 예외의 확장을
조용히 넘기지 않는다.

## 대안과 기각

- **중앙 유지 + 클론에 복사**: 두 사본이 생기면 어느 쪽이 최신인지 판정할 근거가 없다 — that은
  desync 를 위한 장치를 짓는 것이고, 그건 INV-1 의 금지선이다. 기각.
- **저장소 추적 파일로 강제**: gootte 가 **남의 저장소의
  `.gitignore` 를 고치지 않는다**(INV-2 의 본래 금지선). `jinwooauto` 는 이미 `.gootte/` 를 무시로
  걸어뒀고, 추적 예외 한 줄은 그 프로젝트의 표로 남긴다. 이 기능은 그 파일이 추적되든 안 되든
  자기 동작만 옳게 한다.
- **central 을 폴백으로 남기기**: 이관 전 프로젝트를 이관된 척 그리는 거짓이자 이중 원장. 기각.
- **`plan.db`·`settings.json` 을 같이 이사**: 같은 병이지만 이 표가 이관 절차를 먼저 세워야 한다.
  다음 표의 일로 남긴다.

## 파급

- `core-io/memo-store.ts` 의 좌표가 `(dataDir, slug)` → `(projectDir)` 가 되었다. 두 자리를
  동시에 받는 타협은 하지 않았다 — 인자 둘 다 받는 서명은 이중 원장을 코드에 박는 것이다.
- central 좌표는 `centralMemosFile` 로 **이름을 바꿔** 남는다. `memo migrate` 가 옮길 원본을
  가리키는 주소지일 뿐, 읽고 쓰는 자리가 아니다. 이름이 그 사실을 말한다.
- 백엔드 `/api/memos/:slug` 의 응답 규약이 같으므로 **프론트는 무변경**이다.
- `gootte memo` 의 출력 서식(헤더 `== <slug> · 메모 없음 ==`·4칸 들여쓰기·필터 어휘) 은
  변하지 않는다 — 읽은 자리가 바뀌었을 뿐이다.
- **읽기가 파일을 만들지 않는다**는 규칙은 실측 가능하다: 미이관 프로젝트에서 0건을 읽은 뒤
  `.gootte/` 가 없어야 한다(cli·backend 테스트가 각각 잰다).
- 이 표가 머지되기 전에 대상 프로젝트에 T01 의 이관이 실행돼 있어야 한다(순서 강제).
  안 하면 jinwooauto 의 23건이 화면에서 사라진 것처럼 보인다.

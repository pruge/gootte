# T03 — 종단 확인: 두 원장이 하나가 됐는가 (캡틴 확인으로 닫는다)

**Blocked by:** T02

## Goal

이관(T01 명령 + T02 배치 전 실실행) 과 읽기 전환(T02) 이 끝난 자리에서, **central 없이도** 화면·CLI·
git 세 방향이 같은 23건을 같은 내용으로 보는지 확인해 기능을 닫는다.

## Why this slice

이관이 "만든 명령" 으로 끝나면 central 원장은 그대로 남고, T02 가 읽기를 돌린 순간 사용자는 메모가
사라진 것을 본다. 표가 두 갈래인 기능은 **실제로 옮기는 손**이 마지막에 필요하다.

## Produces

- 이 표의 `## Comments` — hash 대조 결과와 남은 후속(jinwooauto `.gitignore` 추적 예외, central `--purge` 결정).

## Consumers

- 없음(종단 확인).

## Touched surfaces

- jinwooauto 저장소의 `.gootte/memo.json` 하나(gootte 제품 명령이 쓴다 — 코드 편집 아님).

## Explicitly out of scope

- jinwooauto `.gitignore` 수정(그 저장소의 표로 남긴다 — INV-2).
- `--purge` 로 central 삭제(캡틴이 확인 후 따로 결정 — 되돌릴 수 없는 일).

## Locked decisions

1. **순서**: T01 머지 → main 에서 `gootte memo migrate jinwooauto` 실행 → T02 배치·머지 → 이 표 확인.
   (실이관을 T02 뒤에 하면 그 사이에 화면이 0건으로 보인다 — T02 §Verification 이 같은 규칙을 잠근다.)
2. 실행 전후central·대상 파일의 **hash 를 적어** 두고, 옮긴 뒤 central 은 손대지 않은 채로 남긴다.
3. `plan.db` 와는 다르게, 메모는 읽기 전용 실행이 원장을 고치지 않는다(읽기가 파일을 안 건드림) — 확인
   항목에 넣는다.

## Evidence anchors

- T01/T02 가 머지된 main 커밋
- `~/.gootte/memos/jinwooauto.json` 23건(완료 8 · 다중 줄 2)

## Regression guards

- 이관 후 `gootte memo`(jinwooauto cwd) 23건 · `--undone` 15건 · 다중 줄 항목이 한 항목으로 붙음.
- 화면 `memo` 탭과 CLI 가 같은 내용을 보이는가(단일 원장 확인 — INV-1).
- central 파일이 그대로 있는가(기본 보존이 지켜졌나).

## Scope

실행 + 확인. 코드 변경 없음.

## Acceptance criteria

- AC1 jinwooauto 프로젝트 파일에 23건, 원본 23건과 내용 동일(hash 대조).
- AC2 CLI·화면이 같은 목록을 보인다.
- AC3 central 은 그대로 남아 있다(삭제 안 함).
- AC4 캡틴이 출력과 화면을 보고 승인한다.

## Verification

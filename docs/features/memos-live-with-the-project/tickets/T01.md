# T01 — `gootte memo migrate` — 중앙 메모를 프로젝트 파일로 옮긴다 (읽기는 아직 중앙)

**Blocked by:** 없음 — 즉시 착수 가능

## Goal

`gootte memo migrate [slug] [--purge]` 를 신설한다. `~/.gootte/memos/<slug>.json` 을 읽어
`<메인 프로젝트>/.gootte/memo.json` 에 쓴다. **이 표에서 읽기 경로는 바꾸지 않는다**(폴백 금지의
순서 — spec §설계 결정).

## Why this slice

읽기를 먼저 돌리면 이관되지 않은 프로젝트의 메모가 화면에서 사라진 것처럼 보인다(실데이터 23건).
그래서 **쓰는 자리를 만들고 → 이관하고 → 읽기를 돌린다** 세 박자로 간다. 이 표는 첫 박스 하나다.

## Produces

- `code/web/core-io/src/memo-migrate.ts` — 순수 판정: `planMemoMigration({centralFile, projectFile})`
  → `write | skip-동일 | error-충돌`. 파일 존재/내용 비교만 한다.
- `code/web/core-io/src/memo-store.ts` — `projectMemosFile(projectDir)`(`<dir>/.gootte/memo.json`) 추가.
  기존 `(dataDir, slug)` 면은 이 표에서 **그대로** 둔다(읽기 전환은 T02).
- `code/web/cli/src/commands.ts` — `memoMigrateText(argv, dataDir, cwd)`.
- `code/web/cli/src/main.ts` — `case "memo"` 안에서 `migrate` 하위 처리 + `usage()` 한 줄.
- 테스트: `memo-migrate.test.ts`(임시 fixture), `cli.test.ts` 배선, `gootte-wrapper.test.sh` 인자 통과.

## Consumers

- T02(읽기를 새 자리로 돌릴 때 이미 프로젝트 파일이 존재해야 한다) · 캡틴(실이관 실행).

## Touched surfaces

`core-io` 2 · `cli` 2 · `scripts/tests` 1. 백엔드·화면·contract 미변경.

## Explicitly out of scope

- 읽기/쓰기 경로 전환(T02) · central 파일 삭제의 자동화(`--purge` 로만) · 다른 프로젝트 `.gitignore`.

## Locked decisions

1. 대상 slug 는 **cwd 유추 우선**(`slugFromCwd`), 명시 인자 허용(`migrate jinwooauto`) — `memo` 읽기와
   같은 규약 단, 이 명령은slug 인자를 **받는다**(여러 프로젝트를 한 번에 돌릴 수 있어야 한다).
2. 프로젝트 해소는 discover 의 **메인 사본**(`requireProject(...).path`). worktree 경로를 쓰지 않는다.
3. 대상 파일이 이미 있으면: 내용 동일 → `skip`, 다름 → **오류로 멈춘다**(central 쪽으로 덮어쓰지 않는다).
   같은 명령을 두 번 돌려도 안전(멱등).
4. `--purge` 가 없을 때 central 은 **그대로 남는다**. 출력에 그 사실을 쓴다(`원본 유지: <path>`).
5. `--purge` 는 대상 쓰기 성공 **뒤에** 지운다(지우고 실패하면 데이터를 잃는다). 그리고 삭제한 경로를
   출력에 남긴다.
6. 출력은 기존 CLI 규약(한 줄 한 항목, TAB 구분, 없으면 `(이관 대상 없음)`).

## Regression guards

- 재실행 멱등(두 번째 `migrate` 는 skip, 파일content 불변).
- 대상에 다른 내용이 있을 때 **덮지 않고** 오류.
- `--purge` 없이 central 이 살아있는가(기본이 보존).
- 메인 아닌 worktree 경로에서 돌면 **메인에** 쓰는가(사본마다 메모 파일이 따로 생기면 안 된다).

## Scope

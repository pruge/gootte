# T02 — 읽기·쓰기를 `<프로젝트>/.gootte/memo.json` 으로 전환 (폴백 없음)

**Blocked by:** T01

## Goal

메모의 유일한 원장을 프로젝트 파일로 바꾼다. 화면·백엔드·CLI 가 전부 새 자리를 읽고 쓰고,
**central 은 더 이상 읽지 않는다**. `AGENTS.md` 불변식 칸과 ADR 에 예외 계보를 남긴다.

## Why this slice

T01 이 쓰는 자리를 만들고 이관 절차를 세웠으니, 이제 읽기를 돌려야 이중 원장이 사라진다(INV-1·INV-3).
읽기를 돌리는 순간 미이관 프로젝트는 0건으로 보여야 옳다 — central 을 몰래 읽는 폴백은 "이관 안 된
것을 이관된 척" 그리는 거짓이라 두지 않는다(grill Locked 5).

## Produces

- `code/web/core-io/src/memo-store.ts` — `(dataDir, slug)` → `(projectDir)` 서명 전환,
  `memosFile(projectDir) = <dir>/.gootte/memo.json` 단일화.
- `code/web/backend/src/routes/memo.ts` · `app.ts`(deps) — slug → **메인 프로젝트 경로** 해소 결과를
  스토어에 넘긴다(지금 `dataDir` 를 넘기는 자리).
- `code/web/cli/src/commands.ts` — `memoText` 가 프로젝트 파일에서 읽는다(`memo migrate` 는 T01 그대로).
- `code/web/frontend` — API 응답 규약이 같으므로 **변경 없음**(변경이 생기면 이 표에서 같이 끝낸다).
- `AGENTS.md` — 불변식 INV-2/INV-5 칸에 `.gootte/memo.json` 한 줄(시간 기록과 같은 계보).
- `docs/features/memos-live-with-the-project/adr/0001-memos-live-in-the-project.md` — 왜 이 자리인가.
- 테스트 전환: `memo-store.test.ts` · backend `app.test.ts` 메모 부분 · `cli.test.ts` · `memo-select` 는 무변경.

## Consumers

- 화면 `memo` 탭 · `gootte memo` · 각 프로젝트의 클론(git 으로 이동).

## Touched surfaces

`core-io` · `backend` · `cli` · `AGENTS.md` · `adr/` · 테스트. contract 무변경(스키마 그대로).

## Explicitly out of scope

- `plan.db`·`settings.json` 의 같은 이사(다음 표).
- 다른 프로젝트 `.gitignore` 에 추적 예외를 넣는 일(그 프로젝트의 표).
- central 파일 삭제(`memo migrate --purge` 의 몫 — 이 표는 읽지 않을 뿐, 지우지 않는다).

## Locked decisions

1. 스토어 서명은 `(projectDir)` 하나만 남기고 **두 자리 지원 금지**(인자 둘 다 받는 식의 타협은
   이중 원장을 코드에 박는 것이다).
2. 메인 사본 해석은 T01 과 같은 함수(`requireProject(...).path`) — 화면(백엔드) 과 CLI 가 같은 판을 쓴다.
3. `.gootte/` 디렉토리가 없는 프로젝트에 쓰기는 `mkdir -p` 로 만든다. 단 **빈 메모 목록을 이유로 파일을
   만들지는 않는다**(읽기 전용 실행이 사본을 더럽히면 안 된다 — 실측 가능한 구분).
4. 파일이 없으면 0건(`메모 없음`), JSON 고장은 원인 + exit 1 / 백엔드 500 — 지금 분기를 그대로 옮긴다.
5. contract 타입(`Memo`·`MemosResponse`) 은 손대지 않는다. `project` 필드 값은 slug 유지(경로 아님 —
   화면이 경로를 알 필요 없다).

## Regression guards

- 읽기가 central 을 **안 읽는지**: central 에만 데이터가 있는 상태에서 화면·CLI 가 0건이어야 한다
  (이걸 거꾸로 하면 폴백이 몰래 살아있다는 증거다).
- 빈 목록 읽기가 `.gootte/` 를 만들지 않는지(Locked 3).
- worktree 의 cwd 에서 읽어도 같은 사본(메인) 답이 나오는지.
- 백엔드 라우트가 프로젝트를 못 찾을 때 404 를 유지하는지.

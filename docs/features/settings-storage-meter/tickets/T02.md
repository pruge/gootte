# T02 — 설정 화면에 사용량 + 비우기 (프론트)

**Blocked by:** T01 — 엔드포인트가 있어야 붙는다

## Goal

설정에 "저장소 사용량" 한 줄과 "비우기" 버튼을 붙인다(S1·S2·S3).

## Why this slice

T01 계약 위에 화면만 얹는 슬라이스다.

## Produces

- 사용량 표시 + 비우기 후 새로고침되는 설정 행.

## Consumers

- 설정 화면 사용자(캡틴).
- `SettingsView` 기존 테스트(있으면 회귀 확인).

## Touched surfaces

- `code/web/frontend/src/components/settings/SettingsView.tsx` (또는 그 일행).
- 바이트 표기 util(작으면 같은 파일, 크면 `lib/`).
- 프론트 테스트 1개(표기·배선).

## Explicitly out of scope

- 항목별 내역. WAL 문구 이상의 네이티브 동작.

## Locked decisions

- D3(INV-3 — 비운 뒤 새로고침으로 신선한 화면).
- D6(앱 내 범위) — 버튼 아래에 "WAL 잔량은 앱 종료 시 정리됩니다" 한 줄을 밝힌다.
- 비우기 순서: `POST /api/storage/clear` → `localStorage.clear()` → `qc.clear()` → `location.reload()`.
  서버 캐시를 먼저 비워야 새로고침 직후 재계산이 깨끗하다.

## Evidence anchors

- T01 `StorageResponse`·두 엔드포인트.
- `useSettings` 옆에 둘 `useStorage` 훅 자리(`lib/query.ts`).

## Regression guards

- 설정 화면 기존 테스트.
- 신규: 바이트 표기 단위 테스트 + 비우기 호출 순서 테스트(가능한 범위에서).

## Scope

- 설정 행 1개 + 훅 + 테스트. 백엔드·contract 금지(T01 완료 전제).

## Implementation notes

- `totalBytes: null` 이면 "확인 불가"로 표시하고 버튼은 비활성화하지 않는다(비우기는 플랫폼 무관하게 동작).
- 실패(localStorage·API 오류)는 toast 로 알리고 화면을 깨지 않는다.

## Acceptance criteria

- 총량이 보이고(A1), 비우기 후 수치가 내려가며(A3) 화면이 정상이다(A2).
- `pnpm verify` green.

## Verification

- 신규 테스트 + `pnpm verify` + 실운행 확인(캡틴).

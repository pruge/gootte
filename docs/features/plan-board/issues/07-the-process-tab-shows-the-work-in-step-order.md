# 07 — process 탭이 할 일을 단계 순서로 보여 준다

**What to build:** 헤더에 세 번째 탭 **`process`** 가 생긴다. 누르면 작업 대상에 올라온 티켓들이
**단계 순서로 줄 서서** 보인다 — `1단계`, `2단계`, `3단계`… 그리고 맨 뒤에 `9999`.
같은 단계 안에서는 **기능별로 다발** 지어 보인다(2026-08-12 캡틴 지시로 뒤집힘 — 아래
"캡틴 결정" 두 번째 항목).
읽기 전용이다 — 티켓을 누르면 그 문서로 갈 뿐, 아무것도 바꾸지 않는다.

**Blocked by:** 05 — 단계와 당김 계산이 먼저 있어야 줄 세울 것이 생긴다. **05 는 작업이 끝나 올라가 있다**

**Status:** claimed

## 캡틴 결정 (verbatim, 2026-08-12)

> “헤더에 feature | plan 이 있는데 여기에 process를 추가하고 화면은 process클릭했을때 보이게해.”

무엇을 보여 줄지는 캡틴 창에서 직접 여쭤 닫았다 — **단계별 작업 순서**, **읽기 전용**(2026-08-12).

## 캡틴 결정 ② — 같은 단계 안은 기능별 다발로 (verbatim, 2026-08-12)

구현을 캡틴이 직접 보며 검토하던 중 오간 대화:

> "1 단계내에 순서는 의미를 따로 두나?"

답은 아니오였다 — `step` 테이블에는 우선순위 칸이 없고, `next` 의 정렬(`seq` 다음 티켓 번호)도
어긋남을 막는 결정적 tie-break일 뿐 우선순위가 아니다(spec §next). 그 답을 들은 뒤:

> "없다면 feature 단위로 그룹을 만들어 표시하자. feature의 이름을 회색 헤더로 두고 그 밑에
> ticket을 두자."
>
> "중간 feature 들 간에 gap을 주자."

이로써 **최초 요구("기능으로 묶지 않는다", 위 What to build 원문과 아래 여러 절의 🔴 표시)가
뒤집혔다.** 판정 자리는 바뀌지 않는다 — `groupProcessSteps`(core)는 여전히 **단계**로만 묶고,
기능별 다발은 그 위에 얹는 화면 서식(`clusterByFeature`, frontend)일 뿐이다. 같은 단계 안
정렬에 의미가 없으므로 어느 쪽으로 보여줘도 판정과는 무관하다.

🔴 아래 절들(`만드는 것`의 예시·"묶음은 단계가 하고 이름은 줄이 한다", 인수 기준 3번째 줄,
테스트 절의 "기능으로 묶이지 않음")은 **이 결정 이전 버전**이다 — 문구를 남겨 결정의 앞뒤를
보이되, 실제 동작은 이 캡틴 결정 ②를 따른다.

## 왜 plan 탭이 아니라 새 탭인가

`plan` 은 **기능 카드**를 다섯 칸에 손으로 옮기는 자리다. 묻는 것이 "무엇을 붙들고 갈까" 다.
`process` 는 **티켓**을 단계로 줄 세워 읽는 자리다. 묻는 것이 "다음에 무엇을 할까" 다.
낱알의 크기가 다르고, 하나는 손으로 바꾸는 자리이고 하나는 읽는 자리다.

🔴 **05 가 만든 것과 겹치지 않는다.** 05 는 카드 하나를 열었을 때 **그 기능의 티켓**을 단계 순으로
세운다 — "이 기능 안에서 무엇이 먼저인가". 이 탭은 **모든 기능의 티켓**을 단계로 모은다 —
"지금 1단계인 것이 통틀어 무엇인가". 같은 값을 다르게 묶는 것이지, 같은 화면을 두 번 그리는 것이 아니다.

🔴 **단계 숫자를 다시 계산하지 않는다.** 05 가 판정 자리 하나(`computeDisplaySteps`)를 세웠고
서버가 이미 계산해서 실어 보낸다. 이 화면은 **받아서 단계별로 모으기만** 한다.
다시 계산하는 순간 판정 자리가 둘이 되고, 언젠가 둘이 어긋난다.

## 만드는 것

**탭 하나** — 헤더의 `feature | plan` 옆에 `process`. 탭은 주소에 실려 있으므로
`process` 도 제 주소를 갖는다 — 새로 고쳐도 그 탭이 열려 있고, 링크로 건네줄 수 있다.

**단계 묶음** — 표시 기준 단계마다 제목 하나와 그 밑의 티켓 줄들.

```
process
──────────────────────────────────────
1단계
  [ ] 실패-재시도-한곳에 / 01 한곳으로 모은다
  [ ] 실패-재시도-한곳에 / 04 죽은 이름을 지운다
  [ ] 문서가-실재만-가리킨다 / 01 검사기를 세운다

2단계
  [ ] 실패-재시도-한곳에 / 02 기다림을 넓힌다

9999 — 아직 순서를 안 정했다
  [ ] 계획-판 / 06 완료 시각을 분까지 읽는다
```

줄마다 **어느 기능의 몇 번 티켓인지**와 제목이 보인다. 기능으로 묶지 않되,
어느 기능 것인지 모르게 두지도 않는다 — 묶음은 단계가 하고 이름은 줄이 한다.

**당김은 이미 계산되어 온다** — 빈 단계를 걷어내고 1부터 세는 것은 05 가 만든 함수의 몫이고,
서버가 그 결과를 카드마다 실어 보낸다. 이 화면이 하는 일은 **그 값을 단계별로 다시 묶는 것**뿐이다.
🔴 `9999` 는 당겨지지 않고 맨 뒤에 그대로 선다(05, INV-B2).

🔴 **단계가 없는 티켓은 나오지 않는다.** 작업 대상 밖의 카드도, 빈 단계로 당겨져 사라진 티켓도
이 표에 값이 없다. 값이 없는 것을 억지로 어느 단계에 끼워 넣지 않는다.

**읽기 전용** — 티켓 줄을 누르면 그 티켓 문서가 열린다. 03 이 카드 머리에서 문서로 가는 길을
이미 냈으니 **그 통로를 그대로 쓴다** — 두 번째 문서 보기를 짓지 않는다.
🔴 끌어 옮기기 없다. 단계를 바꾸는 길은 firstmate 의 명령뿐이다(05).

**상자 표시** — 티켓 줄의 `[ ]` / `[x]` 는 04 가 만든 것과 같은 판정을 쓴다. 새로 만들지 않는다.

**빌 때** — 작업 대상에 아무것도 없으면 `작업 대상에 올라온 것이 없다` 한 줄.
🔴 빈 화면을 그냥 두지 않는다 — 고장과 구별이 안 된다.

## 완료됐을 때 보여줄 수 있는 것

캡틴이 헤더의 `process` 를 누른다. 지금 붙들고 가는 티켓들이 **1단계부터 차례로** 보이고,
서로 다른 기능의 티켓이 같은 단계에 나란히 서 있다. 1단계 티켓이 전부 완료되면
**새로 고치지 않아도** 2단계였던 것이 1단계 자리로 올라온다.
어느 줄을 눌러도 그 티켓 문서가 열린다.

## 인수 기준

- [ ] 헤더에 `feature | plan | process` 세 탭이 있고, `process` 를 누르면 그 화면이 보인다.
- [ ] 새로 고쳐도 `process` 가 열려 있다 — 탭이 주소에 실린다.
- [ ] 티켓이 단계별로 묶여 보이고, **기능으로는 묶이지 않는다.**
- [ ] 줄마다 어느 기능의 몇 번 티켓인지와 제목이 보인다.
- [ ] 표시 단계가 1부터 연속이다 — 빈 단계가 걷혀 있다.
- [ ] `9999` 는 당겨지지 않고 맨 뒤에 제 제목을 달고 선다.
- [ ] 작업 대상 밖(대기·예약·폐기·완료)의 티켓은 **하나도 나오지 않는다.**
- [ ] 문서에서 티켓을 완료로 바꾸면 새로 고침 없이 상자가 채워지고, 단계가 비면 뒤가 당겨진다.
- [ ] 티켓 줄을 누르면 그 티켓 문서가 열린다.
- [ ] 끌어 옮기기가 **없다** — 이 화면에서는 아무것도 바뀌지 않는다.
- [ ] 작업 대상이 비면 `작업 대상에 올라온 것이 없다` 가 보인다.
- [ ] 이 화면의 1단계 집합이 `gootte next` 의 결과와 **같다.**

## 테스트

- 줄 세우기·당김·9999 자리는 05 가 세운 `core` 순수 함수 테스트가 이미 덮는다.
  🔴 **이 티켓은 그 계산을 다시 테스트하지 않는다** — 다시 테스트해야 한다면 계산이 둘로 갈라진 것이다.
- 단계별로 모으는 것 자체는 순수 함수 하나로 떼어 `core` 에서 덮는다 — 🔴 이 티켓이 처음 덮는다.
  최소 골격: 여러 기능이 한 단계에 섞인 경우, 빈 단계가 없는 경우, 9999 만 있는 경우,
  단계가 하나도 없는 경우.
- 화면은 `frontend` 테스트: 탭 전환, 단계 묶음, 기능으로 묶이지 않음, 빈 화면 문구,
  티켓 클릭이 문서로 가는 것, 실시간 갱신.
- 🔴 화면의 1단계와 `next` 의 결과가 같다는 것을 테스트가 실제로 확인한다(05 의 같은 기준을 이어받는다).

## 이 티켓이 하지 않는 것

- 단계를 매기거나 바꾸지 않는다 — 05 의 명령이 한다.
- 단계 계산을 다시 만들지 않는다 — 서버가 실어 보낸 값을 받아 쓴다.
- `plan` 탭의 칸·카드·끌어 옮기기·카드 대화상자를 고치지 않는다. 05 가 만든 카드 안 단계 순서도 그대로 둔다.
- 진행 상황(누가 붙들고 있나, 얼마나 걸렸나)을 보여주지 않는다 — 이 화면은 **순서**를 말한다.
- 티켓 문서를 고치지 않는다.

## 캡틴 확인

- **열 곳** — gootte 헤더의 `process` 탭.
- **할 일** — 작업 대상에 기능 두어 개가 올라가 단계가 매겨진 상태에서 탭을 열어 본다.
  1단계 티켓 하나를 문서에서 완료로 바꿔 본다. 아무 줄이나 눌러 본다.
- **보여야 할 것** — 다음에 할 일이 한눈에 잡히는가. 기능이 섞여 있어도 어느 것인지 알아보겠는가.
  9999 무더기가 멀쩡한 마지막 단계처럼 보이지 않는가.

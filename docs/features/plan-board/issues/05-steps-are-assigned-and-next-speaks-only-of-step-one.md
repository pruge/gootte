# 05 — 단계를 매기고, `next` 는 1단계만 말한다

**What to build:** firstmate 가 티켓마다 단계 숫자를 매긴다. 작업 대상 칸이 그 단계대로 티켓을
줄 세우고, **빈 단계가 생기면 저절로 당겨진다.** `gootte next` 는 작업 대상에 올라온 것 중
**1단계만** 말한다.

**Blocked by:** 03 — 작업 대상에 카드가 올라가야 단계를 매길 것이 생긴다

**Status:** resolved (2026-08-12 20:36)

## 만드는 것

**명령 셋** — 01 이 옛 명령을 걷어낸 자리에 세운다(spec §명령).

| 명령 | 무엇 |
|---|---|
| `step <프로젝트> <기능>/<티켓> <N>` | 단계를 매긴다 |
| `step --clear <프로젝트> <기능>/<티켓>` | 단계를 뗀다 |
| `board <프로젝트>` | 다섯 칸 현황을 읽는다 — **읽기 전용.** 🔴 이 티켓이 소유한다 |

`next <프로젝트>` 는 이름이 남고 규칙이 바뀐다.

🔴 **`--why` 를 받지 않는다.** 단계의 이유는 문서에도 DB 에도 남기지 않는다(캡틴 결정).
🔴 **자리를 옮기는 명령을 만들지 않는다**(spec §자리를 옮기는 명령은 두지 않는다).
`board` 로 읽을 수는 있어도 `area`·`seq` 를 CLI 로 바꿀 수는 없다.

단계는 연속이며 상한은 없다(캡틴 결정: "단계는 연속").

**당김은 표시 계산이다** — 🔴 **저장한 숫자는 아무도 고치지 않는다.**
화면에 그릴 때 비어 있는 단계를 걷어내며 1부터 다시 센다.
🔴 **9999 는 당기지 않는다** — 9999 그대로 맨 뒤에 둔다(spec §올라온 카드는 9999 단계로 붙는다).
당기면 아직 순서를 안 정한 무더기가 멀쩡한 마지막 단계처럼 보인다.
그래서 "1단계가 비워지면 1,2,3,4 가 된다"가 아무도 손대지 않아도 성립한다(INV-B2).

빈 단계가 생기는 길은 둘이다 — 그 단계의 티켓이 전부 완료됐거나, 그 기능이 작업 대상에서 내려갔거나.
앞의 것은 저장을 건드리지 않는다. 뒤의 것은 03 이 그 기능의 단계 행을 지운다 —
단계는 작업 대상에 있는 동안만 존재한다(spec §단계는 잠시 붙었다 사라지는 것이다).

**`next`** — 작업 대상에 있는 기능의, 표시 기준 1단계 티켓만.
정렬은 카드 순서(`seq`) 다음 티켓 번호. 🔴 트랙 묶음 없다. 어긋남 없다(INV-B3).

화면과 명령이 **같은 함수**를 쓴다. 둘이 각자 판정하면 그 순간부터 하나는 거짓이다.

## 완료됐을 때 보여줄 수 있는 것

firstmate 가 작업 대상의 티켓들에 단계를 매긴다. 캡틴이 `plan` 탭에서 1·2·3단계로 줄 선 것을 본다.
1단계 티켓이 전부 완료되면 2단계가 **1단계 자리로 올라온다.**
`gootte next` 를 치면 방금 1단계가 된 그 티켓들이 나온다.

- 단계에 이유를 붙이지 않는다.

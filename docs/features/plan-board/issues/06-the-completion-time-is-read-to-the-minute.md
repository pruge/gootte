# 06 — 완료 시각을 분까지 읽는다

**What to build:** 티켓 문서의 `Status: resolved` 뒤에 이제 **시각까지** 적힌다
(`resolved (2026-08-12 14:30)`, 전달받은 캡틴 결정 2026-08-12). 읽는 쪽은 날짜만 집어내고 시각을 버린다.
분까지 읽는다. 그리고 그 결과로 **04 가 카드에 나란히 세운 두 값이 하나로 줄어든다.**
🔴 **날짜만 적힌 옛 문서 수백 장은 그대로 유효하다.**

**Blocked by:** 🟢 **없음 — 지금 착수 가능.** 04 는 이미 착지했다

**Status:** resolved (2026-08-12 22:06)

🟢 **캡틴 승인 2026-08-12** — 두 값을 하나로 줄이는 결정을 직접 보시고 승인하셨다.

## 🔴 04 를 되감지 않는다 — 그 위에서 바꾼다

04 는 착지했고 캡틴이 화면에서 직접 확인하셨다. 이 티켓은 04 가 만든 것을 없던 일로 만들지 않고,
**지금 동작에서 무엇이 어떻게 달라지는지**로만 말한다.

04 가 두 값을 나란히 세운 이유는 하나였다 — **문서는 날짜까지밖에 말하지 못한다.**
캡틴 결정으로 그 전제가 사라졌다. 문서가 분까지 말하면 두 값은 거의 같은 값이 되고,
카드에 나란히 설 이유가 없어진다.

| | 지금 (04 착지분) | 06 이후 |
|---|---|---|
| 완료 시각 읽기 | `resolved (YYYY-MM-DD)` 의 날짜만 | 날짜 + `HH:MM`. 시각이 없으면 날짜만 |
| 저절로 닫힌 카드 | 저장한 닫힘 시각과 문서 완료 날짜를 **각각** | **문서 하나만** — 완료 시각 중 가장 늦은 것 |
| 저절로 닫을 때 DB 에 쓰는 것 | `area=완료` + `closed_at` | `area=완료` **하나** |
| 덮어 닫은 카드 (캡틴이 손으로) | 저장한 `closed_at` | **그대로** — 문서에 그 사실을 적을 자리가 없다 |

🔴 **저장한 시각이 오히려 덜 정확하다.** gootte 가 꺼져 있던 사이에 마지막 티켓이 끝났다면
저장값은 gootte 가 그것을 **알아챈** 때이지 일이 끝난 때가 아니다. 문서가 말하는 값이 맞다.

## 만드는 것

**읽는 자리 하나** — `Status:` 줄에서 완료 시각을 뽑는 자리는 이미 하나뿐이다.
거기서 날짜에 더해 `HH:MM` 까지 집는다. **읽는 자리를 새로 만들지 않는다**(spec §판정 자리는 하나뿐).

| 문서가 적은 것 | 읽히는 값 |
|---|---|
| `resolved (2026-08-12 14:30)` | 날짜 + 시각 |
| `resolved (2026-08-12)` | 날짜만 — 🔴 **`00:00` 을 지어내지 않는다** |
| `resolved` | 없음 |
| `ready-for-agent (2026-08-12 14:30)` | 없음 — 완료 시각은 완료 상태에만 붙는다(기존 규칙 그대로) |

🔴 **시각은 있을 수도 없을 수도 있는 값이다.** 없는 것을 채워 넣는 순간
"이 티켓은 자정에 끝났다"는 거짓이 화면에 뜬다. 없으면 없는 대로 보여 준다.

값을 나르는 계약의 설명문도 함께 고친다 — 지금은 `YYYY-MM-DD` 라고만 적혀 있어,
읽는 사람이 시각이 없는 값이라고 믿게 된다.

**닫는 판정** — 저절로 닫을 때 저장하는 값에서 닫힘 시각을 뺀다. 카드가 보여 주는 닫힌 시각은
**저절로 닫혔으면 문서에서, 덮어 닫았으면 저장값에서** 온다. 🔴 **한 자리에서 갈라 정하고
화면은 받아 쓴다** — 화면이 스스로 고르면 그 순간 판정 자리가 둘이 된다.

이미 저장된 닫힘 시각은 **건드리지 않는다.** 04 가 착지한 뒤 닫힌 카드에는 값이 남아 있고,
그 카드는 저장값을 계속 보여 준다. 지우면 지금 화면에 있는 사실이 사라진다.

**화면 둘** — 기능 탭 티켓 줄의 완료일 칸, 그리고 판 위 카드(와 그 대화상자)의 닫힘 시각.
🔴 완료일 칸은 폭이 고정된 자리라 **어떤 줄은 날짜만, 어떤 줄은 날짜+시각이 되면 줄이 어긋난다.**
섞여도 읽히게 맞춘다.

## 완료됐을 때 보여줄 수 있는 것

작업자가 어느 티켓을 `resolved (2026-08-12 14:30)` 으로 닫는다.
기능 탭에서 그 줄에 **시각까지** 보이고, 어제 날짜만 적고 끝난 옆줄은 날짜만 보이며 칸이 어긋나지 않는다.
그 기능의 마지막 티켓이었다면 판의 카드가 완료 칸으로 가고, 카드에는 **`14:30` 하나가** 적힌다 —
gootte 가 언제 알아챘는지를 따로 말하지 않는다.

## 인수 기준

- [x] `resolved (YYYY-MM-DD HH:MM)` 의 시각이 읽혀서 기능 탭과 카드에 보인다.
- [x] `resolved (YYYY-MM-DD)` 는 날짜만 보인다 — 시각이 지어내어지지 않는다.
- [x] 완료가 아닌 상태의 괄호 시각은 완료 시각으로 읽히지 않는다.
- [x] 시각이 붙은 줄과 날짜만 있는 줄이 섞여도 완료일 칸이 어긋나지 않는다.
- [x] 저절로 닫힌 카드는 닫힘 시각을 저장하지 **않는다** — 그때 DB 에 남는 것은 자리뿐이다.
- [x] 저절로 닫힌 카드가 보여 주는 시각은 **문서**에서 온 값 하나다.
- [x] 캡틴이 손으로 완료에 넣은 카드는 저장된 닫힘 시각을 그대로 보여 준다.
- [x] 04 착지 뒤 이미 저장된 닫힘 시각이 지워지지 않는다.
- [x] 완료 시각을 읽는 자리도, 닫힌 시각을 고르는 자리도 각각 **하나**다.
- [x] 계약의 설명문이 새 서식을 말한다.

## 테스트

- 읽기는 `core/src/parse/feature.test.ts` — 🟡 자리가 이미 있다. 날짜만·날짜+시각·
  완료 아닌 상태의 괄호 시각·엉뚱한 시각 문자열이 최소 골격이다.
- 닫는 판정과 닫힌 시각의 출처는 `core/src/plan/close.test.ts` — 🟡 04 가 세운 자리를 이어 쓴다.
  🔴 04 의 테스트 중 "저절로 닫을 때 닫힘 시각을 쓴다"는 것은 **이 티켓이 규칙을 바꾸므로 함께 바뀐다.**
  바꾼 것은 그 테스트뿐이어야 한다 — 다른 테스트가 함께 흔들리면 판정 자리가 둘로 갈라진 것이다.
- 화면은 `frontend` 테스트가 값이 나오는 것까지 덮고, 칸이 어긋나는지는 캡틴 확인이 본다.

## 이 티켓이 하지 않는 것

- 04 가 만든 대화상자·체크상자·자동 닫힘 자체를 고치지 않는다. 시각 한 갈래만 바꾼다.
- gootte 가 문서에 시각을 **써 주지** 않는다. 적는 것은 작업자다(INV-2).
- 옛 문서에 시각을 채워 넣지 않는다. 날짜만 있는 것은 날짜만 있는 채로 맞다.
- 이미 저장된 닫힘 시각을 지우거나 옮기지 않는다.
- 시각대를 다루지 않는다. 문서가 적은 문자열을 그대로 읽고 그대로 보여 준다.

## 캡틴 확인

🔴 이 티켓은 **캡틴이 이미 확인하신 화면에서 값 하나를 덜어낸다.** 그래서 눈으로 보셔야 한다.

- **열 곳** — gootte 의 `plan` 탭과 `feature` 탭.
- **할 일** — 티켓 하나를 시각까지 적어 닫아 본다. 그 기능의 마지막 티켓이면 카드가 완료 칸으로 간다.
  완료 칸의 카드 머리를 눌러 대화상자도 열어 본다.
- **보여야 할 것** — 카드에 시각이 하나만 남은 것이 허전하지 않고 오히려 읽기 나은가.
  기능 탭에서 날짜만 있는 줄과 시각까지 있는 줄이 섞였을 때 눈에 거슬리지 않는가.

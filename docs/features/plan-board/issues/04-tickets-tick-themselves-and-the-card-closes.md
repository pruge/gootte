# 04 — 티켓이 스스로 체크되고, 다 되면 카드가 닫힌다

**What to build:** 카드의 티켓 줄마다 `[ ]` / `[x]` 상자가 붙는다. 작업자가 **문서에 완료를 적는
순간** 상자가 채워진다 — 아무도 gootte 에 알리지 않는다. 한 기능의 상자가 전부 채워지면
카드는 **완료 칸으로 옮겨 가고 그 시각이 찍힌다.** 완료 칸의 카드는 접혀 있고, 누르면 펼쳐진다.

**Blocked by:** 02 — 카드와 칸이 먼저 있어야 한다

**Status:** draft

## 이 티켓이 없애는 문제

캡틴의 문제점 ③ — "내용이 문서와 실시간 연동되지 않는다".
실시간 배선은 이미 있었고(spec F1·F3), 티켓 상태도 이미 매 요청 문서에서 다시 읽고 있었다(F4).
없던 것은 **그것을 보여주는 화면** 하나뿐이다.

## 만드는 것

**체크상자** — 티켓 상태가 완료면 `[x]`, 아니면 `[ ]`. 🔴 **저장하지 않는다.** 문서에서 읽는다(INV-5).
읽는 자리는 이미 있다 — 새 파싱을 만들지 않는다.

**저절로 닫힘** — 한 기능의 티켓이 전부 완료인 것을 처음 보면 `area=완료` 와 `closed_at` 을 적는다.
🔴 gootte 가 스스로 계획 DB 에 쓰는 **유일한 자리**다.

`closed_at` 은 gootte 가 닫힌 것으로 **기록한 시각**(날짜+시간)이다.
문서에는 완료 날짜만 있고 시각이 없으므로(spec F6), 마지막 티켓이 실제로 끝난 날은
문서가 가진 그대로 카드에 함께 보여 준다. 둘을 한 값으로 뭉개지 않는다 —
뭉치는 순간 어느 쪽도 사실이 아니게 된다.

**접힌 카드** — 완료 칸의 카드는 머리만 보인다. 누르면 티켓 목록이 펼쳐진다.
접힘은 화면의 상태이지 저장하지 않는다.

**남은 것을 안고 닫힌 카드** — 03 이 캡틴의 손으로 완료에 넣은 카드는 안 채운 상자를 그대로 갖는다.
펼치면 빈 상자가 빈 상자로 보인다(INV-B4). 지우지도, 완료로 위장하지도 않는다.

## 🔴 되돌아 나오는 길을 만들지 않는다

닫힌 기능에는 티켓을 더하지 않는다. 더 할 일이 생기면 새 기능을 세운다(캡틴 결정, INV-B5).
그래서 이 티켓은 **닫을 때 티켓 목록을 기억하지 않고, 새 번호가 붙었는지 감시하지 않고,
자동으로 대기로 되돌리지 않는다.** 규율을 어겨 티켓이 하나 붙으면 카드는 완료 칸에 머문 채
빈 상자를 하나 보여 주고, 캡틴이 보고 정하신다.

## 완료됐을 때 보여줄 수 있는 것

캡틴이 `plan` 탭을 연 채로 둔다. 작업자가 어느 티켓 문서의 상태를 완료로 바꾼다.
**새로 고치지 않았는데** 그 줄의 상자가 채워진다. 마지막 티켓까지 채워지는 순간
카드가 작업 대상에서 사라지고 완료 칸에 **접힌 채로** 나타난다. 시각이 함께 적혀 있다.
눌러 펼치면 티켓들이 전부 채워진 상자로 보인다.

## 인수 기준

- [ ] 티켓 줄에 상태에 맞는 `[ ]` / `[x]` 가 보인다.
- [ ] 문서의 상태를 바꾸면 새로 고침 없이 상자가 바뀐다.
- [ ] 상자가 전부 채워지면 카드가 완료 칸으로 가고 시각이 찍힌다.
- [ ] 완료 칸의 카드는 접혀 있고, 누르면 펼쳐지고, 다시 누르면 접힌다.
- [ ] 남은 티켓을 안고 닫힌 카드는 펼쳤을 때 빈 상자를 그대로 보여 준다.
- [ ] 카드는 자동 완료 시각과 문서가 말하는 완료 날짜를 **각각** 보여 준다.
- [ ] 체크 상태가 계획 DB 에 저장되지 않는다.

## 테스트

- 완료 판정(전부 완료인가)과 닫는 순간의 판단은 `core` 순수 함수 단위 테스트 — 🔴 이 티켓이 **처음** 덮는다.
  티켓 0장인 기능, 일부만 완료, 전부 완료, 폐기 티켓이 섞인 경우가 최소 골격이다.
- 상자 표시와 접힘은 `frontend` 테스트.
- 🔴 문서 파싱 테스트는 고치지 않는다 — 이 티켓은 **읽는 자리를 새로 만들지 않는다.**
  고쳐야 한다면 판정 자리가 둘로 갈라진 것이다.

## 이 티켓이 하지 않는 것

- 끌어 옮기기와 이동 대화상자(03).
- 단계와 `next`(05).
- 닫힌 기능이 다시 열리는 경로 — 만들지 않는 것이 결정이다.

## 캡틴 확인

- **열 곳** — gootte 의 `plan` 탭을 연 채로 둔다.
- **할 일** — 다른 창에서 작업 대상에 올라온 어느 기능의 티켓 문서 상태를 하나씩 완료로 바꿔 본다.
  마지막 하나까지 바꾼다. 그 다음 완료 칸의 카드를 눌러 펼쳐 본다.
- **보여야 할 것** — 새로 고치지 않았는데 상자가 채워지는가. 마지막에 카드가 접힌 채 완료 칸으로 가는가.
  펼친 모습이 읽을 만한가.

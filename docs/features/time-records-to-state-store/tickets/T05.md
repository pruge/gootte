# T05 — TS time 명령 + bin/gootte 모드 분기 + worktree 메인 해소

**Blocked by:** T01

**Time:** started=2026-09-09T09:41:45+09:00 finished=2026-09-09T09:54:56+09:00

## Goal

state.json 모드에서 시간 기록을 수행하는 TS 명령을 만들고, `bin/gootte`가
v2 state.json을 발견하면 위임하게 한다. worktree에서는 메인 프로젝트의
state.json에 기록한다(config.json, 없으면 자동 생성).

## Why this slice

JSON 편집을 bash/python이 아니라 테스트 가능한 TS(core-io)에서 한다 —
`status` 명령이 이미 TS 위임하는 패턴의 확장이다.

## Produces

- `cli/src/time.ts` — start·pause·resume·end·cancel·drop + `--at` 상대시간 파서
- `bin/gootte` — v2 발견 시 TS 위임, 없으면 기존 bash 경로
- worktree 메인 해소: `.gootte/config.json` `mainProject` → 없으면
  `git rev-parse --git-common-dir`로 추론해 생성(B3 해소)

## Consumers

- 캡틴·에이전트의 `gootte start/end` (gootte 프로젝트)
- `routes/time.ts` — 그대로 bin/gootte 호출(분기는 CLI 안에서)

## Touched surfaces

- `code/web/cli/src/time.ts` + `main.ts` — `time <cmd>` 서브명령
- `code/web/cli/src/time.test.ts` — 신설
- `bin/gootte` — 모드 판정 + 위임
- `code/web/core-io/src/state-store.ts` — 기록 후 `recalcProjectState`(배지 동시 갱신)

## Explicitly out of scope

- MD 모드 명령 변경(T04가 결함만 수정)
- 대화형 확인(start --update 가이드) — 비대화형: `--update` 없이 이미 started면 오류

## Locked decisions

- **D4** — 레코드는 항상 메인 프로젝트 state.json에 기록한다
- bash의 검증 규칙을 verbatim 승계: 끝난 티켓 start 금지, 미시작 end/cancel 금지,
  일시중단 중 end 금지(resume 먼저), 이미 폐기 drop 금지
- 기록 후 배지(`recalcProjectState`)를 같은 트랜잭션으로 갱신한다

## Scope

1. `resolveTime("--at")` 포트(ISO8601·90m/1h30m/2h/1d, 과거 해석)
2. 6개 명령 구현(레코드 upsert/remove + 검증 규칙 + 기록 후 배지 재계산)
3. 메인 해소(config.json → git-common-dir 추론 → 생성)
4. bin/gootte 모드 판정(grep '"version": 2' 또는 tickets 키) + 위임
5. vitest 케이스(임시 디렉토리 픽스처)

## Implementation notes

- `cancel`은 레코드 삭제가 MD Time: 줄 삭제의 대응물이다(캡틴 결정: MD 줄은 유지되지만
  레코드 모드에서는 무시되므로 D2에 의해 값도 사라진다 — 올바른 cancel 의미)
- 티켓 존재 검증은 MD 파일 존재로 한다(resolve_ticket_file과 동일) — 파일이 없는
  티켓에 기록하지 않는다

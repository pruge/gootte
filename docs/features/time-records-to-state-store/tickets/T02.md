## Goal

`applyBacklogStatus`와 같은 조인 패턴. 레코드가 권위다.

화면·CLI·백엔드가 같은 상태를 말하려면 조인 자리가 하나여야 한다(INV-3).
지금 시간·상태는 MD 파싱(mergeSlug)에서만 온다 — 레코드 계층이 그 위를 이기게 한다.

## Implementation notes

- `statusRaw`는 `parseStatusLine("Status: " + raw)`로 해석 — 줄 서식 파서를 그대로 쓴다
- 구관례 티켓도 statusRaw 없이 times만 있으면 pending·statusKnown false 유지 —
  현재 MD 동작(Status: 줄 없는 구관례)과 동일해야 한다

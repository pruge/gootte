## Goal

기능 목록을 읽는 세 길(백엔드·CLI·기록 라우트)이 같은 조인 자리를 지나게 한다.

## Why this slice

the-terminal-agrees-with-the-screen — CLI와 화면이 다른 값을 보면 그중 하나는
거짓말이다. 조인 자리는 `applyTimeRecords` 하나뿐이고, 배선만 남는다.

## Produces

- 백엔드 `featuresFor` — 스냅샷 히트·재계산 어느 길이든 반환 직전 조인
- CLI `featureStateText`/`boardText`/`nextText` — readFeatures 뒤 조인
- `routes/time.ts` — 기록 뒤 `recordProjectScan`에 조인된 값 기록

## Consumers

- 화면(features·plan·process 탭)·CLI·배지 — 모두 이 길을 지난다

## Touched surfaces

- `code/web/backend/src/app.ts` — featuresFor
- `code/web/cli/src/commands.ts` — 3개 읽기 명령
- `code/web/backend/src/routes/time.ts` — recordProjectScan
- `code/web/core-io/src/features.ts` — `readFeaturesWithTime(copies, projectDir)` 헬퍼(모드 판정 포함)

## Explicitly out of scope

- 워커(features-worker) 내부 조인 — 스냅샷은 미조인 값을 저장하고 서빙 직전 조인한다(INV-3)
- `snapshot.ts` 스키마 변경 없음

## Locked decisions

- **D2** — 모드 판정은 프로젝트 단위: v2 state.json이 있으면 조인, 없으면 원본 반환
- 조인은 서빙 시점에 한다 — 레코드가 바뀌면 다음 읽기가 곧 새 값을 본다(캐시에 굳지 않는다)

## Scope

1. core-io `readFeaturesWithTime(copies, projectDir)` — v2 판정 + applyTimeRecords
2. 세 소비처 교체
3. 회귀: v2 없음 = 기존(기존 테스트 전부 통과), v2 있음 = 레코드 승(신규 케이스)

## Implementation notes

- `projectDir` = 대표 경로(`proj.path`) — 레코드는 메인에만 있다(D4)
- 스냅샷 히트 경로도 조인을 지난다 — 레코드 갱신이 스냅샷 무효화 없이 반영된다

# T06 — `gootte migrate-time` 이관 명령

**Blocked by:** T02, T05

**Time:** started=2026-09-09T09:54:56+09:00 finished=2026-09-09T10:06:30+09:00

## Goal

MD `Time:`/`Status:` 줄을 state.json v2 레코드로 옮기는 이관 명령을 만든다.
**MD 줄은 삭제하지 않는다**(캡틴 결정 3).

## Why this slice

이관이 없으면 레코드가 권위인 프로젝트에서 기존 144장의 기록이 사라진다.
레코드 기록 + 재파싱 대조 리포트로 "같은 값이 나온다"를 증명한 뒤에야
나중의 MD 삭제가 안전해진다.

## Produces

- `gootte migrate-time [--dry-run] <기능...|전체>` — CLI 명령
- 레코드 기록(멱등 — 이미 같은 레코드면 무변경)
- 리포트: 이관 대상 수·기록된 레코드 수·건너뛴 것(레코드·MD 둘 다 없는 티켓)

## Consumers

- T07 — gootte 자신에 실행

## Touched surfaces

- `code/web/cli/src/migrate-time.ts` — 신설
- `code/web/cli/src/main.ts` — 명령 등록
- `code/web/cli/src/migrate-time.test.ts`

## Explicitly out of scope

- MD 줄 삭제/편집 — 절대 하지 않는다
- 타 프로젝트 실행 — 명령은 얼마든지 다른 루트에 쓸 수 있지만 이번엔 gootte만

## Locked decisions

- 파싱은 **실제 읽기 경로와 같은 파서**(parseTimeLine·parseStatusLine)로 한다 —
  리포트의 "재파싱 대조"가 그래서 의미 있다
- 사본이 여럿이면 `mergeTicketTimes`와 동일 규칙(earliest started / latest finished /
  pause 짝맞춤)으로 합친 뒤 레코드로 기록한다 — MD 계층의 병합 지식이 일회성으로 사라지지 않게

## Regression guards

- 🔴 dry-run은 파일 시스템을 하나도 바꾸지 않는다(INV-2)
- 🔴 재실행(멱등) — 레코드 수가 늘지 않는다
- 🔴 `pnpm verify` 통과

## Scope

1. MD 줄 → 레코드 변환(양 관례, 사본 병합 포함)
2. `--dry-run` 리포트 / 실실행 기록
3. 재파싱 대조 — 기록된 레코드를 applyTimeRecords로 읽어 MD 파싱과 비교, 차이 리포트
4. 테스트(임시 픽스처: 구관례 2·신관례 2·pause 1·cancel 흔적 1)

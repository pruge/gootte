## Goal

`state.json` v2 스키마(`tickets` 맵)를 contract에 정의하고, core-io state-store가
레코드를 읽고·쓰고·지우며, 기존 파생 캐시(`openFeatures`)를 갱신할 때 레코드를
**보존하는** read-modify-write로 바뀌게 한다.

## Why this slice

모든 후속 티켓(T02 조인·T05 쓰기·T06 이관)이 이 저장소 위에 선다. 지금
`updateProjectState`는 파일을 통째로 덮어쓰므로 레코드를 함께 두면 파생 갱신이
레코드를 지우는 사고가 난다. 또 `readState`가 zod 검증 없이 cast라 SoT이 된
순간 깨진 파일이 조용한 데이터 소실이 된다(B4).

## Produces

- contract: `TicketTimeRecord`·`ProjectStateV2` zod 스키마 + 타입
- core-io/state-store: `readTicketRecords`·`upsertTicketRecord`·`removeTicketRecord`·
  `recalcProjectState` — 전부 원자적(.tmp→rename)

- `updateProjectState` → `recalcProjectState` 개정(openFeatures 재계산 + tickets 보존)

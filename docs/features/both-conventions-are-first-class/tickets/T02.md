# T02 — 신관례 티켓을 가리키는 기능 간 선행도 풀린다
Time: started=2026-08-26T10:39:08+09:00 finished=2026-08-26T08:47:14+09:00

## Goal

`Blocked by:` 의 markdown 링크가 다른 기능의 **신관례** 티켓(`tickets/T<NN>.md`)을 가리켜도
그 티켓이 완료되면 선행이 풀린다.
지금은 링크 경로를 뜯는 정규식이 `issues/` 만 알아서 영영 막힌 채 남는다.

## Why this slice

T01 과 같은 부류(경로 모양으로 관례를 가르는 자리가 구관례만 안다)이지만 **다른 자리, 다른 사용자 증상**이다.
T01 은 "읽어도 초록이 안 풀린다", 이 티켓은 "선행이 끝나도 착수 가능이 안 된다".
한 티켓에 묶으면 두 회귀 시험이 서로의 실패를 가린다.

## Produces

**기능을 넘는 선행 링크의 해소 결과** — `parseCrossFeatureRef` 가 돌려주는 `{ feature, num }`.

지금은 링크 경로가 `<기능>/issues/<번호>-` 로 풀릴 때만 값이 나온다.
앞으로는 `<기능>/tickets/T<번호>.md` 로도 값이 나온다.

돌려주는 **모양은 바뀌지 않는다** — 지금과 같은 `{ feature, num }` 이고 `num` 은 `"03"` 같은 숫자 문자열이다.
바뀌는 것은 **어떤 경로가 풀리나** 하나뿐이다.

## Locked decisions

- **추정 금지(INV-4)**: 경로가 기능과 번호를 **둘 다** 담고 있을 때만 푼다.
  안 풀리면 `null` 을 돌려주고 호출자가 지금처럼 계속 막는다(`features.ts:129` — `if (ref === null) return true;`).
- **표시 문구는 안 본다** — `MD_LINK_PATH`(`feature.ts:160`)가 괄호 안 경로만 뗀다. 대괄호 안 꾸밈은 사람 마음이다.
- **`../../` 깊이는 상관없다** — 지금 정규식이 경로 어디에서든 조각을 찾는 이유이고, 그 성질을 유지해야 한다.
- **관례 목록은 `(issues|tickets)` 다** — `core/src/parse/ticket-path.ts:21` 이 이미 그렇게 적고 있다.
- **번호 표기가 관례마다 다르다** — 구관례는 `01-slug.md`(번호 뒤 하이픈), 신관례는 `T04.md`(접두 `T`, 하이픈 없음).
  `ticket-path.ts:45` 가 이미 `/^[Tt]?(\d{1,3})/` 로 두 모양에서 같은 `num` 을 뽑는다 — **같은 뜻이어야 한다.**

## Regression guards

- 기존 시험 `"번호 없이 적힌 진짜 산문"` → `null`(`feature.test.ts:291`)이 계속 통과해야 한다.
- 기존 시험 `"[어딘가](https://example.com/docs)"` → `null`(`:295`)이 계속 통과해야 한다 —
  정규식을 너무 헐겁게 넓히면 바깥 URL 이 기능 이름으로 읽힌다.
- 기존 시험 `"[02](02-x.md)"` → `null`(`:300`)이 계속 통과해야 한다 — 같은 기능 안 상대 링크는 이 자리의 일이 아니다.
- 신관례 폴더의 비티켓 링크(`tickets/README.md`)는 풀리지 않아야 한다 — 새 시험.

## Scope

정규식 한 자리와 그 회귀 시험. 그 이상 넓히지 마라.

## Implementation notes

- 넓히는 방식은 구현자 판단이되, **`ticket-path.ts:21`·`:45` 와 같은 뜻이어야 한다** —
  이 저장소가 아는 관례는 `issues`·`tickets` 둘이고, 신관례 티켓은 `T<NN>.md` 뿐이며, `num` 에서 접두 `T` 는 걷는다.
- 두 관례의 파일명 모양이 다르다는 것을 잊지 마라: 구관례는 번호 뒤 **하이픈이 필수**(`01-x.md`),
  신관례는 하이픈이 **없다**(`T04.md`). 하나의 정규식으로 묶든 둘로 나누든 두 모양 다 옳게 잡아야 한다.
- 판정 자리를 새로 만들지 마라 — `parseCrossFeatureRef` 하나가 계속 유일한 자리다.

## Acceptance criteria

1. `[T03](../../other-feature/tickets/T03.md)` 가 `{ feature: "other-feature", num: "03" }` 로 풀린다.
2. `[03](../../other-feature/issues/03-x.md)` 의 기존 동작이 그대로다.
3. `tickets/README.md` 를 가리키는 링크는 `null` 이다(티켓이 아니다).
4. 바깥 URL·번호 없는 산문·같은 기능 상대 링크가 전부 지금처럼 `null` 이다.
5. 신관례 티켓을 선행으로 건 티켓이, 그 선행이 완료로 조인된 뒤 `startable === true` 가 된다
   (`applyBacklogStatus` 의 재판정 경로까지 도는지 확인한다 — `backlog-join.ts:88`).
6. 시험 전량 통과, 신규 시험 포함.

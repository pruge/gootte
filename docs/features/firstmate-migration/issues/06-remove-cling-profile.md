# 06 — `.cling/` 삭제

**What to build:** 은퇴한 워크플로우의 마지막 흔적인 `.cling/profile.md` 를 지운다.
한 파일 삭제지만 **이 사양에서 유일하게 순서가 위험한 티켓**이라 따로 세웠다 — §순서 참고.

**Blocked by:** 03, 04, 05, 그리고 **자매 기능 `firstmate-project-source` 의 티켓 01**

**Status:** resolved (2026-08-09)

## 완료 시 시연 가능한 것

저장소에 은퇴한 워크플로우의 설정이 하나도 남아 있지 않다.
그러면서도 **gootte 는 여전히 자기 대시보드에 자기 자신을 보여준다** — 새 발견 규칙이
`AGENTS.md` 와 `docs/features/` 를 보기 때문이다.

## 🔴 순서 — 위험한 방향은 하나다

이 제품은 **`.cling/profile.md` 가 있는 디렉토리만 프로젝트로 센다.**
그래서 이 파일을 지우는 순간 gootte 는 **자기 대시보드에서 사라진다.**

자매 기능의 발견 규칙 전환(그쪽 티켓 01)이 착지한 **뒤에** 이 티켓이 착지해야 한다.
반대 순서 — 이 파일을 먼저 지우고 발견 규칙을 나중에 바꾸는 것 — 이 위험한 방향이다.
그 사이 구간에서 제품은 관리 대상을 하나도 못 찾는다.

착수 전에 **새 발견 규칙이 이미 살아 있는지 직접 확인한다.** 대시보드를 띄워 gootte 가
목록에 있는지 보는 것으로 충분하다.

## 완료 조건

- `.cling/` 이 없다.
- 대시보드에 gootte 가 여전히 보인다 (위 확인의 재확인).
- `git grep -rn cling -- . ':!code'` 잔량 0.
- `pnpm verify` green.

## 테스트

새로 만들지 않는다. 이 티켓의 진짜 검증은 **대시보드에 gootte 가 남아 있는지**이고,
그것은 자매 기능 티켓 01 이 만든 테스트가 이미 덮는다.

## 이 티켓이 하지 않는 것

- 제품의 옛 발견·파싱 경로 제거 — 자매 기능의 축소 티켓이 한다. 이 티켓은 설정 파일만 지운다.
- 옛 포트 레지스트리에서 gootte 항목 제거. 그 레지스트리는 이 저장소 밖에 있고 다른 프로젝트가 쓴다.

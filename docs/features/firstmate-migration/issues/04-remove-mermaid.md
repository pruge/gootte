# 04 — mermaid 전부 제거

**What to build:** 다이어그램을 손으로 갱신하는 두 번째 표현을 이 제품에서 완전히 걷어낸다.
저장소의 다이어그램 파일 8개와 그 정합성 검사 스크립트뿐 아니라, **관리대상의 다이어그램을 읽어 화면에
그리는 제품 기능 전체**가 대상이다. 문서 본문에 끼어 있는 다이어그램 표기의 렌더도 포함한다.

**Blocked by:** 01

**Status:** ready-for-agent

## 완료 시 시연 가능한 것

캡틴이 대시보드를 열면 **구조 다이어그램 화면이 아예 없다.** 문서를 열면 다이어그램 표기는
평범한 코드 덩어리로 보인다. 앱 꾸러미에서 다이어그램 라이브러리가 빠져 첫 화면이 가벼워진다.

## 완료 조건

- 저장소의 `docs/mermaid/` 8파일과 `scripts/mermaid-refs-check.sh` 가 없다.
- 제품 표면이 전부 사라졌다 — 계약의 구조 다이어그램 타입 3종과 lineage 노드 종류의 `mermaid` 값,
  순수 계층의 다이어그램 파서와 구조 계산, IO 계층의 다이어그램 수집, 백엔드의 구조 조회 경로,
  프론트엔드의 구조 화면 3개와 다이어그램 렌더 블록, 그리고 문서 렌더에서의 그 연동.
- `code/web/frontend/package.json` 에 다이어그램 라이브러리 의존이 없다.
- `git grep -rni mermaid` 잔량 0.
- contract codegen 을 재실행한 뒤 `git diff` 가 0 이다 (생성물 표류 없음).
- `pnpm verify` green.

## 테스트

**새 테스트를 만들지 않는다.** 이 티켓은 기능 제거이고, 사라진 기능의 테스트도 함께 사라진다.
`app.test.ts` 의 구조 조회 테스트, `structure.test.ts`, `mermaid.test.ts`, 프론트엔드 구조 화면 테스트가
제거 대상이다. **커버리지 숫자가 내려가는 것은 회귀가 아니라 삭제의 결과다.**

남는 검증은 두 가지 — 전체 검증 green 과 codegen 재실행 후 diff 0.
후자가 이 티켓에서 특히 중요하다. 계약 타입을 지우면 생성물이 따라 지워져야 하는데,
그것을 감시하는 것은 사람 눈이 아니라 그 검사다.

## 이 티켓이 하지 않는 것

- 다이어그램을 다른 방식으로 대체하기. **대체하지 않는다.** 의도는 사양과 결정 기록이 담고,
  연결 관계는 도구가 코드에서 뽑는다 — 그것이 이 삭제의 근거다.
- 관리대상 프로젝트들의 다이어그램 파일 건드리기. 이 제품은 관리대상에 쓰지 않는다.
- 문서 렌더 자체를 없애기. 문서는 계속 보인다. 다이어그램 표기만 코드로 보일 뿐이다.

## 실행 모델

기본 작업자 등급을 넘는다.

**이유:** 계약에서 타입을 빼는 일과 lineage 노드 종류에서 값 하나를 빼는 일은 **파급을 배치로 나눌 수 없다.**
계약·순수 계층·IO·백엔드·프론트엔드가 같은 타입을 공유하므로, 한쪽만 고친 중간 상태는 컴파일되지 않는다.
전체를 한 번에 일관되게 들고 있어야 하고, codegen 생성물까지 함께 맞아야 한다.

## 캡틴 확인

- **어디서** — gootte 대시보드를 띄운다 (`pnpm dev`).
- **무엇을** — 왼쪽에서 프로젝트를 하나 고르고, 화면 위쪽 탭들을 훑는다. 그다음 문서 하나를 열어 본다.
- **무엇이 보여야 하나** — 구조 다이어그램 탭이 **없다.** 문서 안에 다이어그램이 있던 자리는
  코드 덩어리로 보인다. 나머지 화면(계획·타임라인·작업 사본)은 그대로 동작한다.

테스트가 판정할 수 없는 것이라 캡틴 눈이 필요하다 — 탭 하나가 사라진 뒤 남은 화면의 배치가
어색하지 않은지는 사람이 봐야 안다.

# 05 — 개발 서버 포트를 firstmate 방식으로

**What to build:** 개발 서버 포트를 **파일 하나가 정하고 스크립트 하나가 읽는 구조**로 바꾼다.
지금은 포트가 소스 안에 기본값으로 박혀 있고, 격리 사본에서 포트를 갈아 끼우던 일은 은퇴한
워크플로우가 하던 것이라 지금은 아무도 하지 않는다. 그 결과 **작업자 둘이 동시에 개발 서버를 띄우면
같은 포트에서 부딪힌다.** jinwooauto 가 이미 푼 방식을 그대로 가져온다.

**Blocked by:** 01

**Status:** ready-for-agent

## 완료 시 시연 가능한 것

캡틴이 메인 작업 사본에서 개발 서버를 띄우면 **뒷단 8804 · 앞단 5304** 로 뜬다.
격리 사본에서 띄우면 firstmate 가 그 사본에 써 넣은 다른 포트로 뜬다. 둘이 동시에 떠도 부딪히지 않는다.
포트 설정이 아예 없으면 **엉뚱한 기본값으로 뜨지 않고 무엇이 없는지 말하며 멈춘다.**

## 완료 조건

- 포트 해석 스크립트가 하나 있고, 그것이 유일한 판정자다. 규칙은 **격리 사본용 파일이 있으면 그 값,
  없으면 메인용 파일 값.** 판정은 파일 존재 여부만 본다 — 작업 사본 경로를 캐묻지 않는다.
- 메인용 포트 파일이 저장소에 추적되고 `BACKEND_PORT=8804` / `FRONTEND_PORT=5304` 를 담는다.
- 격리 사본용 포트 파일은 `.gitignore` 에 있다. **그 파일을 쓰는 주체는 firstmate 다** —
  이 저장소는 읽기만 한다.
- 둘 다 없거나, 값이 비었거나, 값이 숫자가 아니면 **조용히 기본값으로 넘어가지 않고 오류로 멈춘다.**
  무엇이 없는지 말한다.
- 뒷단·앞단 개발 실행 경로가 소스에 박힌 기본값 대신 그 스크립트 값을 쓴다.
- `pnpm verify` green.

## 테스트

**이 티켓이 이 코드를 처음 덮는다.** 포트 해석에 대한 테스트는 지금 하나도 없다.
jinwooauto 의 포트 테스트를 이식하고, 다음 네 경우를 반드시 포함한다.

| 경우 | 기대 |
|---|---|
| 격리 사본용 파일이 있다 | 그 값이 이긴다 |
| 메인용 파일만 있다 | 메인 값이 나온다 |
| **둘 다 없다** | **오류로 멈춘다. 기본값으로 넘어가지 않는다** |
| 값이 비었거나 숫자가 아니다 | 오류로 멈춘다 |

세 번째와 네 번째가 이 스크립트 설계의 핵심이다. 조용히 기본값으로 넘어가는 순간
두 작업 사본이 같은 포트를 쓰면서도 아무도 그 사실을 모르게 된다.

테스트는 실제 저장소 파일을 건드리지 않도록 **임시 디렉토리를 뿌리로 가리켜** 돌린다.

## 이 티켓이 하지 않는 것

- 격리 사본에 포트를 **배정**하는 일. 그것은 firstmate 가 작업 사본을 만들 때 한다.
  이 저장소는 배정된 값을 읽을 뿐이다.
- 옛 포트 레지스트리 정리. 다른 프로젝트가 아직 쓴다.
- 운영 배포 포트 변경. 개발 서버 이야기다.

# T05 — state.json 저장소 신설

**Blocked by:** 없음 (T01~T04와 독립)
**Status:** open
**Time:**

## Goal

프로젝트 상태를 JSON 파일로 관리하는 모듈을 만든다.

## Why this slice

git이 사라지면 staleness·스탬프·카운팅을 대체할 텍스트 기반 저장소가 필요하다. `state.json`은 git 친화적(텍스트)이고, MD 파일이 SoT인 파생물로 동작한다(INV-1).

## Produces

`core-io/src/state-store.ts` 모듈. `readState`·`writeState`·`updateProjectState`·`clearState`.

## Consumers

- `app.ts` — `/api/projects`에서 `openFeatures` 읽기 (T06)
- `app.ts` — `featuresFor` 호출 후 상태 갱신
- `gootte start/end` — Time: 기록 후 상태 갱신

## Touched surfaces

- `core-io/src/state-store.ts` — 신규 생성
- `core-io/src/index.ts` — 새 모듈 export 추가
- `backend/src/app.ts` — state-store 연결

## Explicitly out of scope

- 사이드바 배지 연결 (T06)
- `gootte start/end`와의 연결 (T08 이후)

## Locked decisions

- **D1** — state.json은 파생물, MD가 SoT (spec)
- **D2** — plan.db와 state.json은 분리 (spec)

## Evidence anchors

- `backend/src/app.ts:424` — `openCountBySlug` Map (대체 대상)
- `backend/src/app.ts:478-501` — `scheduleCountFill` (대체 대상)

## Regression guards

- 🔴 `pnpm verify` 통과
- 🔴 state.json 없이도 기존 동작 유지 (점진적 전환)

## Scope

1. `core-io/src/state-store.ts` 신규 생성
2. 스키마 정의: `version`, `updatedAt`, `openFeatures`
3. `readState(projectDir)` — `<projectDir>/.gootte/state.json` 읽기, 없으면 빈 상태 반환
4. `writeState(projectDir, state)` — 원자적 쓰기
5. `updateProjectState(projectDir, features)` — openFeatures 계산 후 기록
6. `clearState(projectDir)` — state.json 삭제
7. `core-io/src/index.ts`에서 export 추가
8. `app.ts`에서 state-store import

## Implementation notes

- 위치: ** `<프로젝트 루트>/.gootte/state.json`** — 프로젝트와 함께 이동
- 스키마: `{ version: 1, updatedAt: string, openFeatures: Feature[] }`
- 원자적 쓰기: `.tmp` → `renameSync` (snapshot.ts와 같은 패턴)
- `readState`는 파일 없으면 빈 상태 반환 (에러 아님)
- `.gootte/` 는 gitignore (이미 관례)

## Acceptance criteria

- AC2 — 읽기/쓰기 정상 동작
- AC3 — `tsc --noEmit` 통과

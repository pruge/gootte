# T12 — gootte start → 메인 state.json 갱신

**Blocked by:** T05, T10
**Status:** open
**Time:**

## Goal

worktree에서 `gootte start` 실행 시 메인 프로젝트의 `.gootte/state.json`을 자동으로 갱신한다.

## Why this slice

worktree는 메인 프로젝트의 복사본이다. worktree에서 `gootte start`로 `Time:`을 기록하면, 메인의 state.json도 갱신되어야 사이드바에서 즉시 반영된다. 현재는 worktree의 `Time:` 변경을 메인이 모른다.

## Produces

- `gootte start`가 메인 state.json을 갱신하는 동작
- worktree의 `.gootte/config.json`에 `mainProject` 경로 기록

## Consumers

- `bin/gootte` — `cmd_start`에서 config.json 읽기 → 메인 state.json 갱신
- `core-io/src/state-store.ts` — `updateProjectState` 호출

## Touched surfaces

- `bin/gootte` — `cmd_start`에 state.json 갱신 로직 추가
- `core-io/src/state-store.ts` — worktree에서 메인 갱신 지원 함수

## Explicitly out of scope

- config.json 자동 생성 — worktree 생성 시 별도 처리 (또는 수동)
- gootte end/pause/resume — start만 해당 (이 티켓에서는)

## Locked decisions

- **D8** — worktree에서 gootte start 시 config.json으로 메인 경로를 찾아 state.json 갱신 (spec)

## Evidence anchors

- `bin/gootte:221-286` — `cmd_start` 함수

## Regression guards

- 🔴 `pnpm verify` 통과
- 🔴 메인 프로젝트에서 gootte start 시 기존 동작 유지
- 🔴 config.json 없으면 메인 갱신 건너뜀 (에러 아님)

## Scope

1. `bin/gootte`의 `cmd_start`에서:
   - `<project>/.gootte/config.json` 읽기
   - `mainProject` 경로 확인
   - 메인 프로젝트의 `.gootte/state.json`에서 openFeatures 갱신
2. config.json 구조: `{ "mainProject": "<absolute_path>" }`
3. config.json 없으면 메인 갱신 건너뜀 (단일 프로젝트 모드)
4. state.json 갱신은 `core-io/src/state-store.ts`의 `updateProjectState` 사용

## Implementation notes

- `cmd_start`는 bash 스크립트 — state.json 갱신은 `node`로 별도 스크립트를 호출하거나, gootte CLI의 `feature state` 명령을 활용
- 또는 `cmd_start` 끝에 `node -e "..."` 로 간단히 갱신
- config.json은 worktree 생성 시 `gootte init` 또는 수동으로 작성

## Acceptance criteria

- AC1 — worktree에서 gootte start 시 메인 state.json 갱신
- AC2 — config.json 없으면 건너뜀 (에러 없음)
- AC3 — `tsc --noEmit` 통과

## Verification

`pnpm verify` + worktree에서 gootte start 후 메인 state.json 확인

# T10 — settings 통합: firstmateHome + watchRoots → projects[]

**Blocked by:** 없음 (T01~T04와 독립)
**Status:** open
**Time:**

## Goal

감시 대상 설정을 `firstmateHome` + `watchRoots` 분리에서 `projects[]` 단일 배열로 통합한다.

## Why this slice

현재 감시 대상은 `firstmateHome`(백그라운드 파생)과 `watchRoots`(명시) 두 곳에서 정의된다. worktree 루트까지 더하면 세 곳이 된다. `projects[]` 하나로 통합하면 단순하고 명시적이다.

## Produces

`settings.json`의 `projects[]` 필드. 기존 필드 폐기.

## Consumers

- `discover.ts` — `discoverProjects`가 `projects[]`를 뿌리로 사용
- `settings-store.ts` — `resolveWatchRoots` → `resolveProjects`로 변경
- `app.ts` — `effectiveRoots()`가 `projects[]` 반환

## Touched surfaces

- `contract/src/index.ts` — `Settings` 스키마: `firstmateHome`·`watchRoots` 제거, `projects` 추가
- `core-io/src/settings-store.ts` — `resolveWatchRoots` → `resolveProjects`, `settingsHasWatchRoots` 제거
- `core-io/src/discover.ts` — `deriveWatchRoots` 제거, `effectiveProjectRoots`에서 `projects` 사용
- `backend/src/app.ts` — `effectiveRoots()` 변경
- `frontend/src/` — settings UI에서 `firstmateHome`·`watchRoots` 입력 제거, `projects[]` 입력으로 변경

## Explicitly out of scope

- backlog/secondmates — `firstmateHome` 폐기 시 별도 처리 필요 (이 티켓 이후)
- state.json — T05에서 별도 처리

2. contract `SettingsUpdateRequest`: `firstmateHome`·`watchRoots` 제거, `projects` 추가
3. contract `SettingsResponse`: `firstmateHomeExists`·`firstmateHomeSuggestion`·`effectiveWatchRoots` 제거, `effectiveProjects` 추가
4. `settings-store.ts`: `resolveWatchRoots` → `resolveProjects(settings, fallback)`, `settingsHasWatchRoots` 제거
5. `discover.ts`: `deriveWatchRoots` 제거, `effectiveProjectRoots`에서 `projects` 사용
6. `app.ts`: `effectiveRoots()` → `effectiveProjects()` 호출

## Implementation notes

- 마이그레이션: `readSettings`에서 `projects` 키가 없고 `watchRoots`가 있으면 자동 복사
- `defaultProjectRoots()`는 fallback으로 유지 (`~/Documents/ai2/projects`)
- `firstmateHome`은 backlog/secondmates에서 아직 쓰이므로, 해당 기능 별도 처리 전까지은 `projects`에서 제외하고 별도 필드로 유지 가능 — 또는 이 티켓에서 같이 폐기

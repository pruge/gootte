# T11 — discoverProjects worktree 루트 스캔 지원

**Blocked by:** T10
**Status:** open
**Time:**

## Goal

`discoverProjects`가 worktree 루트(`~/.claude/worktrees`, `~/.bb/worktrees`)를 깊이 있게 스캔하여 worktree를 별도 프로젝트로 감지한다.

## Why this slice

T10에서 `settings.projects`에 worktree 루트를 등록할 수 있게 되었다. 하지만 현재 `discoverProjects`는 depth 2까지만 스캔한다. worktree는 `root/env_or_name/project/` 구조로 depth 3~4에 있으므로, worktree 루트는 더 깊이 스캔해야 한다.

## Produces

worktree 루트를 depth 4까지 스캔하는 `discoverProjects`.

## Consumers

- `app.ts` — `getProjects`가 worktree를 포함한 프로젝트 목록 반환
- `discover-cache.ts` — 캐시된 프로젝트 목록에 worktree 포함

## Touched surfaces

- `core-io/src/discover.ts` — `discoverProjects`에서 worktree 루트 감지 + depth 확장

## Explicitly out of scope

- worktree의 `withWorktrees` 처리 — 기존대로 유지 (프로젝트별 worktree)
- state.json — T05에서 별도 처리

## Locked decisions

- **D7** — worktree 루트는 settings.projects에 등록, discoverProjects가 자동 감지 (spec)

## Evidence anchors

- `core-io/src/discover.ts:80-106` — `discoverProjects` 스캔 로직
- `core-io/src/treehouse.ts:38-95` — `claudeWorktreeRoots`·`bbWorktreeRoots` (참고용)

## Regression guards

- 🔴 `pnpm verify` 통과
- 🔴 depth 2 스캔 (메인 뿌리) 기존 동작 유지
- 🔴 depth 4 스캔 (worktree 뿌리) 새 동작

## Scope

1. `discoverProjects`에서 루트 경로가 worktree 패턴인지 판별
   - `.claude/worktrees` 포함 → depth 4 스캔
   - `.bb/worktrees` 포함 → depth 4 스캔
   - 그 외 → 기존 depth 2 스캔
2. worktree 디렉토리에서 `AGENTS.md` + `docs/features/` 있으면 프로젝트로 인정
3. worktree의 slug: `<parent_project>/<worktree_name>` (기존 관례 유지)

## Implementation notes

- worktree 루트 판별: 경로에 `.claude/worktrees` 또는 `.bb/worktrees`가 포함된지 확인
- 또는 별도 판별 없이 모든 루트에서 depth 4까지 스캔 (단순하지만 불필요한 I/O)
- worktree slug는 기존 `treehouse.ts`의 slug 관례를 따른다

## Acceptance criteria

- AC1 — settings.projects에 worktree 루트 등록 시 worktree가 프로젝트 목록에 포함
- AC2 — 메인 프로젝트 스캔은 기존대로 depth 2
- AC3 — `tsc --noEmit` 통과

## Verification

`pnpm verify` + worktree 루트에 test 프로젝트 배치 후 수동 확인

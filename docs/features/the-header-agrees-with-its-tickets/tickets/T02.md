# T02 — 취소한 기능이 신관례에서도 취소로 읽힌다

Status: resolved (2026-08-26)
Time: started=2026-08-26T14:00:05+09:00 finished=2026-08-26T14:00:05+09:00

## Goal

`spec.md` 에 선언한 취소(`Status: wontfix`)가 신관례(`tickets/`) 기능에서도 작동하게 한다.
취소된 기능의 아직 안 끝난 티켓은 `dropped` 로 취급되어, 남은 일·`next`·계획판이
그 기능을 그만 물어본다.

## Why this slice

캡틴 말씀: "feature는 만들었지만, 개발을 내가 취소한경우 wontfix를 띄우는 경우도 잇었다."

구관례는 그 표현을 갖고 있었다:

    code/web/core/src/parse/feature.ts:61-64   mapFirstmateStatus
      if (value === "resolved") return "done";
      if (value === "wontfix")  return "dropped";
      return "pending";                          // 나머지 일곱(claimed 포함) + 알 수 없는 값

    실측(parseStatusLine + mapFirstmateStatus 를 실제로 호출):
      "Status: wontfix"                      -> value=wontfix          mapped=dropped
      "**Status:** wontfix"                  -> value=wontfix          mapped=dropped
      "Status: ready-for-agent (2026-08-26)" -> value=ready-for-agent  mapped=pending
      "Status: resolved (2026-08-12)"        -> value=resolved         mapped=done

신관례에는 그 자리가 없다:

    code/web/core/src/project/backlog-join.ts:10-14   SECTION_STATUS
      in_flight -> in_progress
      queued    -> pending
      done      -> done

백로그가 만들 수 있는 상태 셋 어디에도 취소가 없고, `tasks-axi` 에도 없다
(`rm`=기록 소멸, `hold`=대기, `done`=했다고 거짓말).

## 🔴 이건 배지가 아니라 판정이다

`dropped` 를 실제로 읽는 자리(grep 실측, test·fixtures 제외):

    code/web/core/src/project/features.ts:214    hasOpenWork          — 남은 일에서 빠진다
    code/web/core/src/plan/next.ts:44            computeNext          — 다음 할 일에서 건너뛴다
    code/web/core/src/plan/close.ts:26           ticketBoxState       — 계획판 상자 표시
    code/web/core/src/plan/close.ts:138          안읽음 방아쇠         — dropped 는 되올리지 않는다
    code/web/core/src/project/in-progress.ts:64  처리중 표시에서 제외
    code/web/frontend/src/components/features/FeatureCard.tsx:16  머리글 수 세기
    code/web/frontend/src/components/features/TicketRow.tsx:37,60 티켓 줄 아이콘·단계

취소를 표현하지 못하면 취소한 기능의 티켓이 **영원히 "남은 일"** 로 남고
`next` 가 계속 그것을 다음 할 일이라고 말한다.

## Produces

- **취소 선언이 계산을 이긴다**(D3) — `spec.md` 가 `wontfix` 를 선언하면 그것이 최종이다.
  T01 이 만든 파생 배지보다 우선한다.
- **취소가 티켓까지 내려간다**(D4) — 그 기능의 신관례 티켓 중 **아직 안 끝난 것**을
  `dropped` 로 취급한다.
  🔴 이미 `done` 인 티켓은 `done` 으로 남는다 — 실제로 착지한 일을 없던 일로 만들지 않는다.
- 구관례 기능의 취소 동작은 **지금 그대로** — 이미 `mapFirstmateStatus` 가 처리한다.

## Implementation notes

- 🔴 `wontfix` 판정은 **이미 있는** `parseStatusLine` + `mapFirstmateStatus` 를 쓴다.
  새 파서나 새 어휘를 만들지 마라. 아홉 값 어휘와 `Status:` 줄 서식은 안 바뀐다.
- 취소를 얹는 자리는 백로그 조인 **뒤**여야 한다 — 조인이 `pending` 을 채운 다음에
  덮어써야 순서가 맞는다(`applyBacklogStatus` 와 `applyInProgress` 가 이미 그 형태다).
- 🔴 취소를 문서에 **저장하지 마라** — 읽을 때마다 다시 판정한다(INV-1).
- 🔴 백로그에 취소 상태를 새로 만들지 마라 — 범위 밖이다(spec §범위 밖).
- 조인 실패 티켓은 T01 의 규율대로 여전히 "모른다" 다. 다만 기능이 취소됐으면
  그 기능 전체가 취소이므로 배지는 취소로 보인다 — 티켓 줄의 미표시와 모순이 아니다.

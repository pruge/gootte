# 01 — 기능 카드를 열어 문서를 읽는다

**What to build:** 기능 카드를 **접었다 펼 수 있게** 하고, 연 카드 안을 **폴더 트리**로 만들고,
트리의 문서를 누르면 **우측 드로어**에 서식대로 띄운다. 카드 머리글에는 **네 수**를 항상 띄우고
진행 중에 색을 입힌다. 그 과정에서 카드가 티켓을 **잘라먹던 것을 고치고**, 작업을 티켓에
**잇는 규칙을 바로잡는다.**

**Blocked by:** 없음 — 지금 바로 착수 가능

**Status:** resolved (2026-08-09)

## 완료 시 시연 가능한 것

캡틴이 대시보드에서 프로젝트를 고르면 기능 카드들이 **접힌 채로** 줄지어 있고, 각 머리글에
**남은 일 · 완료 · 착수 가능 · 진행 중** 네 수가 보인다. 지금 도는 작업이 있으면 **진행 중에
색이 들어가** 눈에 띄고, 그 작업이 붙은 티켓에도 표시가 붙는다.

카드 하나를 누르면 열리면서 그 기능의 **티켓 목록이 전부** 나온다 — 지금처럼 6장 중 2장만 나오고
나머지가 잘려 사라지지 않는다. 목록 위에는 그 기능 폴더에 실제로 있는 것들이 트리로 있어서
`spec.md` 나 `architecture.md` 로 갈아탈 수 있다. 그중 하나를 누르면 **오른쪽에서 드로어가
열리며** 그 문서가 제목·목록·표가 제대로 보이는 형태로 뜨고, ESC 로 닫힌다.

## 완료 조건

### 잘림 (사양 §설계 1)

- 🔴 **기능 카드는 내용만큼 자란다.** 세로가 모자라도 카드가 눌리거나 넘친 티켓이 사라지지 않는다.
  모자라면 **바깥 목록이** 스크롤된다.
- 이 조건은 **열린 카드에 대해** 성립해야 한다. 접기가 생겼으니 됐다고 넘기지 않는다 —
  화면보다 긴 카드를 열었을 때가 이 조건이 실제로 걸리는 자리다.

### 접기와 진입점 (사양 §설계 2)

- 카드는 **기본 접힘.** 머리글(제목·슬러그·원문 상태·남은 일/완료/처리중/착수 가능 수)은
  접힌 상태에서도 그대로 보인다.
- 머리글을 눌러 열고 닫는다. 키보드로도 되고, 열림/닫힘이 보조기술에 전달된다.
- 열면 **`issues` 가 열린 채로** 시작한다. 티켓 목록을 보려고 한 번 더 누르게 하지 않는다.

### 트리 (사양 §설계 3)

- 트리는 기능 폴더에 **실제로 있는 것만** 띄운다. `adr/` 가 있으면 뜨고, 없으면 안 뜬다.
  `architecture.md` 같은 낱장 문서도 그대로 뜬다.
- 🔴 **폴더에 없는 칸을 그려 넣지 않는다.** 있을 법한 규격을 화면이 선언하지 않는다(INV-4).
- 티켓 줄은 지금 화면이 보여주는 것을 **잃지 않는다** — 원문 상태, 알 수 없는 상태 경고,
  처리중 표시, `대기 →` 선행, 착수 가능. 트리가 됐다고 파일 이름만 남기지 않는다.

### 문서 읽기 (사양 §설계 4)

- 문서 본문을 내주는 읽기 경로를 새로 뚫는다. **읽기 전용**이다(INV-2).
- 🔴 **그 경로는 기능 폴더 밖의 파일을 절대 내주지 않는다.** 화면이 준 문자열을 그대로
  파일 경로로 쓰면 관리대상 저장소 밖까지 읽히는 구멍이 된다. 요청받은 경로가 그 기능 폴더
  안으로 해소되는지 **판정한 뒤에** 읽는다. 벗어나면 거절한다.
- 마크다운은 **서식대로** 렌더링한다 — 제목·목록·표·코드블록·링크가 제대로 보여야 한다.
- **다이어그램은 되살리지 않는다.** 다이어그램 코드블록은 코드블록으로 남는다.
- 드로어는 우측에서 열리고 ESC 로 닫힌다. 닫으면 포커스가 눌렀던 자리로 돌아온다.
- 열린 문서는 **URL 에 실린다.** 새로고침하거나 링크를 넘겨도 같은 문서가 열린다.
- 읽지 못한 문서는 조용히 빈 드로어가 되지 않는다 — 무엇을 못 읽었는지 말한다.

### 네 수와 진행 중 (사양 §설계 5)

- 카드 머리글에 **남은 일 · 완료 · 착수 가능 · 진행 중** 네 수를 **항상** 띄운다.
  🔴 **0 이어도 칸이 사라지지 않는다** — 조건부로 나타났다 사라지면 캡틴이 "진행 중이 0" 과
  "진행 중을 셀 줄 모름" 을 구별할 수 없다. 이 화면의 다른 수들도 같은 규칙을 따른다.
- 진행 중에는 색이 들어간다. 장식이 아니라 지금 움직이고 있다는 신호다.
- 🔴 **잇는 규칙은 지금 그대로 둔다** — "그 가지의 커밋이 건드린 티켓 파일". 실측에서 10건 중
  1건만 맞았지만(사양 F11), 그건 규칙의 결함이 아니라 **규약의 공백**이었다. 티켓을 구현하는
  변경이 그 티켓의 `Status:` 줄을 같은 커밋에서 뒤집는 규칙이 착지했으므로(사양 F15),
  구현 가지는 이제 **반드시 자기 티켓 파일을 건드린다** — 지금 규칙이 이미 보고 있는 신호다.
  🔴 **새 표식이나 알림 장치를 만들지 않는다.** 이 티켓은 잇는 코드를 새로 짜지 않는다.
- 🔴 **첫 커밋 전의 작업은 "티켓 미상 · 작업중" 으로 남는다.** 이건 고칠 결함이 아니라 이 설계가
  받아들인 값이다 — 무언가 돌고 있다는 것은 보이고, 어느 티켓인지 아직 모른다는 것도 보인다.
  추정으로 메우지 않는다(INV-4).
- 🔴 **관측한 것을 파일에 되쓰지 않고, 어디에도 저장하지 않는다**(INV-1·INV-2).
  볼 때마다 다시 관측한다. 사본이 정리되면 진행 중도 같이 사라져야 한다.

### 공통

- 관리대상 프로젝트에는 아무것도 쓰지 않는다(INV-2).
- `pnpm verify` green.

## 테스트

**이 티켓이 아래 넷을 처음 덮는다.** 전례가 없다.

| 픽스처 / 상황 | 기대 |
|---|---|
| 🔴 화면보다 긴 카드를 연다 (티켓 다수) | **티켓이 전부 렌더된다.** 잘리거나 사라지지 않는다 — F1 회귀 |
| 기능 폴더 = `spec.md` + `issues/` + `adr/` | 셋 다 트리에 뜬다 |
| 기능 폴더 = `spec.md` + `issues/` (adr 없음) | **`adr/` 칸이 없다.** 빈 칸으로도 안 뜬다 |
| 기능 폴더에 `architecture.md` 같은 낱장 | 그대로 뜬다. 버려지지 않는다 |
| 카드를 연다 | issues 가 열린 상태다 |
| 🔴 문서 경로에 폴더 밖을 가리키는 값을 준다 | **거절한다.** 파일 내용이 나가지 않는다 |
| 표가 들어간 문서를 드로어에 연다 | 표로 렌더된다 |
| 다이어그램 코드블록이 든 문서 | 코드블록으로 남는다. 그림이 되지 않는다 |
| 읽을 수 없는 문서 | 무엇이 잘못됐는지 화면에 뜬다. 빈 드로어가 아니다 |
| URL 에 문서를 실은 채 새로고침 | 그 문서가 열린 채로 뜬다 |
| 진행 중이 0 인 기능 | **진행 중 칸이 0 으로 보인다.** 칸이 사라지지 않는다 |
| 착수 가능이 0 인 기능 | 착수 가능 칸이 0 으로 보인다 |
| 진행 중인 티켓이 있는 기능 | 그 수가 머리글에 색과 함께 보이고, 해당 티켓 줄에도 표시가 붙는다 |

잇는 계산 자체(사본 스캔·유휴/작업중 판정·미상 집계·중복 제거)는 앞 티켓이 이미 테스트와 함께
덮었다. **이 티켓은 그 계산을 건드리지 않으므로 다시 덮지 않는다** — 머리글이 그 결과를 어떻게
보여주는지만 덮는다.

첫 줄과 여섯째 줄이 이 티켓의 본체다. 첫 줄을 놓치면 **화면이 지금처럼 다시 거짓말한다** —
"남은 일 6" 이라고 써놓고 네 장을 감춘다. 여섯째 줄을 놓치면 **읽기 전용 대시보드가
저장소 밖 파일을 내주는 통로가 된다.**

## 이 티켓이 하지 않는 것

- **티켓 파일의 `Status:` 줄 고치기.** 착지한 티켓들의 상태 줄이 갱신되지 않아 화면이
  "완료 0" 이라고 말하지만, 화면은 문서를 정직하게 읽고 있을 뿐이다. 문서 쪽 일이다(INV-2).
- **탭 띠 정리.** 항목 하나짜리 탭 띠는 그대로 둔다 — 별도 판단.
- **작업중인 카드 자동 펼치기.** 요구되지 않았다.
- **다이어그램 렌더링 복원.**
- **드로어에서 문서 편집.**
- 🔴 **작업을 티켓에 잇는 장치 새로 만들기.** 표식 파일도, 알림 CLI 도, 가지 이름 규약도
  만들지 않는다(사양 §설계 5). 지금 규칙을 그대로 두고, 상태 줄 규약이 그 규칙을 맞게 만든다.
- 🔴 **작업 가지 이름 바꾸기.** firstmate 가 `fm/<작업번호>` 모양에 의존한다 — 손대면 로컬
  머지와 리뷰 diff 가 깨진다(사양 F13). 이 길은 닫혀 있다.
- **firstmate 의 사설 기록 읽기.** 남의 사설 영역에 손을 뻗지 않는다. 앞 티켓이 같은 이유로
  이미 거절한 길이다.
- **밀린 티켓 10장의 상태 줄 따라잡기.** 별건으로 진행 중이다. 여기 섞지 않는다.

## 캡틴 확인

- **어디서** — gootte 대시보드를 띄운다 (`pnpm dev`).
- **무엇을** — `gootte` 프로젝트를 고르고, 기능 카드 하나를 눌러 연 다음,
  트리에서 `spec.md` 를 눌러본다.
- **무엇이 보여야 하나** — 카드가 접혀 있다가 눌러야 열린다. 머리글에 네 수가 다 보이고
  진행 중에 색이 들어가 있다. 열린 카드에 티켓이 **전부** 보인다(`firstmate-migration` 이면
  6장 전부). `spec.md` 를 누르면 오른쪽에서 드로어가 열리며 사양이 표까지 제대로 보이고,
  ESC 로 닫힌다.

여닫는 느낌, 드로어 폭, 트리가 읽히는 모양, 진행 중 색의 세기는 테스트가 판정할 수 없어
캡틴 눈이 필요하다.

**진행 중 0 은 실패가 아니다.** 상태 줄 규약이 실제 가지에 도착하기 전이거나 작업자가 아직
첫 커밋을 하지 않았다면, 진행 중이 0 이고 도는 작업이 "티켓 미상 · 작업중" 으로 뜨는 것이
**정답이다** — 그 상태가 보이면 맞게 만든 것이다. 감춰지지만 않으면 된다.

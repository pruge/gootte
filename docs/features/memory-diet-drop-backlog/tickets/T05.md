# T05 — 백엔드 상주 캐시 상한 (`folderCache` LRU)

**Blocked by:** 없음 — 즉시 착수 가능

## Goal

요청마다 쌓이는 `folderCache` 에 상한을 둬서 백엔드 프로세스 상주를 제한한다(S1).

## Why this slice

백엔드 유휴 메모리 중 코드로 확인된 무제한 상주가 여기다 — `Map` 에 evict 가 없고, 키에 전체 사본 목록이 들어가 사본이 바뀔 때마다 새 항목이 쌓인다. 요청 경로(`readFeatures`) 하나에 손잡이가 모여 있어 독립 슬라이스다.

## Produces

- 항목 수 상한이 있는 폴더 캐시. 적중률은 유지하고, 오래된 항목이 버려진다.

## Consumers

- `readFeatures` 호출처 전부(backend 라우트·CLI·워커 `features-worker`).
- `clearFeatureCache` 호출처(테스트·명시적 무효화) — 의미 그대로 유지한다.

## Touched surfaces

- `code/web/core-io/src/features.ts` — `folderCache`·`clearFeatureCache`.
- 캐시 관련 테스트(`features.test.ts` 계열).

## Explicitly out of scope

- `snapshot.ts` 의 `memo` — 별도 상주지만 이번에 손대지 않는다(필요하면 후속).
- `tsx` → 빌드 JS 전환 — 실행 구조 변경이라 별도 계획으로.
- 워처·스냅샷·워커 구조 변경.

## Locked decisions

- D2(INV-1) — 캐시는 파생물이라 버려도 된다. 다음 read 가 다시 계산한다.
- LRU든 단순 상한이든, 지문 불일치 시 재계산 경로는 그대로 둔다.

## Evidence anchors

- `folderCache` 정의와 `mapKeyOf`·`keyOf` (키에 사본 목록 전체가 들어감).
- `clearFeatureCache` 호출처.

## Regression guards

- `core-io/src/features.test.ts` 계열.
- 캐시 적중/무효화 기존 테스트 — 상한 도입 후에도 지문 판정 로직 동일.

## Scope

- 캐시 상한 + 테스트. 계산 로직·응답 형식 변경 금지.

## Implementation notes

- 상한 수치(예: 50~100 폴더)는 실측 후 Comments 에 기록한다. 출발은 단순 삽입순 evict 로 충분하다.
- `clearFeatureCache` 는 전체 비우기 의미를 유지한다.

## Acceptance criteria

- 장시간 운용 후 백엔드 상주가 감소한다(A1).
- 같은 지문 요청은 여전히 캐시 적중한다(응답 시간 회귀 없음).
- `pnpm verify` green(A5).

# T02 — 백로그 조인 본체 제거 (동일 결과 보장)

**Blocked by:** T01 — 신호·감시가 먼저 끊겨야 조인 삭제가 단순해진다

## Goal

백로그 리더·파서·조인·워처 파일을 삭제하고, backend/CLI 의 조인 호출을 빈 목록 조인과 동일한 결과를 내는 경로로 바꾼다(S3).

## Why this slice

T01 이 신호를 끊으면 조인은 호출만 남는다. backend 와 CLI 가 이미 빈 목록(`readBacklogTasks(undefined)`)으로 부르고 있어, 삭제해도 화면 값은 바뀌지 않는다 — 그 동등함을 회귀로 잠그는 것이 이 티켓의 핵심이다.

## Produces

- 백로그 없는 기능 목록 계산 경로. 빈 목록 조인과 바이트 동등한 features/plan 응답.

## Consumers

- backend `GET /api/features/:slug`·`/api/plan/:slug` 계열 — `withBacklogStatus` 호출처 전부.
- CLI `board`·`next`·`frontier`·`feature state` — `withBacklogStatus` 호출처 전부.
- `scripts/verify-header-badge.ts` — 리더+조인을 직접 쓰는 검사 스크립트.
- 기존 테스트: `cli.test.ts` backlog 섹션, `core-io/src/backlog*.test.ts`, `secondmates.test.ts`(명부는 유지 — 아래 범위 참조), backlog-join 관련 core 테스트.

## Touched surfaces

- 삭제: `code/web/core-io/src/backlog.ts`, `code/web/core-io/src/backlog-watch.ts`, `code/web/core/src/project/backlog-join.ts`, `code/web/core/src/parse/backlog.ts` 및 그 테스트.
- 수정: `code/web/backend/src/app.ts`(`withBacklogStatus`), `code/web/cli/src/commands.ts`(`withBacklogStatus`), `code/web/scripts/verify-header-badge.ts`.
- 유지: `code/web/core-io/src/secondmates.ts`(discover 입력), `firstmateHome` 설정 일체.

## Explicitly out of scope

- secondmates 명부·discover·설정 UI (S4).
- T03~T05 의 캐시·무효화·상한 변경.
- `applyBacklogStatus` 가 하던 재계산(대기·착수 가능·배지·경과) 중 화면에 필요한 것의 삭제 — 동등 결과를 위해 필요한 재계산은 새 자리에 살린다.

## Locked decisions

- D4(INV-4) — 빈 목록 조인 결과와 동등함을 픽스처 테스트로 잠근다.
- D5(범위), D6(state.json 불변).
- backend·CLI 모두 현재 빈 목록으로 호출 중이라 오버레이는 이미 죽어 있다(스윕 확인 2026-09-11).

## Evidence anchors

- `app.ts`·`commands.ts` 의 `withBacklogStatus` (둘 다 `readBacklogTasks(undefined)`).
- `joinTicket` — 태스크 없음·조인 실패 시 문서 기반 판정으로 그대로 두는 분기.
- `applyBacklogStatus` 말미의 대기 재계산·취소·배지 파생(동등성 판단의 기준).

## Regression guards

- `cli.test.ts` 의 backlog 섹션(삭제 전 동작 스냅샷 용도로 먼저 읽는다).
- backend `app.test.ts`, core/backlog-join 관련 테스트.
- 새로 추가: 빈 목록 조인 결과 고정 픽스처 테스트(삭제 후에도 같은 응답임을 보증).

## Scope

- 조인 관련 파일 삭제 + 호출처 정리 + 동등성 테스트. 캐시 정책·워처·프론트 금지.

## Implementation notes

- 순서는 동등성 테스트 먼저(현재 빈 조인 결과 고정) → 삭제·호출처 정리 → 테스트 green.
- 재계산 중 화면에 필요한 부분은 조인tik 없이 같은 값을 내는 최소 경로로 옮기고, 그 판단 근거를 티켓 Comments 에 남긴다.

## Acceptance criteria

- 동일 픽스처에 대한 features/plan 응답이 삭제 전 빈 조인 결과와 동일하다(A3).
- backlog 파일 유무·내용이 응답에 영향을 주지 않는다.
- `pnpm verify` green(A5).

## Verification

- `pnpm verify` 전체 + 신규 동등성 픽스처 테스트.

# T04 — 광범위 invalidate 를 키 지정으로

**Blocked by:** T01 — 같은 `live.ts` 를 건드리므로 순서대로 간다

## Goal

인자 없는 전체 `invalidateQueries()` 를 쿼리 키 지정 무효화로 바꾼다. 같은 신호에 다시 읽는 양이 준다(S1·S2).

## Why this slice

T01 이 `backlog` 분기를 지우면 live.ts 에 남는 broad 호출은 재연결 시 전체 무효화 하나다. 설정 저장 쪽 broad 호출과 함께 좁히면 refetch 폭풍이 사라진다. 같은 파일을 T01 과 나누어 쓰는 충돌을 피하려고 순서 의존을 건다.

## Produces

- 신호별 최소 무효화: 재연결·설정 저장·메모·시간 기록이 자기 쿼리만 다시 읽는다.

## Consumers

- `useLiveSync` 재연결 경로 — 놓친 변경 흡수 의도는 유지하되 범위를 좁힌다.
- `useSaveSettings`·`useBlockedCopies`·`useRecordTime`·`useFeatureDoc` 후속 무효화.
- 폴백 폴러(`FALLBACK_POLL_MS`) — 좁아진 무효화와 함께 stale 상한 15초 유지.

## Touched surfaces

- `code/web/frontend/src/lib/live.ts` — 재연결 시 `invalidateQueries()`.
- `code/web/frontend/src/lib/query.ts` — `useSaveSettings`·`useBlockedCopies`·`useRecordTime`·`useFeatureDoc` 의 무효화 범위.

## Explicitly out of scope

- T03 의 보관·영속 변경(선행 병렬 가능하나 파일이 겹치므로 T03 과 동시 편집 금지).
- 폴백 주기 변경 — 15초 상한 유지.
- 백엔드 방송 내용 변경 — 이미 T01 에서 끝난다.

## Locked decisions

- D3(INV-3) — 좁힐 때 신호가 커버하는 쿼리는 전부 포함한다. 재연결 흡수(놓친 변경) 보장은 유지한다.
- D2(INV-1) — 무효화는 다시 읽기만 일으키고, 화면이 값을 조립하지 않는다.

## Evidence anchors

- `live.ts` 재연결 `onopen` 의 전체 invalidate.
- `query.ts` 의 `void qc.invalidateQueries()` 호출 4곳.

## Regression guards

- 프론트 테스트 + WS 재연결 시 최신값 반영 수동 확인(연결 끊기→문서 변경→재연결).

## Scope

- 위 두 파일의 무효화 범위 변경 + 테스트. 정책 수치 변경 금지.

## Implementation notes

- 설정 저장은 `projects`+현재 프로젝트 키로, 시간 기록은 `plan`·`features`(해당 프로젝트)로 좁히는 것이 출발점.
- 재연결 흡수는 현재 열린 프로젝트 키 + `projects` + `plan` 으로 좁히고, 빠뜨린 쿼리가 없는지 리뷰에서 확인한다.

## Acceptance criteria

- 동일 신호에 다시 읽는 쿼리 수가 줄어든다(개발자도구 Network 또는 쿼리 로그로 확인).
- 재연결 후에도 놓친 변경이 화면에 반영된다(INV-3).
- `pnpm verify` green(A5).

## Verification

- `pnpm verify` + 재연결·설정 저장 시나리오 수동 확인.

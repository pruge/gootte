# T02 — preview arm 전환: 창이 backend 를 본다 (migrate)

**Blocked by:** T01 — 서빙 자리가 있어야 점화한다

## Goal

설치 모드에서 vite 자식을 안 띄우고 창이 backend(dist 서빙)를 본다(A1·A2).

## Why this slice

점화(migrate) 단계 — T01 의 길을 preview arm 에 잇는다. dev(HMR) arm 은 그대로 둔다.

## Produces

- preview 실행 = backend 자식 1개 + backend 포트 창. `gootte-front` 프로세스 없음.

## Consumers

- `pnpm dev:tauri`(dev arm — 그대로 vite dev).
- `pnpm build:tauri` 산출 .app(preview arm — 바뀐다).
- `tauri-dev.sh`·`tauri-build.sh` 주석.

## Touched surfaces

- `code/web/src-tauri/src/main.rs` — `spawn_children` preview 분기, `StackConfig`·`wait_listening`·창 URL, `GOOTTE_SERVE_DIST=1` 전달, dist 존재 사전 검사(A3: 없으면 fail_fatal).
- `scripts/tauri-build.sh` — 주석 현실화(preview dist 서빙 주체 변경).

## Explicitly out of scope

- `FrontendMode` 삭제(T03). dev arm·HMR. e2e·`pnpm dev`. `proc-title.mjs`(dev-frontend 가 쓴다).

## Locked decisions

- D3(flag 점화는 preview arm 만), D5(순서 불변), D8의 반대 — enum 은 이번에 안 건든다.
- A3: dist 미존재는 preview arm 기동 실패로(조용한 placeholder 금지). dev arm 은 검사 안 한다.
- `VITE_BACKEND_URL` 전달 삭제(preview 자식이 없으니) — dev arm 잔재가 있으면 그때 본다.

## Evidence anchors

- `spawn_children` preview 분기 + `wait_listening` 두 포트 대기 + 창 `WebviewUrl::External(frontend)`.
- `FrontendMode::resolve` (이번엔 유지).

## Regression guards

- `cargo check` + `cargo clippy -- -D warnings`.
- 기존 backend 테스트(T01) — 서빙 동작 보증.
- 실기동(GUI)은 캡틴 환경 수동 확인(`dev:tauri` + 설치 빌드): A1(프로세스 목록) · A2(`/`·`/api`·WS).

## Scope

- main.rs preview arm + 빌드 스크립트 주석. enum 삭제·dev arm 금지.

## Implementation notes

- `kill_all`·감시 스레드는 자식 수와 무관하게(등록부 순회) 그대로 돈다 — 손대지 않는다.
- `named_child_alive("frontend")` 참조가 있으면 정리한다(죽은 이름 조회 금지).

## Acceptance criteria

- preview 기동 시 vite 없음(A1), 창이 뜨고 화면·실시간 동작(A2).
- dist 없음 → FATAL(A3).
- `cargo check`·`clippy` green(A5).

## Verification

- `cargo check` + `clippy` + 캡틴 수동 기동 확인.

# T01 — mountFallback 정적 서빙 확장 (expand)

**Blocked by:** 없음 — 즉시 착수 가능

## Goal

flag + dist 존재 때 backend 가 `frontend/dist` 를 서빙한다. 기본 off 라 기존 동작은 그대로다(S3·A4의 안전망).

## Why this slice

seam 하나(`mountFallback`)에 새 길을 옆에 세우는 expand 단계다. 뒤 티켓이 켜기만 하면 된다.

## Produces

- `GOOTTE_SERVE_DIST=1` + dist 존재 → `/`·정적 파일 서빙, `/api*` 는 기존 라우트 우선.

## Consumers

- T02 main.rs preview arm(유일한 점화자).
- 기존 테스트: `app.test.ts` + 신규 서빙 테스트.

## Touched surfaces

- `code/web/backend/src/app.ts` — `mountFallback` 확장.
- `code/web/backend/test/` — 서빙 테스트(픽스처 dist).
- 필요시 `@hono/node-server` serve-static 계열 import(의존성 추가 없이 — `hono`·`@hono/node-server` 안에 있다).

## Explicitly out of scope

- main.rs·스크립트(T02·T03). dist 빌드 변경. SPA rewrite(D4).

## Locked decisions

- D2(seam), D3(flag + 존재 조건), D4(정확 파일 + `/`만), D5(WS 등록 순서), D6(dist 는 파생물).
- dist 경로 해소: backend 기준 `../frontend/dist`, 테스트용 env 오버라이드(`GOOTTE_DIST_DIR`, `GOOTTE_WEBKIT_DATA_DIR` 선례).
- dist 없음 + flag on → placeholder가 아니라 기동 실패?contra — T01은 서빙 함수 자리만 만든다. "없으면" 동작(placeholder 유지 vs throw)은 T02 점화자가 정한다. 기본 유지 = placeholder.

## Evidence anchors

- `mountFallback` 현 본문 + "Phase 5" 주석.
- `server.ts` 의 WS-then-fallback 등록 순서.
- `frontend/dist` 실물(`index.html` + assets).

## Regression guards

- `backend/test/app.test.ts` — `/api/*` 가 캐치올에 안 먹히는지(이미 있음).
- 신규: `/`→index.html, 에셋 바이트 일치, `/api/projects` 여전히 JSON, `/api/live` 라우트 생존.

## Scope

- backend 서빙 + 테스트. Rust·스크립트·프론트 금지.

## Implementation notes

- serve-static 미들웨어보다 `app.get("*")` 안에서 파일 매핑을 직접 해도 된다 — 판단은 구현자에게. 조건: 루트 고정(경로 탈출 금지), `/api` 우선(마운트 순서로 보장).
- `VITE_BACKEND_URL`·프록시 설정은 건드리지 않는다(dev 가 쓴다).

## Acceptance criteria

- flag off → 기존 placeholder 그대로(A4).
- flag on + 픽스처 dist → `/`·에셋·`/api`·WS 순서 모두 green(A2의 서버 절반).
- `pnpm verify` green(A5).

## Verification

- 신규 테스트 + `pnpm verify`.

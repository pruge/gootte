# Issue tracker: `docs/features/` (로컬 마크다운)

이 저장소의 spec·티켓은 **`docs/features/` 아래 마크다운 파일**로 산다. GitHub Issues 는 쓰지 않는다 —
외부 기여자 유입이 없고, 이 저장소는 md 를 단일 SoT 로 삼는 규율(INV-1 — 손으로 유지되는 2차 SoT 금지)을 따른다.

## 레이아웃

```
docs/features/<기능-slug>/
├── spec.md                 ← spec 1개 = 파일 1개
├── tickets/
│   ├── T01.md              ← 🔴 **지금 쓰는 관례.** 티켓당 파일 1개, 의존 순서로 T01 부터
│   ├── T02.md
│   └── T03.md
├── adr/
│   └── NNNN-<slug>.md      ← 그 기능에 속한 결정 기록
├── issues/                 ← 옛 관례(아래 §두 관례). **새 티켓을 여기 만들지 않는다**
└── _out-of-scope/          ← 거절·범위 밖으로 밀어낸 요청
```

## 🔴 지금 쓰는 관례 — `tickets/T<NN>.md`

경로 `docs/features/<기능-slug>/tickets/T<NN>.md`, 제목 `# T<NN> — <제목>`(em dash).
**손으로 쓰는 머리글 줄은 `**Blocked by:**` 하나뿐이고, `Time:`·`Status:` 는 `gootte` 만 쓴다.**

🔴 **본문 절 목록과 `gootte` 명령 사용법은 스킬 `gootte-ticket` 이 SoT 다** — 티켓을 쓰거나 닫을 때
그 스킬이 뜬다. 여기 두 벌로 적지 않는다(같은 사실이 두 곳에 있으면 그 순간부터 하나는 거짓이다).

### 선행 표기 두 가지 — 둘 다 읽힌다

| 표기 | 실측(2026-09-04) | |
|---|---|---|
| `**Blocked by:** T02` 줄 | 10장 | **앞으로 이것을 쓴다** — AGENTS.md 가 "순서는 `Blocked by:` 가 소유한다" 고 말한다 |
| `## Depends on` 절의 목록 | 51장 | 옛 티켓 다수가 이것을 쓴다. 파서가 **둘을 합집합으로** 읽으므로 고치러 다니지 않는다 |

판정 자리는 `core/src/parse/feature.ts` 의 `parseNewBlockedBy` 하나다.

## 두 관례 — 새 것만 쓰고, 옛 것은 읽기만 한다

| | 옛 관례 `issues/<NN>-<slug>.md` | 지금 관례 `tickets/T<NN>.md` |
|---|---|---|
| 새로 만드나 | 🔴 **아니다** | ✅ 그렇다 |
| 완료를 무엇이 정하나 | 문서의 `Status: resolved (날짜)` | **`Time:` 줄의 `finished=`**(gootte 가 적는다) |
| 상태 줄 | 손으로 적는다 | 🔴 **손대지 않는다** |
| 캡틴 눈 표시 | 계산된다 | 🔴 **계산되지 않는다**(아래) |

옛 관례 파일은 **그대로 읽힌다.** 2026-09-04 기준 이 저장소에 11개 기능이 아직 `issues/` 를 갖고
있고(53장), 전부 지난 작업의 기록이다. 🔴 **옮기지 마라** — 옮기면 완료 판정의 근거(`Status:` 줄)가
`Time:` 줄로 바뀌어야 하는데 그 시각은 남아 있지 않다. 읽히는 채로 두는 것이 정직하다.

## `Blocked by:` 의 의미

`**Blocked by:** T01, T02` — **같은 기능 폴더 안의 티켓**에 대한 구조적 의존이다.
나열된 티켓이 **전부 완료되면 기계적으로 해제**된다. 사람이 따로 풀어 줄 것이 없다.
신관례에서 "완료" 는 그 티켓의 `Time:` 줄에 `finished=` 가 있는 것이다(§완료는 gootte 가 적는다).

- 번호는 `T01` · `01` · `1` 을 다 받는다 — 파서가 `T` 접두를 걷고 숫자로 비교한다.
- 의존이 없으면 `**Blocked by:** 없음 — 즉시 착수 가능` 처럼 그 사실을 명시한다(빈칸으로 두지 않는다).
- 번호로 특정할 수 없는 외부 대기(다른 기능의 착지, 캡틴 결정, 상류 릴리스)는 `Blocked by:` 에
  적을 수 없다. 🔴 **신관례에는 그것을 적을 `Status:` 줄이 없다**(gootte 만 쓴다) — 그런 대기는
  본문 `## Blocked` 이나 `## Comments` 에 산문으로 적고, 정말로 못 하게 됐으면 `gootte drop` 이다.
- 다른 기능의 티켓을 가리킬 때는 `<기능-slug>/T01` 처럼 기능을 앞에 붙인다.

## 다음 할 일은 계산되는 것이지 적어 두는 것이 아니다

**별도 원장 문서가 없다.** 완료는 티켓의 `Time:` 줄이, 순서는 `Blocked by:` 줄이 소유한다.
다음 할 일 = **frontier** — `tickets/` 에서 아직 안 끝났고(`finished=` 없음) 선행이 다 풀린 것 중
번호가 빠른 것. **임자가 있다** = 그 티켓에 `started=` 가 있다(누가 `gootte start` 를 불렀다).

🔴 예전에는 작업자가 `Status:` 를 `claimed` 로 손수 바꾸는 것이 임자 표시였다. 지금은
**`gootte start` 가 그 자리를 대신한다** — 표시를 적는 것과 시각을 남기는 것이 한 동작이라
"바꾸는 것을 잊는" 경우가 없다.

따로 갱신할 원장이 없고, 그래서 stale 해질 원장도 없다.
(이 저장소가 만드는 제품이 정확히 이 계산을 자동화한다 — INV-1·INV-4.)

## 🔴 완료는 `gootte` 가 적는다 — 손으로 쓰지 않는다

**티켓을 구현하는 변경이 그 티켓의 완료 기록을 같은 커밋에 담는다.** 다만 **적는 주체가 사람이
아니라 `gootte` 다.** 명령과 인자는 스킬 `gootte-ticket` 이 갖는다.

**왜 이렇게까지 못 박는가.** 손으로 적던 시절을 한 번 돌려봤고 결과가 남아 있다 — 2026-08-09 기준
이 저장소의 티켓 10장이 **전부 구현되어 머지됐는데 파일은 열 장 다 `ready-for-agent`** 였다.
그래서 대시보드가 "완료 0" 이라고 말했다. 화면이 고장난 게 아니라 문서가 그렇게 말하고 있었다.
지금 관례는 그 실수를 **가능하지 않게** 만든다 — 사람이 적을 자리가 없다.

**딸려오는 성질 하나.** 이렇게 하면 티켓을 구현하는 가지는 **반드시 자기 티켓 파일을 건드린다.**
그래서 어느 작업이 어느 티켓의 것인지를 기계적으로 읽을 수 있다. 이 저장소가 만드는 제품이
"지금 무엇이 진행 중인가" 를 그 신호로 계산한다.

### 🔴 남의 티켓을 닫히게 만들었으면 그 티켓까지 가서 닫아라

내 티켓이 **다른 티켓의 완료 조건을 만족시켰으면**, 같은 커밋에서 그쪽 티켓도
`gootte end <기능> <그 티켓>` 으로 닫는다. 내 티켓 본문에 *"저쪽이 이걸로 함께 닫힌다"* 고 적는 것은
**닫는 것이 아니다** — 🔴 계획에 보이는 것은 기록된 `finished=` 뿐이다.

## 캡틴 눈 표시 — 🔴 신관례 티켓에서는 계산되지 않는다

`## 캡틴 확인` 절과 `**캡틴 확인:**` 표시 줄을 읽는 판정(`parseNeedsCaptainEye`)은 **옛 관례
(`issues/`) 티켓에만 걸린다.** 신관례 티켓의 `needsCaptainEye` 는
`core/src/project/features.ts:65` 에서 **무조건 `false`** 다(실측 2026-09-04).

- 그래서 `tickets/T<NN>.md` 에 `## 캡틴 확인` 절을 써도 **`gootte next` 의 👁 에 안 잡힌다.**
  절을 쓰는 것 자체는 자유다(사람이 읽는다) — 다만 **기계가 세어 줄 것이라 기대하지 마라.**
- 캡틴 검수가 필요하면 **그것을 티켓 한 장으로 끊는 편**이 확실하다(예:
  [`read-path-redesign/tickets/T08.md`](../features/read-path-redesign/tickets/T08.md) — 종착 티켓이
  검수를 자기 일로 갖는다). 그러면 계획에 남고 `Blocked by:` 로 순서도 선다.
- 🔴 되살리려면 화면·CLI 에 자리를 먼저 정하고 새 결정으로 판단한다. **지금 상태를 "곧 될 것" 으로
  적지 않는다** — 이 저장소는 그렇게 남은 유령 값을 이미 둘 걷어냈다
  (`workedBy` · `unlanded`, `read-path-redesign/T01`).

## "이슈 트래커에 올려라" / "해당 티켓을 가져와라"

- **올려라** = `docs/features/<기능-slug>/tickets/T<NN>.md` 를 새로 만든다(폴더가 없으면 만든다).
  🔴 `issues/` 에 만들지 않는다.
- **가져와라** = 참조된 경로의 파일을 읽는다. 보통 경로나 번호를 직접 받는다.

## 기존 결정을 뒤집을 때

옛 파일을 고쳐 덮어쓰지 않는다. **새 ADR 을 그 기능 폴더의 `adr/` 에 쓰고 무엇을 뒤집는지 적는다.**
옛 결정 기록은 그 자리에 남는다 — 왜 그때 그렇게 정했는지가 다음 판단의 재료이기 때문이다.

> ⚠️ **미해결**: 기능이 여러 개로 늘면 전역 색인이 필요해질 수 있다. 지금은 폴더 목록으로 충분해서
> 만들지 않았다 — 필요해지는 시점에 결정한다.
